## How it works

The data has no coordinates: the node mark has no `x` and `y` channels. The definition passes `layout: force({ engine })`, so the first batch of nodes is laid out as soon as the graph mounts. Communities of uneven sizes pull together and push each other apart, and the view keeps the graph framed while it settles.

The simulation runs in a Web Worker, so the page stays responsive. From 2,000 nodes the automatic engine computes it on the GPU with WebGL2; below that, when the GPU is not available or when the browser draws WebGL in software, it runs on the CPU. From 1,000 nodes, the layout works in levels: it places a coarse copy of the graph first, then refines it, which is why the first frames show small clusters opening up. See [large graphs](/docs/layout#large-graphs).

The example reads the progress from `graph.store`, under `layout`, and times each run between `layoutstart` and `layoutend`.

## Try it

- Drag a node while the layout runs: it stays where you drop it and the others settle around it.
- Press **Add ten nodes**: the new nodes are placed near their neighbors, and the rest of the graph does not move.
- Press **Nodes** to switch between 1,000 and 500,000 nodes, then **Engine** to compare the GPU and the CPU.
- Press **Run again** to restart from the current positions, or **Stop** to keep them as they are.
