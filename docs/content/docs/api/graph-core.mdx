`GraphCore` is the graph without its element: data, layouts, view, selection, states, time, history, paths, the store and the events. [`GraphInstance`](/docs/api/graph-instance), returned by `mountGraph`, extends it with the element, the focus, the lens, the anchors, `drawn`, `suspend` and `resume`. A function that takes a `GraphCore`, such as [`createLegend`](/docs/api/legend), [`createTimeline`](/docs/api/timeline), [`exportDrawio`](/docs/api/export) or [`exportVsdx`](/docs/api/export), reads none of these.

`S` is the union of the state names and `M` the union of the marks of the definition, as for `GraphInstance`. See [TypeScript](/docs/typescript).

## Settled

`settled()` resolves once nothing is left to do: data changes applied, live sources loaded or the [`waitForData`](/docs/api/define-graph#wait-for-the-data) deadline past, no layout run, no view or position animation, edge bundling, edge routing and bridges computed, the fills of large shapes triangulated and the hulls ready. Frames do not count: `await graph.drawn()` afterwards waits for the frame that shows the result.

```ts
await graph.settled()
await graph.drawn()
report(graph.positions.snapshot())
```

It applies pending data changes first, like the other reads, and checks again after each step of work, so a layout that a live source restarts keeps it waiting. Once the graph is destroyed, it rejects with the reason of `signal`, also while it waits.
