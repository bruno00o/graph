---
title: cypherGraph
description: Convert the result of a Cypher query into nodes and edges for the marks.
---

```ts
import { cypherGraph } from '@bruno00o/graph/cypher'

function cypherGraph<N extends object = CypherProperties, E extends object = CypherProperties>(
  input: CypherInput,
  options?: CypherOptions,
): CypherGraph<N, E>
```

Finds the nodes, relationships and paths in `input` and returns them deduplicated by `elementId`. It runs no query and imports no driver. `N` and `E` type the `properties` of the nodes and of the edges.

## Result

```ts
const { nodes: items, edges: links } = cypherGraph(result)

nodes(items, { label: (node) => String(node.properties.name) })
edges(links, { source: 'source', target: 'target', color: 'type' })
```

<api-table path="cypher/index.ts" name="CypherRelationshipLike" />

<api-table path="cypher/index.ts" name="CypherPathSegmentLike" />

These interfaces list only the fields the adapter reads. The classes of the official `neo4j-driver` (`QueryResult`, `EagerResult`, `Record`, `Node`, `Relationship`, `Path`) satisfy them, and so does the same data parsed from JSON.

Fields that are not listed are ignored, and `identity`, `start` and `end` stand in for `elementId`, `startNodeElementId` and `endNodeElementId` when a server is old enough not to send them.

See [Cypher](/docs/cypher) for a walkthrough.
