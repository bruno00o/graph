```ts
import { geo, grid, layers, radial, rings } from '@bruno00o/graph/layouts'

function layers(options?: LayersOptions): Layout
function grid<T = unknown>(options?: GridOptions<T>): Layout<T>
function rings<T = unknown>(options?: RingsOptions<T>): Layout<T>
function radial(options?: RadialOptions): Layout
function geo<T = unknown>(options?: GeoOptions<T>): Layout<T>
```

Each returns a frozen [`Layout`](/docs/api/define-graph#layout) named `'layers'`, `'grid'`, `'rings'`, `'radial'` or `'geo'`, with `incremental: false`. Pass it as `layout` to `defineGraph`, or to `graph.layout.run` for a single run. See [Layouts](/docs/layout#layers) for a walkthrough.

## Shared behavior

- Only free nodes move: alive, without `x` and `y` in the data, chosen by the run, and not being dragged.
- Moved nodes are centered on their current center, so a run on part of the graph stays where that part was. `geo` is the exception: it places nodes by their coordinates.
- Every spacing option is a gap between node borders, in world units, as in `force`. `grid`, `rings` and `radial` give every node a place of the same size, so their `spacing` is the gap between two of the largest moved nodes: neighboring places are that diameter plus `spacing` apart. It defaults to the largest diameter, and at least 24.
- A negative or non-finite spacing falls back to its default. `0` is allowed: the largest nodes touch.
- The result ends without progress, in a microtask: nodes glide to it over `transitions.layout`, or the `duration` of the run.
- When nodes arrive, every free node is laid out again.
- `geo` places every node by its coordinates, then pushes apart the containers of unfolded groups that overlap, 16 units from their neighbors.
- `grid`, `rings` and `radial` lay unfolded groups out as blocks, from the deepest up: each group with the same layout, then its blocks in the group above, each standing in as one node the size of its container. Containers that still overlap are then pushed apart, 16 units from their neighbors. `layers` places groups in the same layers as the rest of the graph, see below. See [groups in layouts](/docs/layout#groups).

## layers

```ts
type LayersDirection = 'down' | 'up' | 'right' | 'left'

interface LayersOptions {
  readonly direction?: LayersDirection
  readonly root?: Key | readonly Key[]
  readonly layerSpacing?: number
  readonly nodeSpacing?: number
}
```

<api-table path="layouts/index.ts" name="LayersOptions" />

- **Cycles.** Edges that close a cycle are turned around, as few as a greedy pass can find. They are still drawn, pointing back. Duplicate edges count once.
- **Layers.** Each node gets a layer so that every edge goes to a later one, with the smallest total length (network simplex). Each component starts at the first layer.
- **Order.** Nodes of a layer are sorted by the mean position of their neighbors, sweeping down and up while crossings drop. An edge that skips layers holds a place in each layer it crosses.
- **Placement.** Each node is aligned with its neighbors where it can be, and pushed aside by its radius and `nodeSpacing` where it cannot. The four alignments, from each side and each direction, are balanced.
- **Components.** Separate components and lone nodes are packed in rows, the largest first, `layerSpacing` apart.
- **Groups.** Unfolded groups get layers with the rest of the graph: each group spans the layers from its first member to its last, and the layering keeps that span short, the more so for groups with many members. On every layer, the members of a group are side by side, nested groups inside, and sibling groups keep the same order from one layer to the next. Each container leaves its `padding` around its members and the room of its label on the side where it is drawn, both on top of `nodeSpacing` and `layerSpacing`. An edge that skips layers stays inside the group of its source while that group lasts, then joins the group of its target, so it crosses borders on the ends of the containers. When some nodes do not move, or a container is a circle, containers are then pushed apart, 16 units from their neighbors.
- Edges to nodes that do not move, because they have `x` and `y` in the data or were left out of the run, are ignored.
- The same graph always gives the same result.

## Order

```ts
type NodeOrder<T> = 'degree' | ((a: T, b: T) => number)
```

`'degree'` puts the nodes with the most edges first. A function compares the items of two nodes, as given to `nodes()`; ties keep the internal order. `T` is the item type of the node marks. `graph.layout.run` infers it from the definition; inside `defineGraph`, pass it as the type argument of `grid`, `rings` or `geo`, or annotate a parameter.

## radial

```ts
interface RadialOptions {
  readonly root?: Key | readonly Key[]
  readonly spacing?: number
}
```

<api-table path="layouts/index.ts" name="RadialOptions" />

- A breadth-first walk from the roots, through free nodes only, gives each node its ring and the node it was reached from. Edges count in both directions.
- Each branch gets a slice of the circle in proportion to its number of leaves, and each node sits in the middle of its slice. When a ring is crowded, it grows and its nodes spread apart in the same order.
- A single fixed root keeps its place and the rings form around it. A single free root goes to the center of the moved nodes.
- Nodes the walk does not reach go on an outer ring, evenly spaced.

## geo

```ts
interface GeoOptions<T = unknown> {
  readonly longitude?: Channel<T, number>
  readonly latitude?: Channel<T, number>
  readonly center?: GeoPoint
  readonly scale?: number
  readonly spacing?: number
  readonly order?: NodeOrder<T>
}
```

<api-table path="layouts/index.ts" name="GeoOptions" />

- **Projection.** A node at `longitude` and `latitude` goes to `(geoToWorld(point) − geoToWorld(center)) × scale`: the Web Mercator world of a map, 512 units wide, moved so that `center` is at the origin and multiplied by `scale`. Latitudes are clamped to ±85.05, as on a map. A coordinate that is not a finite number counts as missing.
- **Scale.** Without `scale`, the layout looks for the smallest scale at which about one distinct place in five would share a spot, the size of a typical node plus `spacing`, with another place. The search stays within a factor 4 below and 32 above the scale that would spread the places evenly over their box, so a few tight clusters far apart give dense clusters, not a huge empty graph.
- **Center.** Without `center`, the middle of the box around the places is drawn at the origin. Coordinates stay small, which keeps their precision at any scale.
- **Spread.** Places are taken from the most crowded area first, then the places that hold the most nodes. A node whose spot is free stays there. Otherwise it takes the nearest free spot close by, else a free spot at the edge of the crowd it ran into, on the side facing its place. No two nodes end closer than their radii plus `spacing`, fixed nodes included; only containers of groups can be pushed later.
- **Same place.** Two to six nodes at the same coordinates sit on a ring around it, the first on top, then clockwise. More sit on a spiral from the place outward, in the same order.
- **No coordinates.** A node without coordinates goes at the mean of its placed neighbors, or the free spot nearest to it, and the walk goes on through its own neighbors. Nodes the walk cannot reach line up in a grid, right of the others and level with their top.
- Fixed nodes, with `x` and `y` in the data or left out of the run, keep their place and count as placed neighbors and as obstacles.
- The same data and options always give the same result.
