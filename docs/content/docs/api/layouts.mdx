---
title: layers, grid, rings, radial
description: Layouts computed at once, on the main thread, that glide nodes to their place.
---

```ts
import { grid, layers, radial, rings } from '@bruno00o/graph/layouts'

function layers(options?: LayersOptions): Layout
function grid<T = unknown>(options?: GridOptions<T>): Layout
function rings<T = unknown>(options?: RingsOptions<T>): Layout
function radial(options?: RadialOptions): Layout
```

Each returns a frozen [`Layout`](/docs/api/define-graph#layout) named `'layers'`, `'grid'`, `'rings'` or `'radial'`, with `incremental: false`. Pass it as `layout` to `defineGraph`, or to `graph.layout.run` for a single run. See [Layouts](/docs/layout#layers) for a walkthrough.

## Shared behavior

- Only free nodes move: alive, without `x` and `y` in the data, chosen by the run, and not being dragged.
- Moved nodes are centered on their current center, so a run on part of the graph stays where that part was.
- Every spacing option is a gap between node borders, in world units, as in `force`. `grid`, `rings` and `radial` give every node a place of the same size, so their `spacing` is the gap between two of the largest moved nodes: neighboring places are that diameter plus `spacing` apart. It defaults to the largest diameter, and at least 24.
- A negative or non-finite spacing falls back to its default. `0` is allowed: the largest nodes touch.
- The result ends without progress, in a microtask: nodes glide to it over `transitions.layout`, or the `duration` of the run.
- When nodes arrive, every free node is laid out again.

## layers

```ts
type LayersDirection = 'down' | 'up' | 'right' | 'left'

interface LayersOptions {
  readonly direction?: LayersDirection
  readonly root?: Key | readonly Key[]
  readonly layerSpacing?: number
  readonly nodeSpacing?: number
}
```

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `direction` | `LayersDirection` | `'down'` | Where edges point: the first layer is at the top for `'down'`, at the left for `'right'` |
| `root` | `Key \| readonly Key[]` | Nodes without incoming edges | Nodes forced onto the first layer. Edges into them are turned around, and edges between two roots are left out |
| `layerSpacing` | `number` | Twice the largest diameter, at least that diameter plus 24 | Gap between two layers, from the borders of their largest nodes, in world units |
| `nodeSpacing` | `number` | The largest diameter, at least 8 | Gap between the borders of two neighboring nodes of a layer, in world units |

- **Cycles.** Edges that close a cycle are turned around, as few as a greedy pass can find. They are still drawn, pointing back. Duplicate edges count once.
- **Layers.** Each node gets a layer so that every edge goes to a later one, with the smallest total length (network simplex). Each component starts at the first layer.
- **Order.** Nodes of a layer are sorted by the mean position of their neighbors, sweeping down and up while crossings drop. An edge that skips layers holds a place in each layer it crosses.
- **Placement.** Each node is aligned with its neighbors where it can be, and pushed aside by its radius and `nodeSpacing` where it cannot. The four alignments, from each side and each direction, are balanced.
- **Components.** Separate components and lone nodes are packed in rows, the largest first, `layerSpacing` apart.
- Edges to nodes that do not move, because they have `x` and `y` in the data or were left out of the run, are ignored.
- The same graph always gives the same result.

## Order

```ts
type NodeOrder<T> = 'degree' | ((a: T, b: T) => number)
```

`'degree'` puts the nodes with the most edges first. A function compares the items of two nodes, as given to `nodes()`; ties keep the internal order. `T` is the item type of the node mark: pass it as the type argument of `grid` or `rings`.

## grid

```ts
interface GridOptions<T = unknown> {
  readonly columns?: number
  readonly spacing?: number
  readonly order?: NodeOrder<T>
}
```

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `columns` | `number` | Square root of the count, rounded up | Nodes per row. Rounded down, at least 1 |
| `spacing` | `number` | See above | Gap between rows and between columns |
| `order` | `NodeOrder<T>` | Internal order | Order of the nodes, row by row from the top left |

## rings

```ts
interface RingsOptions<T = unknown> {
  readonly center?: Key
  readonly order?: NodeOrder<T>
  readonly spacing?: number
}
```

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `center` | `Key` | First node in `order` | Node in the middle. A fixed center keeps its place and the rings form around it |
| `order` | `NodeOrder<T>` | `'degree'` | Order from the middle outward. Ring `n` holds up to `⌊2πn⌋` nodes |
| `spacing` | `number` | See above | Gap between two rings |

## radial

```ts
interface RadialOptions {
  readonly root?: Key | readonly Key[]
  readonly spacing?: number
}
```

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `root` | `Key \| readonly Key[]` | Free node with the most edges | Start of the walk. Several roots share the inner ring and each grows its own branch |
| `spacing` | `number` | See above | Smallest gap between two rings, and between two nodes of a ring |

- A breadth-first walk from the roots, through free nodes only, gives each node its ring and the node it was reached from. Edges count in both directions.
- Each branch gets a slice of the circle in proportion to its number of leaves, and each node sits in the middle of its slice. When a ring is crowded, it grows and its nodes spread apart in the same order.
- A single fixed root keeps its place and the rings form around it. A single free root goes to the center of the moved nodes.
- Nodes the walk does not reach go on an outer ring, evenly spaced.
