---
title: exportPng and exportSvg
description: Save a mounted graph as a PNG image or a standalone SVG document.
---

```ts
import { exportPng, exportSvg } from '@bruno00o/graph/export'

function exportPng<S extends string>(
  graph: GraphInstance<S>,
  options?: PngExportOptions,
): Promise<Blob>

function exportSvg<S extends string>(
  graph: GraphInstance<S>,
  options?: SvgExportOptions,
): Promise<string>
```

`exportPng` draws the graph offscreen in a WebGL context of its own and resolves to a `Blob` of type `image/png`. `exportSvg` writes an SVG document from the scene, without reading pixels back, and resolves to its text. Both wait for the images of the nodes and for the fonts of the page. See [Export](/docs/export) for a walkthrough.

## Errors

- A graph that was not created by `mountGraph`, or that is destroyed, throws an `Error`.
- A `zoom` or a `pixelRatio` that is not a positive number throws a `RangeError`, as does an area smaller than one pixel, a `size` with no side or a side that is not a finite number of pixels, 1 or more, and a `size` given with a `zoom`.
- Without WebGL2, or when the browser refuses a drawing buffer, `exportPng` rejects with an `Error`.

## Behavior

- The export reads the graph as it is when the call starts: pending data is flushed first. Nodes that move while the export waits for images, fonts or shape fills are drawn where they were when it started, so the image never tears and every node it frames stays inside it.
- Shapes are drawn at their data, in the PNG as in the SVG, even while a [shape editor](/docs/api/editor) shows one as a preview, slides it, or waits for its data to answer an edit.
- Sizes set in screen pixels, such as edge widths, labels and nodes with `units: 'screen'`, keep their size whatever the `zoom` of the export.
- `region: 'graph'` frames every node, plus the labels, loops, curved parallel edges, great circle arcs and hulls that reach past them, with `padding` around them. `padding` must be finite, 0 or more, or the export throws a `RangeError`.
- With `size`, the image has exactly that size in pixels and the zoom is chosen to fit the region inside it; `pixelRatio` still sets the image pixels per CSS pixel, so the area drawn is `size` divided by it.
- The background grid, unless `grid` is `false`, and the hulls are drawn as on screen: grid, group containers, hulls, then edges and nodes. With a `window` or a `zoom` that shows other nodes than the screen, each hull wraps the nodes the export shows. HTML anchors are not part of the scene and stay out of both exports.
- Past 4,096 pixels on a side, the PNG is drawn in tiles and encoded strip by strip. Labels are chosen once for the whole image.
- The PNG records its pixel density in a `pHYs` chunk, at 96 dots per inch times `pixelRatio`.
