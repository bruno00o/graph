```ts
import { createTimeline, mountTimeline } from '@bruno00o/graph/timeline'

function createTimeline<S extends string, M extends Mark, E = TimelineEvent>(
  graph: GraphInstance<S, M>,
  options?: TimelineOptions<E>,
): Timeline<E>
function createTimeline<E = TimelineEvent>(options?: TimelineOptions<E>): Timeline<E>

function mountTimeline<E>(timeline: Timeline<E>, options?: TimelineViewOptions): TimelineView
```

`createTimeline` follows the time of a graph made by [`mountGraph`](/docs/api/mount-graph) and keeps it in a store, with the time window of the graph. Without a graph, it counts the `events` it is given and keeps a window of its own in its store. `mountTimeline` renders a timeline in a plain element. See [Time](/docs/time#timeline) for a walkthrough, and [Events](/docs/time#events) for a timeline of the events of your application.

## React

```ts
import { Timeline, useTimeline } from '@bruno00o/graph/react'

function Timeline<E = TimelineEvent>(props: TimelineProps<E>): ReactNode

function useTimeline<E = TimelineEvent>(options?: UseTimelineOptions<E>): UseTimelineResult<E>
```

Use both inside the children of [`<Graph>`](/docs/api/graph-component) or [`<MapGraph>`](/docs/api/map-graph), or anywhere with the `graph` prop or option, which wins over the graph in context. Without a graph from either, they throw; `graph: null` waits for a graph, with an empty state, and `graph: false` makes a timeline without a graph. `<Timeline>` renders the default timeline in a `div` where it stands; its props are the options of `createTimeline` and of `mountTimeline`, and `graph`. With `timeline`, it renders that timeline, such as the one `useTimeline` returns, and leaves the options of `createTimeline` to it. `useTimeline` renders again when the state changes.

## Errors

- A graph that was not created by `mountGraph` throws an `Error`.
- `bins`, `ticks` or `speed` that is not a positive number throws a `RangeError`, as does an `extent` whose start comes after its end.
- `set`, `brush` and `events` with a time that is not a finite number or a valid date throw a `RangeError`.

## Behavior

- The timeline counts again after a change of data, never more often than ten times its own cost allows, and at least 50 ms apart. It reads only the elements whose time changed, and the edges that end on them.
- A new `events` array counts again at once, in `update`. When it starts with the items of the previous array, only the items added are read; otherwise every event is read again. A function given to `eventTime` or `eventKind` reads every event again each time it changes: in React, define it outside the component.
- `hiddenKinds` sets the hidden kinds only when it changes, so `toggleKind` keeps its effect when other options change.
- Bins and ticks follow the calendar of the local time zone: a week starts on Monday, a month on its first day.
- In controlled mode, actions call `onTimeChange` of the graph instead of moving the window. Playback goes on from the window it asked for until a new `time` arrives, so a controlled graph plays smoothly.
- Playback stops when the window cannot move any further, unless `loop` is on. A frame late by more than 100 ms moves the window by 100 ms of playback at most.
- Destroying the graph destroys its timelines, and a timeline created on a destroyed graph comes back destroyed: empty, it never plays. Destroying the timeline leaves the window where it is.
- In the default renderer, the element carries `data-graph-timeline` and `role="group"`. The handles carry `data-part="start"` and `data-part="end"`, the window `data-part="window"`, the cursor of `instant` `data-part="cursor"`; all four are sliders with `aria-valuemin`, `aria-valuemax`, `aria-valuenow` and `aria-valuetext`. The play button carries `aria-pressed`. The buttons of the kinds sit in a group with `data-part="kinds"`, each with `data-kind` and `aria-pressed`, pressed while the kind shows.
- On the window and the cursor, <kbd>Shift</kbd> with the arrow keys calls `stepEvent` when there are events.
- Colors come from the `--graph-…` tokens: `--graph-accent` for the window and the counts inside it, `--graph-ink` and `--graph-ink-muted` for the rest. Events take the colors of their kinds, full inside the window, or before the cursor, and lighter elsewhere.
