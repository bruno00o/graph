title: force
description: A force layout computed in a Web Worker, on the GPU or the CPU.

```ts
import { force } from '@bruno00o/graph/layouts/force'

function force(options?: ForceOptions): Layout
```

Returns a frozen [`Layout`](/docs/api/define-graph#layout) named `'force'`. Pass it as `layout` to `defineGraph`, or to `graph.layout.run` for a single run. See [Force layout](/docs/layout) for a walkthrough.

## Result

<api-table path="layouts/force/index.ts" name="ForceSettings" />

`layout.options` holds the resolved `ForceSettings`. Two `force()` calls with the same settings are equal for the graph: a new definition with an equal layout does not run it again.

## Behavior

- The simulation runs in a Web Worker shipped inside the package, created from a `blob:` URL. No bundler setup is needed.
- On the GPU, it runs in WebGL2 on an `OffscreenCanvas` inside the worker, and needs `EXT_color_buffer_float` and `EXT_float_blend`. Without them, or when the context is lost, the CPU takes over from the last positions.
- Without `Worker`, when the content security policy refuses `worker-src blob:`, or when the worker fails, the simulation continues on the main thread in slices of 8 milliseconds.
- From 100 moving nodes, on runs that move at least half of the nodes, the graph is laid out in levels: a coarse copy first, then finer ones, the last being the graph itself. Coarse levels run on the CPU in the worker, levels of 4,000 nodes or more on the GPU when it is chosen. `multilevel` turns this on at any size or off. Graphs with unfolded groups use a single level. See [Large graphs](/docs/layout#large-graphs).
- Once the forces settle, a last pass turns branches and moves nodes to remove edge crossings, and nodes glide to the result. It stops at its `budget`, skips graphs with more than 4 crossings per edge, and does not run with unfolded groups. See [Untangle crossed edges](/docs/layout#untangle-crossed-edges).
- Nodes with `x` and `y` channels never move. Pinned nodes, dragged or set through `positions.set` during the run, keep their place.
- Unfolded groups stay whole: members pull toward their group with `cohesion`, edges between groups move whole groups, and at the end no container overlaps another container or a node next to it, with `groupSpacing` around each. See [groups in layouts](/docs/layout#groups).
- A [block](/docs/api/layouts#blocks-and-containers) pushes the other nodes as hard as all the nodes it holds, on the CPU, the GPU and every level. Inside a [container](/docs/api/define-graph#layout), `cohesion` pulls the nodes toward their center in place of `gravity`, and below 1,000 nodes a run takes 120 steps unless `steps` is given. The layout's `turns` is `'free'`.

## Follow a drag

`force().follow` lets the neighbors of a dragged node follow it with [`interaction.drag: 'elastic'`](/docs/interaction#let-the-neighbors-follow). It runs on the main thread, on the dragged nodes and the nodes around them only:

- Each edge is a spring whose rest length is its length when the drag starts, stiffer around nodes of low degree, and each node is held lightly to its starting place.
- Two nodes closer than their radii plus 12 units push apart, never further than they were.
- A node wakes once a neighbor has moved half a screen pixel, at most 5,000 of them; it takes 120 steps per second of motion.
- After the drop, the motion cools down over 90 steps, or stops sooner once no node moves more than a twentieth of a screen pixel per step.
- It gives the same positions for the same moves.

The cost per frame grows with the nodes in motion, not with the graph: see [Interaction](/docs/interaction#let-the-neighbors-follow).
