```ts
interface GraphInstance<S extends string = string, M extends Mark = Mark> {
  readonly store: GraphStore<S, M>
  readonly view: GraphView
  readonly selection: GraphSelection
  readonly focus: GraphFocus<M>
  readonly states: GraphStates<FreeState<S>>
  readonly positions: GraphPositions
  readonly layout: GraphLayout<M>
  readonly anchors: GraphAnchors<FreeState<S> | BuiltInState>
  readonly groups: GraphGroups
  readonly paths: GraphPaths<M>
  readonly layers: GraphLayers<LayerName<M>>
  readonly support: GraphSupport
  readonly bundling: GraphBundling
  readonly routing: GraphRouting
  readonly time: GraphTime
  readonly element: HTMLElement
  pick(point: Point): GraphTarget<M> | null
  neighbors(key: Key): Key[]
  edgesOf(key: Key): Key[]
  endpoints(key: Key): { source: Key; target: Key } | undefined
  on<K extends GraphEventName>(name: K, handler: GraphEventHandler<K, M>): () => void
  update(
    options: Partial<
      Omit<
        MountGraphOptions<S, M>,
        'initialView' | 'initialFolded' | 'initialTime' | 'initialHiddenLayers'
      >
    >,
  ): void
  destroy(): void
}
```

`S` is the union of the state names and `M` the union of the marks of the definition. They type the state methods, and the targets of `pick`, `focus.get`, the events and the store. `update` takes a definition of the same marks, or of fewer. See [TypeScript](/docs/typescript).

```ts
  readonly y: number
  readonly zoom: number

```

<api-table path="index.ts" name="GraphView" />

`fit` without keys frames every node. `padding` defaults to 32 pixels. Durations are in milliseconds, and zero with `prefers-reduced-motion`. Every call, and each frame of its animation, stays within the [view limits](/docs/view#view-limits) of the definition, and works with `pan: false` and `zoom: false`. In controlled mode, `set`, `fit` and `zoomBy` call `onViewChange` instead of moving the view.

## Positions

Positions are in world units. `set` emits `positionchange` with the origin `'api'`. During a layout run, the nodes moved by `set` are pinned until the run ends.

## Layout

```ts
interface GraphLayout {
  run(layout?: Layout, options?: LayoutRunOptions): Promise<boolean>
  stop(): void
}

interface LayoutRunOptions {
  readonly keys?: Iterable<Key>
  readonly fit?: boolean | FitOptions
  readonly duration?: number
}
```

`run` applies pending data changes, stops the current run, then lays out every free node, or only `keys`, with `layout` or the layout of the definition. It resolves to `true` when the run ends and `false` when it is stopped, replaced or the graph is destroyed. It rejects when there is no layout to run. `stop` ends the current run and leaves nodes where they are. See [Layouts](/docs/layout).

## Bundling

```ts
interface GraphBundling {
  run(): Promise<boolean>
}
```

<api-table path="index.ts" name="GraphBundling" />

Bundles are computed on their own once nodes stand still. `run` computes them now, without waiting, from the current positions. It resolves to `false` when the definition has no `bundling`, when more edges than `maxEdges` would be bundled, or when the run is replaced. See [Edge bundling](/docs/bundling).

## Anchors

```ts
interface GraphAnchors<S extends string> {
  set(element: HTMLElement, options: AnchorOptions<S>): () => void
  remove(element: HTMLElement): void
}
```

`set` moves the element into a layer over the canvas, inside `graph.element`, and places it from then on at each frame, with a CSS transform: no code of yours runs while the view or the nodes move. Calling `set` again on the same element changes its options. `destroy` removes every pinned element. Pinned elements are HTML, not part of the scene: [exports](/docs/export) leave them out.

```ts
const menu = document.createElement('div')
graph.anchors.set(menu, { state: 'selected', side: 'top', interactive: true })
```

<api-table path="index.ts" name="AnchorOptions" />

The element keeps its own size: the anchor reads it with a `ResizeObserver`. It is hidden with `visibility: hidden` while its target is missing, off screen, or out of the `when` state. A state given to `state` or `when` must be declared in the definition, or be `selected`, `hovered` or `focused`; otherwise `set` throws.

Without `interactive`, the element lets every pointer event through to the graph. With it, the element takes clicks and drags, and the wheel still goes to the graph unless the element under the pointer can scroll. Keys pressed inside the element do not reach the graph shortcuts.

In React, use [`<Anchor>`](/docs/api/anchor).

## Graph state

```ts

  readonly view: View
  readonly width: number
  readonly height: number

  readonly selection: ElementKeys

  readonly folded: readonly Key[]
  readonly bundling: GraphBundlingStatus
  readonly routing: GraphRoutingStatus
  readonly lens: GraphLensState | null
  readonly time: TimeWindow | null
  readonly hiddenLayers: readonly LayerName<M>[]
}

interface GraphLayoutStatus {
  readonly running: boolean
  readonly progress: number
}

interface GraphBundlingStatus {
  readonly running: boolean
}

interface GraphRoutingStatus {
  readonly running: boolean
}
```

<api-table path="index.ts" name="GraphState" />

`width` and `height` are the size of the graph in CSS pixels. `positionsVersion` changes whenever a position changes; read the positions themselves with `positions.get`. `layout.progress` goes from 0 to 1 during a run. `bundling.running` is `true` while bundles are computed, and `routing.running` while routes are.
