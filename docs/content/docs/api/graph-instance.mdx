title: GraphInstance
description: The object returned by mountGraph, and by the ref of the Graph component.

`S` is the union of the state names and `M` the union of the marks of the definition. They type the state methods, and the targets of `pick`, `focus.get`, the events and the store. `update` takes a definition of the same marks, or of fewer. See [TypeScript](/docs/typescript).

Data changes, from `update` or from a live source, are applied at the next frame. Every method that reads or moves elements by key or by point applies them first, so it sees the data you just passed: `pick`, `neighbors`, `edgesOf`, `endpoints`, `datumOf`, `issues`, `count`, `view.fit`, `focus.set`, `positions`, `groups`, `paths`, `support`, `layout.run`, `bundling.run` and `routing.run`. When nothing is pending, this costs nothing. States and the selection hold keys, with or without an element, so they need no data.

## Lists of keys

The methods and options that take several keys or names, such as `groups.fold`, `layers.hide`, `selection.set`, `view.fit` or `initialFolded`, take a `KeyList`: an array, a `Set`, `Map#keys()`, a generator or any other iterable object.

```ts
type KeyList<K extends Key = Key> = Iterable<K> & object
```

A single string is refused: it would iterate over its characters, so `groups.fold('g1')` would fold `'g'` and `'1'`. Pass `['g1']`. A string that gets through anyway, from plain JavaScript or a cast, keeps that behavior and logs a warning once per method in development.

## Lifecycle

`destroy` removes the element, frees the WebGL resources, the workers and the listeners, then aborts `signal`. It runs once; later calls do nothing. A graph also ends when the `signal` passed to [`mountGraph`](/docs/api/mount-graph#signal) aborts.

### Signal

`signal` aborts once the graph is destroyed, with an `AbortError` `DOMException` whose message is `graph: the graph was destroyed`, or with the reason of the `signal` of the mount when that signal destroyed the graph. Its listeners run once `destroy` is done: `destroyed` is `true` and the element is gone. Pass it to the work that should end with the graph:

```ts
const timer = setInterval(refresh, 1000)
graph.signal.addEventListener('abort', () => clearInterval(timer))
window.addEventListener('resize', fit, { signal: graph.signal })
const response = await fetch(url, { signal: graph.signal })
```

`destroyed` is `true` from the call to `destroy` on.

### Drawn

`drawn()` resolves after the next frame the graph draws, the first one included. It never asks for a frame of its own: when no frame is due, it resolves on the next animation frame, without drawing. While the WebGL context is lost, it waits for the context to come back. On a [map](/docs/map), it resolves once the map has drawn the layer of the graph. Once the graph is destroyed, it rejects with the reason of `signal`.

```ts
graph.update({ definition: next })
await graph.drawn()
const canvas = graph.element.querySelector('canvas')
```

### Loaded

`loaded()` resolves once no [live source](/docs/data#loading) of the definition is loading and what they delivered is applied: `count()`, `issues()` and the store hold the complete data. It resolves at once when nothing loads, as with array data, and also when a source failed: `store.state.data.failed` lists it. A layout may still run after it: wait for `layoutend`, or `await graph.drawn()` for the next frame. Once the graph is destroyed, it rejects with the reason of `signal`, also while it waits.

```ts
const graph = mountGraph(element, { definition, ariaLabel: 'Sample graph' })
await graph.loaded()
report(graph.count().nodes)
```

### After destroy

Every member stays callable after `destroy`, and none throws. Reads answer from the last state of the store or return nothing, actions do nothing, and promises resolve to `false` or reject.

| Member | After `destroy` |
| --- | --- |
| `store` | Keeps its last state and notifies no one again |
| `element` | Removed from the page |
| `view.get`, `view.toScreen`, `view.toWorld`, `selection.get`, `focus.get`, `states.get`, `states.has`, `groups.folded`, `groups.isFolded`, `layers.hidden`, `layers.isHidden`, `time.get`, `lens.get`, `lens.toWorld` | Answer from the last state of the store |
| `groups.keyOf` | Returns the key, as before |
| `pick`, `paths.shortest` | `null` |
| `endpoints`, `datumOf`, `positions.get`, `groups.parent` | `undefined` |
| `neighbors`, `edgesOf`, `issues`, `groups.children`, `layers.names` | An empty array |
| `positions.snapshot` | An empty `Map` |
| `count` | Zero for every count |
| `paths.reach`, `support.carriers`, `support.carried` | An empty result |
| `on`, `anchors.set` | Register nothing and return a function that does nothing |
| `update`, `destroy`, and the methods that change the view, the selection, the focus, the states, the positions, the groups, the layers, the time, the lens or the anchors | Do nothing |
| `layout.run`, `bundling.run`, `routing.run` | Resolve to `false`. A layout run in progress at `destroy` resolves to `false` too |
| `drawn`, `loaded` | Reject with `signal.reason` |
| [`exportPng`, `exportSvg`](/docs/api/export) and [`exportMapPng`](/docs/api/map) | Reject with an error |
| [`createMinimap`](/docs/api/minimap), [`createLegend`](/docs/api/legend), [`createTimeline`](/docs/api/timeline) | Return a companion already destroyed: empty, it holds no worker, observer or timer, never changes and never plays |

A graph mounted with a signal already aborted comes back in this state: nothing is mounted, its element is never added to the page, and a warning is logged in development. Its store holds the view, the selection, the states, the folded groups, the time window and the hidden layers of the options.

An event handler, a store subscriber or a controlled callback can call `destroy`: the graph stops at once and changes nothing after it. See [Errors in handlers](/docs/api/events#errors-in-handlers).

## Numbers

Numbers given to the graph must be finite. A call with one that is not, such as `NaN` from a division by zero, throws a `RangeError` and changes nothing:

- the `x`, `y` and `zoom` of `view.set`, and the factor of `view.zoomBy`, which must also be above 0;
- the `padding` and `maxZoom` of `view.fit`, and of the `fit` of `layout.run`;
- every `duration`;
- the `at`, `radius` and `zoom` of `lens.set`, whose `radius` must also be above 0;
- the ends of the window of `time.set`.

`layout.run` rejects with that error instead of throwing. `positions.set` reads its entries as data, the way the `x` and `y` channels ignore a value that is not finite: an entry whose `x` or `y` is not finite is skipped, with a warning in development, its node stays where it is, and the other entries apply. Once the graph is destroyed, no call throws.

## View

<api-table path="index.ts" name="GraphView" />

<api-table path="index.ts" name="View" />

`fit` frames its `nodes`, `edges` and `shapes`, or every node and shape when it names none; a path or the selection fits as is. `padding` defaults to the `padding` of the [view of the definition](/docs/view#padding), 32 pixels unless set. Called before the element has a size, `fit` waits for one. During the first layout run, the view keeps framing the nodes of the last `fit` while they move, until the view is moved. Durations are in milliseconds, and zero with `prefers-reduced-motion`. An animation goes straight to its end when the last frames took longer than what is left of it. Every call, and each frame of its animation, stays within the [view limits](/docs/view#view-limits) of the definition, and works with `pan: false` and `zoom: false`. In controlled mode, `set`, `fit` and `zoomBy` call `onViewChange` instead of moving the view. A view, a factor or an option that is not finite throws a `RangeError`: see [Numbers](#numbers).

## Positions

<api-table path="index.ts" name="GraphPositions" />

Positions are in world units. `set` emits `positionchange` with the origin `'api'`. During a layout run, the nodes moved by `set` are pinned until the run ends. An entry whose `x` or `y` is not finite is skipped, with a warning in development: see [Numbers](#numbers).

`snapshot` reads every node of the data at once: nodes hidden in folded groups, group nodes and nodes placed by your data included. A node that glides, after `set` with a duration, after a layout result or toward new `x` and `y` values, is read where its glide ends, so a snapshot taken during the glide saves where the nodes are going. Pass `settled: false` to read where they are drawn now, as `get` does. Give the map back to `set` to restore it.

```ts
const saved = graph.positions.snapshot()
graph.positions.set(saved, { duration: 400 })
```

## Issues

```ts
issues(): readonly GraphIssue[]
```

The problems present in the data now: an item without a key, a key held twice, a `parent` that names no node or would make a node contain itself, a `supportedBy` that names no edge, a [shape](/docs/shapes) that cannot be drawn as given. The graph draws around each one: it keeps the first item of a key, leaves a node without its parent at the top level, and skips the item without a key. A problem goes away once the data no longer holds it, so `issues()` is a state, not a log.

The same array comes back until the problems change. Each change emits `issueschange` with the new list, and in development, problems that appear are summarized by type in a single console warning per data change. See [Problems in the data](/docs/data#problems-in-the-data).

```ts
graph.on('issueschange', ({ issues }) => {
  report(issues.filter((issue) => issue.type === 'duplicate-key'))
})
```

## Count

```ts
count(): GraphCountOf<M>
type GraphCountOf<M extends Mark> = HasShapes<M> extends true ? GraphShapeCount : GraphCount
```

<api-table path="index.ts" name="GraphCount" />

<api-table path="index.ts" name="GraphShownCount" />

With a [shape mark](/docs/shapes) in the definition, the counts hold the shapes as well:

<api-table path="index.ts" name="GraphShapeCount" />

<api-table path="index.ts" name="GraphShownShapeCount" />

`nodes`, `edges` and `pending` count the data, whatever is drawn. `shown` counts what is drawn now, in the view or not: a folded group is one node and hides its members, merged edges count once, and an element out of its [zoom range](/docs/zoom), out of the [time window](/docs/time), in a [hidden layer](/docs/multilayer) or hidden by a state with `hide` does not count. Counting reads every element, so `count()` keeps its result, and returns the same object, until the data, the folded groups, the zoom of a graph with zoom ranges, the time window, the hidden layers or the members of a hiding state change.

```ts
const { nodes, shown } = graph.count()
status.textContent = `${shown.nodes} of ${nodes} nodes shown`
```

## Layout

<api-table path="index.ts" name="GraphLayout" />

`run` applies pending data changes, stops the current run, then lays out every free node, or only `keys`, with `layout` or the layout of the definition. It resolves to `true` when the run ends and `false` when it is stopped, replaced or the graph is destroyed. It rejects when there is no layout to run. `stop` ends the current run and leaves nodes where they are. See [Layouts](/docs/layout).

## Bundling

<api-table path="index.ts" name="GraphBundling" />

Bundles are computed on their own once nodes stand still. `run` computes them now, without waiting, from the current positions. It resolves to `false` when the definition has no `bundling`, when more edges than `maxEdges` would be bundled, or when the run is replaced. See [Edge bundling](/docs/bundling).

## Routing

<api-table path="index.ts" name="GraphRouting" />

Routes are computed on their own once nodes stand still. `run` routes now, from the current positions, and resolves to `false` when the definition has no `routing`, when more edges than `maxEdges` would be routed, or when the run is replaced. See [Edge routing](/docs/routing).

## Anchors

<api-table path="index.ts" name="GraphAnchors" />

`set` moves the element into a layer over the canvas, inside `graph.element`, and places it from then on at each frame, with a CSS transform: no code of yours runs while the view or the nodes move. Calling `set` again on the same element changes its options. `destroy` removes every pinned element. Pinned elements are HTML, not part of the scene: [exports](/docs/export) leave them out.

```ts
const menu = document.createElement('div')
graph.anchors.set(menu, { state: 'selected', side: 'top', interactive: true })
```

### Targets

`AnchorOptions` takes exactly one target. The types refuse two targets at once, and `when` where it does not apply.

| Target | Follows | `when` |
| --- | --- | --- |
| `{ node: key }` | The node, on its box | Shows the element only while the node is in the state |
| `{ nodes: keys }` | The bounding box of the nodes. Missing keys are skipped | Shows it while one of the nodes is in the state |
| `{ edge: key }` | The anchor of the edge label | Shows it while the edge is in the state |
| `{ point }` | A point of the world, in world units | Not accepted |
| `{ state }` | The bounding box of the nodes in the state, as it changes | Not accepted |

The types are `AnchorNodeTarget`, `AnchorNodesTarget`, `AnchorEdgeTarget`, `AnchorPointTarget` and `AnchorStateTarget`, and their union `AnchorTarget`. A target built apart from the placement keeps its type when it is inferred:

```ts
graph.on('contextmenu', ({ target, world }) => {
  const at = target?.kind === 'node' ? { node: target.key } : { point: world }
  graph.anchors.set(menu, { ...at, side: 'right', align: 'start', interactive: true })
})
```

### Placement

<api-table path="index.ts" name="AnchorPlacement" />

The element keeps its own size: the anchor reads it with a `ResizeObserver`. It is hidden with `visibility: hidden` while its target is missing, off screen, or out of the `when` state. A state given to `state` or `when` must be declared in the definition, or be `selected`, `hovered` or `focused`; otherwise `set` throws.

Without `interactive`, the element lets every pointer event through to the graph. With it, the element takes clicks and drags, and the wheel still goes to the graph unless the element under the pointer can scroll. Keys pressed inside the element do not reach the graph shortcuts.

In React, use [`<Anchor>`](/docs/api/anchor).

## Groups

<api-table path="index.ts" name="GraphGroups" />

`fold`, `unfold`, `toggle` and `set` emit `foldchange`. In controlled mode, they call `onFoldChange` instead of changing the folded groups. See [Groups](/docs/groups).

## Paths

<api-table path="index.ts" name="GraphPaths" />

Shortest paths and reachable nodes, on the data or, with `visible: true`, on the graph as drawn. The results hold node and edge keys, ready for `states.set`. See [Paths](/docs/paths) and the [reference](/docs/api/paths).

## Layers

<api-table path="index.ts" name="GraphLayers" />

`L` is the union of the `layer` names of the marks. `hide`, `show`, `toggle` and `set` emit `layerchange` and update `hiddenLayers` in the store. In controlled mode, they call `onLayerChange` instead. See [Multilayer graphs](/docs/multilayer).

## Support

<api-table path="index.ts" name="GraphSupport" />

Walks the `supportedBy` links of edges, down to the edges that carry an edge and up to the edges it carries. Both apply pending data changes first. See [Multilayer graphs](/docs/multilayer#support) and the [reference](/docs/api/support).
