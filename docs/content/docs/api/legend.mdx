```ts
import { createLegend, mountLegend } from '@bruno00o/graph/legend'

function createLegend<S extends string, M extends Mark>(
  graph: GraphInstance<S, M>,
  options?: LegendOptions<S>,
): Legend<S, M>

function mountLegend<S extends string, M extends Mark>(
  legend: Legend<S, M>,
  options?: LegendViewOptions<M>,
): LegendView<M>
```

`createLegend` reads the legend of a graph made by [`mountGraph`](/docs/api/mount-graph) and keeps it in a store. `mountLegend` renders a legend in a plain element. See [Minimap and legend](/docs/minimap-and-legend#legend) for a walkthrough.

### Scales of a mark

A mark with [`scales`](/docs/scales#scales-of-a-mark) of its own has an entry in `marks`, in the order of the marks, nodes first. Its id is `n` or `e` and the position of the mark among the marks of its kind, from 0, such as `n1`. The ids of its categories carry it after `c:`, such as `c:n1:string:north`, so the same value can stand in two scales; a category of a shared scale keeps `c:string:north`. `keys`, `hover`, `toggle` and `only` take both; `only` switches off the other categories of the same scale.

<api-table path="legend/index.ts" name="LegendMarkScales" />

```ts
type LegendScalesOf<M extends Mark = Mark> = LegendMarkScales<…>
```

`LegendScalesOf<M>` gives `mark` the names of the marks of `M`.

### Looks

```ts
type LegendLook<M extends Mark = Mark> = LegendNodeLook<…> | LegendEdgeLook<…>
type LegendItem<M extends Mark = Mark> = LegendCategory | LegendLook<M>
```

`LegendLook<M>` narrows on `kind`, then on `mark`, to the names of the marks of `M`. Elements with a raw color, set by `raw()`, have no category: like elements with a `fill`, they count only under their look.

### Layers

One item per layer named by the marks, hidden layers included, with the id `l:` followed by the name. Switching a layer item off hides the layer through [`graph.layers`](/docs/api/graph-instance#layers), so it goes through `onLayerChange` in controlled mode; `off` lists the ids of the hidden layers along with the other items switched off. `keys` and the `highlight` state cover every element of the layer.

## React

```ts
import { Legend, useLegend } from '@bruno00o/graph/react'

function Legend<S extends string = string, M extends Mark = Mark>(
  props: LegendProps<S, M>,
): ReactNode

function useLegend<S extends string = string, M extends Mark = Mark>(
  options?: UseLegendOptions<S, M>,
): UseLegendResult<S, M>
```

Use both inside the children of [`<Graph>`](/docs/api/graph-component) or [`<MapGraph>`](/docs/api/map-graph), or anywhere with the `graph` prop or option, which wins over the graph in context. Without a graph from either, they throw. `<Legend>` renders the default legend in a `div` where it stands; its props are the options of `createLegend` and of `mountLegend`, and `graph`. `useLegend` renders again when the state changes.

## Errors

- A graph that was not created by `mountGraph` throws an `Error`.
- A `highlight` or `hidden` state missing from `states` throws an `Error`, as in `graph.states.set`. A state that a later definition removes is left alone, with a warning in development.

## Behavior

- Counts and keys cover what the graph draws: nodes hidden in a folded group or by a state with `hide` are left out, and an edge between folded groups counts once. The legend reads past its own `hidden` state, so the items it switches off stay listed even when that state hides its members.
- A categorical scale lists the values of its `domain` even without elements, and at most 64 categories. Items switched off stay listed while they have no element.
- The legend reads the graph again after a change of data or definition, never more often than ten times its own cost allows, and at least 50 ms apart.
- Destroying the legend empties its `highlight` and `hidden` states. Destroying the graph destroys its legends, and a legend created on a destroyed graph comes back destroyed and empty.
- In the default renderer, items are toggle buttons with `aria-pressed` when `toggle` is on, plain rows otherwise. The element carries `data-graph-legend`, its items `data-item` with their id.
