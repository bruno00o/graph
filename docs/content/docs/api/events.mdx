Subscribe with `graph.on(name, handler)`, which returns the function that unsubscribes. In React, use the matching prop of `<Graph>` or `useGraphEvent`. Payloads take `M`, the union of the marks of the definition, which types their targets: `mountGraph` and `<Graph>` pass it for you.

In React, each event has a prop of [`<Graph>`](/docs/api/graph-component#props) named after it: `onClick`, `onDoubleClick`, `onPositionChange`, `onLayoutEnd` and so on.

## Targets

```ts
interface NodeTarget<T = unknown, N extends MarkName = MarkName> {
  readonly kind: 'node'
  readonly key: Key
  readonly datum: T
  readonly mark: N
}

interface EdgeTarget<T = unknown, N extends MarkName = MarkName> {
  readonly kind: 'edge'
  readonly key: Key
  readonly datum: T
  readonly mark: N
  readonly aggregate?: AggregateEdge<T>
}

type GraphTarget<M extends Mark = Mark> =
  M extends NodeMark<infer T, infer N>
    ? NodeTarget<T, N>
    : M extends EdgeMark<infer T, infer N>
      ? EdgeTarget<T, N>
      : NodeTarget | EdgeTarget
```

`GraphTarget<M>` is a `NodeTarget` or an `EdgeTarget` for each mark of `M`, the union of the marks of the definition. `datum` is the item from your data, typed by its mark, and `mark` is the `name` of that mark, `undefined` without one. Narrow on `kind`, then on `mark` when several marks of one kind carry different types: see [TypeScript](/docs/typescript). Without `M`, `datum` is `unknown`.

## Payloads

```ts
interface GraphPointerEvent<M extends Mark = Mark> {
  readonly target: GraphTarget<M> | null
  readonly point: Point
  readonly world: Point
  readonly originalEvent: MouseEvent
}

interface GraphTargetEvent<M extends Mark = Mark> {
  readonly target: GraphTarget<M>
  readonly originalEvent: MouseEvent
}

interface GraphDragEvent<M extends Mark = Mark> {
  readonly target: Extract<GraphTarget<M>, { readonly kind: 'node' }>
  readonly keys: readonly Key[]
  readonly point: Point
  readonly world: Point
  readonly originalEvent: PointerEvent
}

interface GraphPositionEvent {
  readonly origin: 'drag' | 'api' | 'layout'
  readonly positions: ReadonlyMap<Key, Point>
}

interface GraphFocusEvent<M extends Mark = Mark> {
  readonly target: GraphTarget<M> | null
}

interface GraphFoldEvent {
  readonly folded: readonly Key[]
}

interface GraphLayoutEvent {
  readonly name: string
}

interface GraphLayoutEndEvent extends GraphLayoutEvent {
  readonly completed: boolean
}
```

- `point` is in screen pixels relative to the graph element, `world` in world units.
- `keys` lists every node moved by the drag: the whole selection when the dragged node is selected, and the nodes inside a dragged group.
- `folded` lists the keys of every folded group after the change.
- `positions` holds the target positions. Moves that come from your data do not emit `positionchange`.
- With the origin `'layout'`, `positions` holds every node the run moved. A stopped run emits nothing.
- `name` is the name of the layout, `'force'` for [`force()`](/docs/api/force). `completed` is `false` when the run was stopped or replaced.

## Order

`click` fires before the default selection, so a handler sees the selection as it was. `selectionchange` and `viewchange` fire on every change, from the user or from code. In controlled mode, `selectionchange` fires when a new `selection` is applied, and `onSelectionChange` on `<Graph>` receives requests instead of events. `foldchange` and `onFoldChange` follow the same rule with `folded`.

A `doubleclick` on a group folds or unfolds it after the handlers run, unless one calls `originalEvent.preventDefault()`.

At the end of a layout run, `positionchange` fires before `layoutend`. Nodes that arrive during a run join it without a new `layoutstart`, and a run replaced by another ends with `completed: false` before the next `layoutstart`.
