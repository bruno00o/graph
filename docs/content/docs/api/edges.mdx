`source` and `target` are required. An edge whose two ends are not both present waits until they are. `T` is the item type and `N` the type of `name`: both type the targets of the edges, see [TypeScript](/docs/typescript). `L` is the type of `layer`, `undefined` without one.

## Options

`width` and `color` take a number literal for `width`, or a function wrapped in [`raw()`](/docs/api/nodes#types), to skip the scale. See [Marks and channels](/docs/marks#channels-and-styles).

## Scales

`scales` gives the mark its own `color` and `width` scales, with their own extents and categories. The ends of its edges use them too. Other marks keep the shared scales of [`defineGraph`](/docs/api/define-graph#scales). See [Scales of a mark](/docs/scales#scales-of-a-mark).

## Layers and support

`layer` puts the edges of the mark in a layer that `graph.layers` hides and shows at run time. Between the same two nodes, edges of different layers form one band per layer, in the order of the marks. `supportedBy` gives, for each edge, the keys of the edges that carry it, in path order. A key that names no edge is reported in `issues` as `missing-carrier`, and the walk skips it until that edge arrives. See [Multilayer graphs](/docs/multilayer).

## Labels

`EdgeLabelOptions` has the text options of a node label: `text`, `background`, `color`, `size`, `weight`, `font` and `maxWidth`. See [`LabelTextOptions`](/docs/api/nodes#labels). The default size is 11.

<api-table path="index.ts" name="EdgeLabelOptions" />

- The label sits halfway along the edge, on the arc of a curved edge, and turns with it while staying upright.
- Without a background, it sits above the line. With one, it is centered on the line.
- It shows only when it fits between the two nodes. The hovered or focused edge shows it over other labels.

```ts
edges<Link>(links, {
  source: 'from',
  target: 'to',
  label: { text: 'name', size: 10, color: 'var(--graph-ink-muted)', background: true },
})
```

## Ends

`ends` gives each end of an edge its own look and label, on either side of `split`. See [Edge ends](/docs/marks#edge-ends).

```ts
type EdgeEnd = 'source' | 'target'
```

<api-table path="index.ts" name="EdgeEndsOptions" />

<api-table path="index.ts" name="EdgeEndOptions" />

- The widest end gives the width used for picking and for the middle label.
- An aggregated edge takes the ends of `aggregate.ends`, read from the `AggregateEdge`, or else those of its first merged edge, whose labels show only when it merges a single edge. See [both directions on one line](/docs/transformations#both-directions-on-one-line).
- `target.end` reports the end under the pointer, measured along the visible length. It is set only on edges of a mark with `ends`, `{}` included.

```ts
type Link = {
  id: string
  from: string
  to: string
  out: number
  back: number
  backLabel: string
}

edges<Link>(links, {
  source: 'from',
  target: 'to',
  ends: {
    source: { color: 'out', dash: 'dashed' },
    target: { color: 'back', label: { text: 'backLabel', background: true } },
  },
})
```

## Parallel edges and loops

Edges that share the same two nodes, in either direction, bend apart in symmetric arcs; an edge alone on its pair stays straight. An edge from a node to itself is a loop, and several loops nest. There is no option for the curvature yet.

## Merged edges

An end inside a folded group is drawn at the outermost folded group that holds it. The edges of one mark that land on the same two ends, in the same direction, draw as one aggregated edge; an edge whose two ends land in the same group is hidden. `merge` merges the parallel edges between visible nodes too. See [Transformations](/docs/transformations#merge-parallel-edges).

<api-table path="index.ts" name="EdgeMergeOptions" />

`aggregate` styles the aggregated edges from an `AggregateEdge`: the merged edges with their count, split by direction.

```ts

>
```

<api-table path="index.ts" name="AggregateEdge" />

<api-table path="index.ts" name="AggregateDirection" />

`betweenGroups` chooses where the edges between two unfolded groups draw: between their members, or as one aggregated edge per pair of groups. See [one edge between two groups](/docs/groups#one-edge-between-two-groups).

```ts
type EdgesBetweenGroups = 'members' | 'groups'
```

- With `directed: false`, an aggregated edge points the way of the first edge in its `keys`: `forward` holds the edges that go that way, `backward` the others. Otherwise `forward` holds every merged edge and `backward` none.
- Without `aggregate`, an aggregated edge looks like its first merged edge. An option that `aggregate` leaves out takes the value of the first merged edge, `ends` included. Labels, end labels included, show only when it merges a single edge.
- Arrows join the arrow of the first edge of each direction, turned to the orientation of the aggregated edge: two opposite edges with `arrow: 'target'` give an arrow at each end.
- Its `time` goes from the earliest start to the latest end of the merged edges, or is missing when one of them has none.

```ts
edges<Link>(links, {
  source: 'from',
  target: 'to',
  merge: { directed: false },
  aggregate: {
    width: (aggregate) => aggregate.count,
    ends: {
      target: { color: (aggregate) => aggregate.forward.count },
      source: { color: (aggregate) => aggregate.backward.count },
    },
  },
})
```

## Example

```ts
type Link = { id: string; from: string; to: string; kind: 'main' | 'side' }

edges<Link>(links, {
  source: 'from',
  target: 'to',
  color: 'kind',
  arrow: 'target',
  dash: (link) => (link.kind === 'side' ? 'dashed' : 'solid'),
})
```
