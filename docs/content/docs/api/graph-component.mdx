---
title: Graph
description: The React component that mounts a graph and renders overlays above it.
---

```tsx
import { Graph } from '@bruno00o/graph/react'

<Graph definition={definition} ariaLabel="Sample graph" style={{ height: 480 }} />
```

```ts
function Graph<S extends string = string, M extends Mark = Mark>(props: GraphProps<S, M>): JSX.Element
```

`S` and `M` come from `definition`: they type the targets of the event props and the instance given to `ref`. A ref object typed as a plain `GraphInstance` works too.

## Props

<api-table path="react/index.tsx" name="GraphProps" />

Each event prop receives the payload of the matching [event](/docs/api/events). The latest function passed is always called. An event prop or a controlled callback, such as `onSelectionChange`, that throws stops neither the other handlers nor the graph: see [Errors in handlers](/docs/api/events#errors-in-handlers).

With `selection`, `onSelectionChange` receives selection requests and the graph only changes when `selection` does. `folded` and `onFoldChange` work the same way for [groups](/docs/groups), `view` and `onViewChange` for the [view](/docs/view#controlled-view), and `time` and `onTimeChange` for the [time window](/docs/time#controlled-window). `onSurfaceChange` receives `surfacechange` once the graph has moved onto a map or back to its canvas, whether `surface` or the map itself moved it: see [Map](/docs/map#with-and-without-a-map).

## Behavior

- The wrapping `div` takes the position that your `className`, a stylesheet or `style` give it, such as `absolute inset-0`. When nothing positions it, the component makes it `relative`. The graph fills it, so it needs a height from the page, and children render above the canvas. To pin a child to a node or an edge, wrap it in [`<Anchor>`](/docs/api/anchor).
- The graph mounts once, in a layout effect, and is destroyed on unmount. Under StrictMode, one instance remains.
- Children only render once the graph exists, so `useGraph` always returns an instance.
- `surface` moves the graph onto a map, made by [`useMapSurface`](/docs/api/map-graph#usemapsurface), and `null` brings it back to its canvas. It is applied with `definition`, in one `update`, so the graph never draws one side with the definition of the other. The instance, its children and their state stay: no remount. A graph sent back to its canvas by the map, removed or released, stays there until `surface` changes again.
- `suspended` suspends the graph while `true` and resumes it once `false`: see [Suspended](#suspended). Left out, the instance alone suspends and resumes it.
- `keepFrame` set to `false` keeps no copy of the last frame while the graph is suspended, and can change at any time. It defaults to `true`.
- For a graph that only lives inside a MapLibre map, use [`<MapGraph>`](/docs/api/map-graph), which shares the same context.

## Suspended

`suspended` goes through [`suspend` and `resume`](/docs/api/graph-instance#suspend), in a layout effect: the instance, its children, its overlays and its state stay, only the WebGL context goes. Given `true` at mount, the graph creates no context until the prop turns `false`. `onSuspendChange` receives `suspendchange` on each change, and `useGraphState((state) => state.suspended)` reads it. `keepFrame={false}` spares the copy of the last frame each suspended graph keeps, and leaves an empty box until the graph resumes. `<MapGraph>` has neither prop: the map owns its context.

```tsx
function Card({ definition }: { readonly definition: GraphDefinition }) {
  const [card, setCard] = useState<HTMLElement | null>(null)
  const [shown, setShown] = useState(false)
  useEffect(() => {
    if (!card) return
    const observer = new IntersectionObserver(([entry]) => setShown(entry?.isIntersecting ?? false))
    observer.observe(card)
    return () => observer.disconnect()
  }, [card])
  return (
    <section ref={setCard} style={{ height: 320 }}>
      <Graph definition={definition} ariaLabel="Sample graph" suspended={!shown} />
    </section>
  )
}
```
