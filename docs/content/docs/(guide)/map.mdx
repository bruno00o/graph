## Install

`@bruno00o/graph/map` draws the graph inside a [MapLibre GL JS](https://maplibre.org) map, version 6 or later. MapLibre is an optional peer dependency: install it next to the library.

```sh
pnpm add maplibre-gl
```

## Mount on a map

Place the nodes with `longitude` and `latitude`, create the map, then mount the graph on it.

```ts
import { defineGraph, edges, nodes } from '@bruno00o/graph'
import { mountMapGraph } from '@bruno00o/graph/map'
import { Map } from 'maplibre-gl'
import 'maplibre-gl/dist/maplibre-gl.css'

const definition = defineGraph({
  marks: [
    edges(routes, { source: 'from', target: 'to' }),
    nodes(places, { longitude: 'lng', latitude: 'lat', label: 'name', color: 'group' }),
  ],
})

const map = new Map({ container, style: 'https://demotiles.maplibre.org/style.json', center: [10, 48], zoom: 3 })
const graph = mountMapGraph(map, { definition, ariaLabel: 'Places and routes' })
```

`mountMapGraph` takes any map, with any style, before or after its style loads. It adds a custom layer to the style and draws in the map's own WebGL context, on top of the style or under the layer named by `beforeId`, such as the place labels of the basemap. It returns the same [`GraphInstance`](/docs/api/graph-instance) as `mountGraph`: data updates, states, selection, events, anchors and the store work the same way. Call `graph.destroy()` before `map.remove()`, or pass a `signal` that you abort before removing the map.

The layer comes back by itself after `setStyle`, and after the browser restores a lost WebGL context: MapLibre then warns that it cannot restore custom layers, and the graph adds its own back. See [Browser support](/docs/browser-support#context-loss).

Node sizes are in screen pixels, so a node keeps its size as the map zooms. Edges are straight in Web Mercator, as on the map, unless they follow [great circles](#great-circles).

The map keeps its own camera at mount: the graph does not frame its nodes by itself. To frame them, call `fit` right after mounting; it waits until the graph has measured the map.

```ts
const graph = mountMapGraph(map, { definition, ariaLabel: 'Places and routes' })
graph.view.fit({ padding: 40 })
```

The map sets the zoom limits, and the `view` of the definition does not apply: `padding` and `autoFit` there change nothing, and each `fit` takes its own `padding`, 32 pixels by default.

See the [nodes on a flat map](/examples/flat-map) example.

## React

`@bruno00o/graph/map/react` exports [`<MapGraph>`](/docs/api/map-graph). It mounts the graph on the map you pass, and destroys it on unmount or when `map`, `id` or `beforeId` change. It takes the props of [`<Graph>`](/docs/api/graph-component) without the view, which belongs to the map. It renders no element of its own: its children render where it stands, with the graph in context, so the hooks, `<Anchor>`, `<Legend>` and `<Timeline>` work inside it as inside `<Graph>`.

```tsx title="Places.tsx"
import { MapGraph } from '@bruno00o/graph/map/react'
import { Timeline } from '@bruno00o/graph/react'
import { Map } from 'maplibre-gl'
import { useEffect, useRef, useState } from 'react'

export function Places() {
  const host = useRef<HTMLDivElement>(null)
  const [map, setMap] = useState<Map | null>(null)
  useEffect(() => {
    if (!host.current) return
    const created = new Map({ container: host.current, style, center: [10, 48], zoom: 3 })
    setMap(created)
    return () => created.remove()
  }, [])
  return (
    <div className="stage">
      <div ref={host} className="map" />
      {map ? (
        <MapGraph map={map} definition={definition} ariaLabel="Places and routes">
          <Timeline mode="grow" />
        </MapGraph>
      ) : null}
    </div>
  )
}
```

Create the map in `useEffect`, not `useLayoutEffect`: on unmount, React runs the layout cleanup of `<MapGraph>` before the passive cleanup that removes the map, so the graph leaves the map first. Outside `<MapGraph>`, give the graph to `<Legend>`, `<Timeline>`, `useLegend` or `useTimeline` with their `graph` prop or option: see [React](/docs/react#companions-beside-the-graph).

See the [map component](/examples/map-component) example.

## Globe

The graph follows the projection of the map. Set the globe projection of MapLibre, in the style or at any time, and nodes, edges, labels, badges, images, hulls and the lasso go with it:

```ts
map.on('style.load', () => map.setProjection({ type: 'globe' }))
```

On the globe, an element on the far side is hidden and cannot be picked, and an edge that passes behind the horizon is cut there. Edges between distant nodes bend with the surface; short ones stay straight. When the map zooms in, MapLibre turns the globe into a flat map between zoom 11 and 12, and the graph turns with it.

`graph.view.toScreen` and `toWorld` take the globe into account: `toScreen` gives the point on the globe, also on its far side, and `toWorld` gives the point under the pointer, or, beside the globe, the point of the flat map.

With 100,000 nodes and 200,000 edges on a 1280 × 800 page, the layer takes 12.6 ms per frame while the globe turns, against 7.8 ms on the flat map. Nodes alone take 5.5 ms and 3.9 ms.

## Great circles

Set `geodesic` on an edge mark and its edges follow the shortest path over the Earth, a great circle, between nodes placed by `longitude` and `latitude`:

```ts
edges(routes, { source: 'from', target: 'to', geodesic: (route) => route.long })
```

On the globe, such an edge is an arc of the sphere. On a flat map, it bends toward the poles, and an edge that crosses the antimeridian is cut in two, each part reaching the edge of the world. Arrows, dashes, flows, labels and picking follow the path. Geodesic edges are never bundled, an edge with [waypoints](#routes-along-a-network) ignores `geodesic`, and the option has the same effect on a graph without a map. See [`EdgeOptions`](/docs/api/edges#options).

Examples: [great circles without a map](/examples/great-circles), and [flows on a map](/examples/map-flows).

## Routes along a network

To draw an edge along a road, a river or any line of a network instead of straight, give it the points of that line with `waypoints`. `lineWaypoints` reads a GeoJSON `LineString` or `MultiLineString` geometry as `{ longitude, latitude }` points, the lines of a `MultiLineString` one after the other, and drops the first and last positions, which usually sit on the nodes:

```ts
import { edges, lineWaypoints } from '@bruno00o/graph'

type Road = { id: string; from: string; to: string; geometry: LineStringGeometry }

edges<Road>(roads, {
  source: 'from',
  target: 'to',
  waypoints: (road) => lineWaypoints(road.geometry),
})
```

Pass `{ keepEnds: true }` to keep them, for a line that stops short of its nodes. The edge still starts and ends on its nodes; only the points in between are fixed. See [Waypoints](/docs/marks#waypoints) for the rules shared with plain graphs.

```ts
type LineGeometry = LineStringGeometry | MultiLineStringGeometry
```

- On a flat map, a line that crosses the antimeridian takes the short way, from one point to the next, and is drawn on both sides like a [great circle](#great-circles).
- On the globe, the line follows the surface: stretches longer than 8 world units, about 5.6 degrees at the equator, are split into shorter ones, and a line that passes behind the horizon is cut there. The first and last segments, from the nodes to the line, stay straight on screen.
- Points are stored in world units with double precision and drawn relative to the camera, so a line stays on its road at street level. The GPU keeps them in 32 bits relative to the origin of the positions, which is moved when the camera goes far from it.
- A line drawn by `waypoints` has sharp corners: give it more points for a smoother curve.

With 100,000 edges of 30 points each on a 1280 × 800 page, the first render takes about a second more than straight edges, and a frame while panning costs about twice as much. See the [routes along a network](/examples/map-routes) example.

## With and without a map

The same data can switch between a map and a plain graph. On the map, the `longitude` and `latitude` channels pin each node to its place. Without the map, the [`geo` layout](/docs/layout#geography) uses the same projection, and moves apart the nodes that overlap. Keep the sources, and build one definition for each mode:

```ts
import { defineGraph, edges, geoToWorld, nodes, type View } from '@bruno00o/graph'
import { geo } from '@bruno00o/graph/layouts'

const center = { longitude: 10, latitude: 48 }
const scale = 2048

const onMap = defineGraph({
  marks: [
    edges(routes, { source: 'from', target: 'to' }),
    nodes(places, { longitude: 'lng', latitude: 'lat', label: 'name' }),
  ],
})

const plain = defineGraph({
  marks: [
    edges(routes, { source: 'from', target: 'to' }),
    nodes(places, { label: 'name', units: 'screen' }),
  ],
  layout: geo<Place>({ longitude: 'lng', latitude: 'lat', center, scale }),
})
```

With `center` and `scale` given, a point of the map world maps to the plain graph by a shift and a factor. The zoom of a graph on a map is `2 ** map.getZoom()`, so the same camera reads:

```ts
const origin = geoToWorld(center)

const toPlain = (view: View): View => ({
  x: (view.x - origin.x) * scale,
  y: (view.y - origin.y) * scale,
  zoom: view.zoom / scale,
})

const toMap = (view: View): View => ({
  x: view.x / scale + origin.x,
  y: view.y / scale + origin.y,
  zoom: view.zoom * scale,
})
```

To leave the map, read its camera, destroy the map graph, then mount the plain one at the same view. To come back, do the reverse.

```ts
function leaveMap(map: Map, mapGraph: GraphInstance): GraphInstance {
  const view = toPlain(mapGraph.view.get())
  mapGraph.destroy()
  map.remove()
  return mountGraph(element, { definition: plain, initialView: view, ariaLabel: 'Places' })
}

function backToMap(graph: GraphInstance): GraphInstance {
  const view = toMap(graph.view.get())
  graph.destroy()
  const map = new Map({ container, style })
  const mapGraph = mountMapGraph(map, { definition: onMap, ariaLabel: 'Places' })
  mapGraph.view.set(view)
  return mapGraph
}
```

Nodes that overlap moved apart in the plain graph only, so a crowded place looks tighter on the map. With `units: 'screen'`, nodes keep the same size in pixels in both modes, and the spread is computed for the zoom at which the layout runs.

## Who moves what

The map owns the camera. Dragging the background, the wheel, pinches and double clicks on the background move the map as usual, and the graph follows: `graph.view.get()` and `viewchange` report the map's camera, in [world units](/docs/positions#longitude-and-latitude).

The graph owns its elements: hover, clicks, the selection, the lasso and node drags. While a node is dragged or a lasso drawn, the graph pauses the map's drag and box zoom, and a double click on a node does not zoom the map.

`graph.view.set`, `fit` and `zoomBy` move the map, animations included, and the keyboard of the graph does too: arrows move the focus, Shift and arrows pan, `+`, `-` and `0` zoom and fit. `update({ view })` has no effect: move the map instead.

The map stays north up and without pitch: `mountMapGraph` turns off rotation and pitch, and gives them back when the last graph on the map is destroyed. On a flat map, the graph is drawn once, between longitudes -180 and 180, on the world copy the camera is over: across the antimeridian, a node and its edges show on one side only.

## Time

The [time window](/docs/time) works on a map as on any graph. In React, put `<Timeline>` inside [`<MapGraph>`](#react), or pass it the graph with `<Timeline graph={graph} />`. Without React, create the timeline with `createTimeline(graph)` and draw it with `mountTimeline`, or from its store.

```ts
import { createTimeline, mountTimeline } from '@bruno00o/graph/timeline'

const graph = mountMapGraph(map, { definition, ariaLabel: 'Places in time' })
const timeline = createTimeline(graph, { mode: 'grow' })
const view = mountTimeline(timeline, { ariaLabel: 'Timeline', labels })
footer.append(view.element)
```

Destroy them in the reverse order: `view.destroy()`, `timeline.destroy()`, `graph.destroy()`, then `map.remove()`. See the [map in time](/examples/map-time-window) example.

## Precision

Positions are stored relative to an origin that follows the camera, so nodes sit on their place on the map down to the deepest zoom of the map, at street level and beyond.

## Hulls and groups

[Hulls](/docs/drawing-layers#hulls) work on a map, on the globe too: their padding is in pixels, as anywhere else. [Groups](/docs/groups), made with the `parent` channel or with [`groups()`](/docs/transformations#group-items-by-a-field), work as well: a group needs no coordinates, its container encloses its children, and a folded group starts at their center and can be dragged. A `groups()` mark without `units` takes the units of its members, so the groups of nodes placed by `longitude` and `latitude` keep their size in pixels. On a map, the `padding` of a container is in pixels, so the frame keeps its margin as the map zooms. On the globe, a container is a rectangle facing the screen around its children.

Places that share coordinates, or that overlap at the zoom of the map, are [spread](/docs/groups#spread-children) when their group unfolds: they move apart around their place, a few pixels from each other, and keep that gap as the map zooms, on the globe too. Their coordinates do not change, and they go back to their place when the group folds. Pass `container: { spread: false }` to `groups()` to keep them stacked, and `gap` to change the space between them. Near the horizon of the globe, the gaps shrink with the curve of the Earth.

## What is left out

On a map, the definition keeps its marks, states, scales, labels, images, badges, flows, hulls, groups, [time window](/docs/time) and interaction options, and the [legend](/docs/minimap-and-legend#legend) works as on any graph. These parts are left out:

- `layout`: positions come from the coordinates. Give every node a `longitude` and a `latitude`, or `x` and `y` in world units. A node without coordinates is placed near its placed neighbors, or on a spiral. In development, a layout in the definition logs a warning, and `graph.layout.run` rejects.
- `background`, `bundling`, `routing` and `bridges`.
- The [lens](/docs/lens): `graph.lens.set` does nothing.
- The [minimap](/docs/minimap-and-legend#minimap): the map has its own navigation, and the minimap does not support a map graph.
- Rotation, pitch and terrain: the graph draws on a north-up map, flat or on the globe. In development, it warns when the map is rotated or tilted.

## Export

`exportMapPng` saves the map and the graph in one PNG. It draws the map again in a hidden element at the chosen pixel ratio, waits until its tiles are loaded, draws the graph above it, and writes the attribution of the map in the bottom right corner: most tile licenses require it.

```ts
import { exportMapPng } from '@bruno00o/graph/map'

const png = await exportMapPng(graph, { pixelRatio: 2 })
```

The attribution is the text the map shows, or else the attribution of its sources. Pass `attribution` to write your own. On the globe, the image shows the globe as on screen. `exportPng` and `exportSvg` from [`@bruno00o/graph/export`](/docs/export) draw the graph alone, without the map: `exportPng` follows the globe for the region on screen, and `exportSvg` always draws the flat map.

## Bundlers

MapLibre loads its tiles in a web worker, which it looks for next to its own module. Once a bundler has moved that module, give MapLibre the URL of the worker before you create the map. With Vite:

```ts
import { setWorkerUrl } from 'maplibre-gl'
import workerUrl from 'maplibre-gl/dist/maplibre-gl-worker.mjs?worker&url'

setWorkerUrl(workerUrl)
```

See [`mountMapGraph`](/docs/api/map) for every option, and the [map example](/examples/map).
