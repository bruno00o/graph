## Install

`@bruno00o/graph/map` draws the graph inside a [MapLibre GL JS](https://maplibre.org) map, version 6 or later. MapLibre is an optional peer dependency: install it next to the library.

```sh
pnpm add maplibre-gl
```

## Mount on a map

Place the nodes with `longitude` and `latitude`, create the map, then mount the graph on it.

```ts
import { defineGraph, edges, nodes } from '@bruno00o/graph'
import { mountMapGraph } from '@bruno00o/graph/map'
import { Map } from 'maplibre-gl'
import 'maplibre-gl/dist/maplibre-gl.css'

const definition = defineGraph({
  marks: [
    edges(routes, { source: 'from', target: 'to' }),
    nodes(places, { longitude: 'lng', latitude: 'lat', label: 'name', color: 'group' }),
  ],
})

const map = new Map({ container, style: 'https://tiles.openfreemap.org/styles/positron', center: [10, 48], zoom: 3 })
const graph = mountMapGraph(map, { definition, ariaLabel: 'Places and routes' })
```

`mountMapGraph` takes any map, with any style, before or after its style loads. It adds a custom layer to the style and draws in the map's own WebGL context, on top of the style or under the layer named by `beforeId`, such as the place labels of the basemap. It returns the same [`GraphInstance`](/docs/api/graph-instance) as `mountGraph`: data updates, states, selection, events, anchors and the store work the same way. Call `graph.destroy()` before `map.remove()`, or pass a `signal` that you abort before removing the map.

The graph adds its own layer back after the browser restores a lost WebGL context: MapLibre then warns that it cannot restore custom layers. See [Browser support](/docs/browser-support#context-loss).

## Size of the map

MapLibre sizes the map from its container: a container 0 px high draws nothing, graph included, and nothing warns. The MapLibre stylesheet also sets `position: relative` on that container, through the class `maplibregl-map` it adds to it. This rule sits in no cascade layer, so it beats every rule inside a layer, whatever its specificity. The utilities of Tailwind CSS v4 live in `@layer utilities`: a container with the classes `absolute inset-0` stays relative, and with no content of its own it is 0 px high.

Give the container its size with an inline style, or with a rule outside any layer that comes after the MapLibre stylesheet:

```tsx
<div ref={setContainer} style={{ position: 'absolute', inset: 0 }} />
```

## Where the graph sits

`graph.element` is a `div` that `mountMapGraph` inserts into the container of the map, right after the canvas container of MapLibre: a sibling of it, not a child. It is positioned absolutely over the whole map, so it measures what the map measures and clips its content at the edges of the map, and it takes no pointer events itself: the map canvas keeps them. It has no `z-index`, so it stacks by order in the document. From bottom to top: the map canvas and its markers, which live in the canvas container; the graph element; the popups of MapLibre, which are added to the map container later; then the controls, whose `z-index` is 2.

For your own overlays, this means three things:

- Put them in an [`<Anchor>`](/docs/api/anchor) or in `graph.anchors`. Their layer is inside `graph.element`, over the markers and under the popups and controls of MapLibre, and it follows the camera of the map.
- An overlay of your own placed in the map container goes over `graph.element` when it comes later in the document, or has a `z-index` of 1 or more.
- A `position: absolute` child you add to `graph.element` yourself is clipped at the edges of the map, and it receives no pointer events unless you set `pointer-events: auto` on it: the property is inherited.

## Units of nodes on a map

On a map, a node with `longitude` and `latitude` is sized in screen pixels: `units` defaults to `'screen'`, and `size` is a diameter in pixels at every zoom. Setting `units: 'world'` on such a node scales it with the map as a disc on the Earth would: the world is 512 units wide at map zoom 0 and doubles at each zoom, so a `size` of 1 is 1 pixel at zoom 0 and 2 pixels at zoom 1, and a node of size 10 spans 7 degrees of longitude. `units` changes no position and no edge. It sets the unit of the `gap` of [spread children](/docs/groups#spread-children), in pixels or in world units.

A node placed by `x` and `y` in world units, or without coordinates, defaults to `'world'` and is huge at the zooms of a map: set `units: 'screen'` on it. A `groups()` mark takes the units of its first member.

## Nodes at one place

Nodes at the very same `longitude` and `latitude` draw on top of each other. With `spread: true` in the definition, they move apart around their place, `gap` pixels apart, and keep their gaps as the map zooms, flat or on the globe. Their data keeps its coordinates. To gather them instead, put them in a [group](/docs/groups#spread-children) by place: its children spread while it is unfolded. See [Nodes at one place](/docs/positions#nodes-at-one-place).

```ts
const definition = defineGraph({
  marks: [nodes(places, { longitude: 'lng', latitude: 'lat' })],
  spread: true,
})
```

A node without coordinates starts near its neighbors placed by theirs, from the first data on, at a distance in pixels when it is sized in screen units; with no placed neighbor, it starts next to the placed nodes. It stays there as the map zooms: give it coordinates, or drag it, to move it.

## Switching the basemap

Call `map.setStyle(style)` to change the basemap: the graph stays on the map, whether the style is a URL or an object and whether MapLibre patches the old style or loads the new one from scratch. It is drawn on top of the new style, or under the layer named by `beforeId` when the new style has that layer.

Colors that read well on a light basemap can vanish on a dark one or on imagery: give edges and nodes a light color and a dark outline there. See the [basemaps](/examples/basemaps) example, which switches between five vector styles and a satellite raster style, and shows each attribution in the map.

<LiveExample slug="basemaps" />

Node sizes are in screen pixels when the node has a `longitude` and a `latitude`, so such a node keeps its size as the map zooms. Edges are straight in Web Mercator, as on the map, unless they follow [great circles](#great-circles).

The map keeps its own camera at mount: the graph does not frame its nodes by itself. To frame them, call `fit` right after mounting; it waits until the graph has measured the map.

```ts
const graph = mountMapGraph(map, { definition, ariaLabel: 'Places and routes' })
graph.view.fit({ padding: 40 })
```

The map sets the zoom limits, and the `view` of the definition does not apply: `padding` and `autoFit` there change nothing, and each `fit` takes its own `padding`, 32 pixels by default.

See the [nodes on a flat map](/examples/flat-map) example.

## React

`@bruno00o/graph/map/react` exports [`<MapGraph>`](/docs/api/map-graph). It mounts the graph on the map you pass, and destroys it on unmount or when `map`, `id` or `beforeId` change. It takes the props of [`<Graph>`](/docs/api/graph-component) without the view, which belongs to the map. It renders no element of its own: its children render where it stands, with the graph in context, so the hooks, `<Anchor>`, `<Legend>` and `<Timeline>` work inside it as inside `<Graph>`.

```tsx title="Places.tsx"
import { MapGraph } from '@bruno00o/graph/map/react'
import { Timeline } from '@bruno00o/graph/react'
import { Map } from 'maplibre-gl'
import { useEffect, useRef, useState } from 'react'

export function Places() {
  const host = useRef<HTMLDivElement>(null)
  const [map, setMap] = useState<Map | null>(null)
  useEffect(() => {
    if (!host.current) return
    const created = new Map({ container: host.current, style, center: [10, 48], zoom: 3 })
    setMap(created)
    return () => created.remove()
  }, [])
  return (
    <div className="stage">
      <div ref={host} className="map" />
      {map ? (
        <MapGraph map={map} definition={definition} ariaLabel="Places and routes">
          <Timeline mode="grow" />
        </MapGraph>
      ) : null}
    </div>
  )
}
```

Create the map in `useEffect`, not `useLayoutEffect`: on unmount, React runs the layout cleanup of `<MapGraph>` before the passive cleanup that removes the map, so the graph leaves the map first. Outside `<MapGraph>`, give the graph to `<Legend>`, `<Timeline>`, `useLegend` or `useTimeline` with their `graph` prop or option: see [React](/docs/react#companions-beside-the-graph).

See the [map component](/examples/map-component) example.

### One graph, on the map or not

To move one graph between its own canvas and a map, render `<Graph>` and give it a `surface`: [`useMapSurface(map)`](/docs/api/map-graph#usemapsurface) makes one for the map you created and releases it on unmount, and `null` keeps the graph on its canvas. `<Graph>` applies `surface` and `definition` in one `update`, so give each side its definition in the same render, as in [With and without a map](#with-and-without-a-map). The instance stays, and so do its children: the hooks, `<Legend>`, `<Timeline>` and `<Anchor>` keep their state across the moves.

```tsx title="Places.tsx"
import { useMapSurface } from '@bruno00o/graph/map/react'
import { Graph, Legend } from '@bruno00o/graph/react'
import { Map } from 'maplibre-gl'
import { useEffect, useRef, useState } from 'react'

function Backdrop({ shown, onMap }: { shown: boolean; onMap: (map: Map | null) => void }) {
  const host = useRef<HTMLDivElement>(null)
  useEffect(() => {
    if (!host.current) return
    const created = new Map({ container: host.current, style, center: [10, 48], zoom: 3 })
    onMap(created)
    return () => {
      onMap(null)
      created.remove()
    }
  }, [onMap])
  const hidden = { opacity: shown ? 1 : 0, pointerEvents: shown ? 'auto' : 'none' } as const
  return <div ref={host} style={{ position: 'absolute', inset: 0, ...hidden }} />
}

export function Places({ wanted }: { wanted: boolean }) {
  const [map, setMap] = useState<Map | null>(null)
  const surface = useMapSurface(map)
  const there = wanted && surface !== null
  return (
    <Graph
      definition={there ? onMap : plain}
      surface={there ? surface : null}
      ariaLabel="Places"
      className="stage"
    >
      <Backdrop shown={there} onMap={setMap} />
      <Legend />
    </Graph>
  )
}
```

The element of the map is a child of `<Graph>`, before the overlays: it sits above the canvas, hidden while the graph is there, and under the legend on both sides. Hide it with `opacity` rather than `display: none`, so that it keeps its size. Read the side the graph is on with `useGraphState((state) => state.surface)` or `onSurfaceChange`.

To show the same area on both sides, move the map before the switch with `map.jumpTo`, from the plain view converted as below, and set the plain view in a layout effect of the parent after the switch back: it runs after the one of `<Graph>`. A map removed while the graph is on it sends the graph back to its canvas; it stays there until `surface` changes again. See the [React example](/examples/map-and-back-react).

## Globe

The graph follows the projection of the map. Set the globe projection of MapLibre, in the style or at any time, and nodes, edges, labels, badges, images, hulls, [anchors](/docs/drawing-layers#anchored-html) and the lasso go with it:

```ts
map.on('style.load', () => map.setProjection({ type: 'globe' }))
```

On the globe, an element on the far side is hidden and cannot be picked, and an edge that passes behind the horizon is cut there. Edges between distant nodes bend with the surface; short ones stay straight. When the map zooms in, MapLibre turns the globe into a flat map between zoom 11 and 12, and the graph turns with it.

`graph.view.toScreen` and `toWorld` take the globe into account: `toScreen` gives the point on the globe, also on its far side, and `toWorld` gives the point under the pointer, or, beside the globe, the point of the flat map.

With 100,000 nodes and 200,000 edges on a 1280 × 800 page, the layer takes 12.6 ms per frame while the globe turns, against 7.8 ms on the flat map. Nodes alone take 5.5 ms and 3.9 ms.

## Great circles

Set `geodesic` on an edge mark and its edges follow the shortest path over the Earth, a great circle, between nodes placed by `longitude` and `latitude`:

```ts
edges(routes, { source: 'from', target: 'to', geodesic: (route) => route.long })
```

On the globe, such an edge is an arc of the sphere. On a flat map, it bends toward the poles, and an edge that crosses the antimeridian is cut in two, each part reaching the edge of the world. Arrows, dashes, flows, labels and picking follow the path. Geodesic edges are never bundled, an edge with [waypoints](#routes-along-a-network) ignores `geodesic`, and the option has the same effect on a graph without a map. See [`EdgeOptions`](/docs/api/edges#options).

Examples: [great circles without a map](/examples/great-circles), and [flows on a map](/examples/map-flows).

## Routes along a network

To draw an edge along a road, a river or any line of a network instead of straight, give it the points of that line with `waypoints`. `lineWaypoints` reads a GeoJSON `LineString` or `MultiLineString` geometry as `{ longitude, latitude }` points, the lines of a `MultiLineString` one after the other, and drops the first and last positions, which usually sit on the nodes:

```ts
import { edges, lineWaypoints } from '@bruno00o/graph'

type Road = { id: string; from: string; to: string; geometry: LineStringGeometry }

declare const roads: Road[]

edges(roads, {
  source: 'from',
  target: 'to',
  waypoints: (road) => lineWaypoints(road.geometry),
})
```

Pass `{ keepEnds: true }` to keep them, for a line that stops short of its nodes. The edge still starts and ends on its nodes; only the points in between are fixed. See [Waypoints](/docs/marks#waypoints) for the rules shared with plain graphs.

```ts
type LineGeometry = LineStringGeometry | MultiLineStringGeometry
```

- On a flat map, a line that crosses the antimeridian takes the short way, from one point to the next, and is drawn on both sides like a [great circle](#great-circles).
- On the globe, the line follows the surface: stretches longer than 8 world units, about 5.6 degrees at the equator, are split into shorter ones, and a line that passes behind the horizon is cut there. The first and last segments, from the nodes to the line, stay straight on screen.
- Points are stored in world units with double precision and drawn relative to the camera, so a line stays on its road at street level. The GPU keeps them in 32 bits relative to the origin of the positions, which is moved when the camera goes far from it.
- A line drawn by `waypoints` has sharp corners: give it more points for a smoother curve.

See the [routes along a network](/examples/map-routes) example.

## With and without a map

One graph can move between its own canvas and a map, and back. `mapSurface(map)` makes a surface for a MapLibre map; pass it as `surface` to `graph.update` to move the graph onto the map, and `null` to bring it back. The graph keeps its data, selection, states, folded groups, hidden layers, time window and event handlers across the moves.

On the map, the `longitude` and `latitude` channels pin each node to its place. Without the map, the [`geo` layout](/docs/layout#geography) uses the same projection, and moves apart the nodes that overlap. Build one definition for each side, and give it with the surface: both apply together, so the layout and the positions never see one without the other.

```ts
import { defineGraph, edges, geoToWorld, mountGraph, nodes, type View } from '@bruno00o/graph'
import { geo } from '@bruno00o/graph/layouts'
import { mapSurface } from '@bruno00o/graph/map'

const center = { longitude: 10, latitude: 48 }
const scale = 2048

const plain = defineGraph({
  marks: [
    edges(routes, { source: 'from', target: 'to' }),
    nodes(places, { label: 'name', units: 'screen' }),
  ],
  layout: geo<Place>({ longitude: 'lng', latitude: 'lat', center, scale }),
})

const onMap = defineGraph({
  marks: [
    edges(routes, { source: 'from', target: 'to' }),
    nodes(places, { longitude: 'lng', latitude: 'lat', label: 'name' }),
  ],
})

const graph = mountGraph(element, { definition: plain, ariaLabel: 'Places' })
const surface = mapSurface(map)

function showMap(): void {
  graph.update({ surface, definition: onMap })
}

function hideMap(): void {
  graph.update({ surface: null, definition: plain })
}
```

The map lives in its own element: while the graph is on its canvas, hide it with `opacity: 0` and `pointer-events: none` rather than `display: none`, so that it keeps its size for when the graph comes. `surfacechange` and the `surface` field of the store, `'canvas'` or `'map'`, tell which side the graph is on.

Each surface keeps its own positions and its own view. On the way back, nodes are where you left them, without a layout run, and the view is the one you left. Nodes added while the graph was away are placed when it comes back: on the canvas, by the layout, near the others; on the map, by their coordinates. A node whose `longitude` and `latitude` changed moves to its new place. A layout run that the move stopped starts again on the way back. Positions on a map are in the world units of the map, and those of a plain graph in the units of its layout, so [`positions.snapshot()`](/docs/positions#restore-at-mount) reads the side the graph is on.

The first time on the map, the graph takes the camera of the map as it is. To show the same area as the plain graph, give `view` with the surface. With `center` and `scale` given to `geo`, a point of the map world maps to the plain graph by a shift and a factor, and the zoom of a graph on a map is `2 ** map.getZoom()`:

```ts
const origin = geoToWorld(center)

const toMap = (view: View): View => ({
  x: view.x / scale + origin.x,
  y: view.y / scale + origin.y,
  zoom: view.zoom * scale,
})

graph.update({ surface, definition: onMap, view: toMap(graph.view.get()) })
```

`view` given with a new surface is the view to take there, on the canvas too: the reverse conversion brings the plain graph to the area shown on the map. A controlled [`view`](/docs/view#controlled-view) is ignored on the map, as with `mountMapGraph`, and applies again on the canvas.

A surface holds one graph at a time. It keeps its layer and its renderer after the graph leaves, so that the next visit is quick: `surface.release()` frees them, and brings back to its canvas a graph that is on it. Removing the map does the same, with a warning in development. `graph.destroy()` releases every surface the graph visited.

[`persistPositions`](/docs/api/persist-positions) writes the moves made on the side the graph is on when you call it, and leaves out those of the other side: pass `surfaces: ['canvas', 'map']` to write both, in different fields or collections if they should not mix. `positionchange` carries the `surface` of its positions. [Edge bundling](/docs/bundling) and [routing](/docs/routing) run again on the way back.

Companions follow the move, without being created again:

- The [minimap](/docs/minimap-and-legend#minimap) empties and leaves the graph on the map, and draws again on the canvas, from the positions of the canvas.
- The [lens](/docs/lens) hides on the map, with a `lenschange`, and shows again on the way back if it was still set.
- The [shape editor](/docs/editing-shapes#on-a-map) draws in degrees on the map and in world units on the canvas with `units: 'auto'`. A gesture or a drawing in progress is dropped at the move, and a text being typed is proposed; edits waiting for their data stay.
- The [devtools](/docs/devtools) show the surface in the View section and keep the history of the graph.
- [Presence](/docs/editing-shapes#who-else-is-editing) writes the surface of each person: cursors show only between people on the same surface, and selections show on every surface.
- The legend, the timeline and anchors need nothing: they follow keys and stores, and anchors live in the graph element, which moves with the graph.

Code of your own that sits beside the graph does the same with `surfacechange`, or with `useGraphState((state) => state.surface)` in React: the event comes once the graph has moved, after the companions above. `graph.positions`, `graph.view` and `positionchange` already answer for the side the graph is on, and `graph.drawsOnMap` tells whether that side is a map.

Nodes that overlap moved apart in the plain graph only, so a crowded place looks tighter on the map. With `units: 'screen'`, nodes keep the same size in pixels on both sides.

In React, give the surface to `<Graph>`: see [One graph, on the map or not](#one-graph-on-the-map-or-not).

Without `surface`, mount one graph for each side: read the camera and `positions.snapshot()` of one, destroy it, then mount the other with `initialView` and [`initialPositions`](/docs/positions#restore-at-mount). Each side gets its own snapshot, and nodes that have `longitude` and `latitude` ignore their entry.

## Who moves what

The map owns the camera. Dragging the background, the wheel, pinches and double clicks on the background move the map as usual, and the graph follows: `graph.view.get()` and `viewchange` report the map's camera, in [world units](/docs/positions#longitude-and-latitude).

The graph owns its elements: hover, clicks, the selection, the lasso and node drags. While a node is dragged or a lasso drawn, the graph pauses the map's drag and box zoom, and a double click on a node does not zoom the map. With a [lasso](/docs/interaction#lasso) whose `modifier` is `null`, every drag on the background draws a lasso: the map then moves with the wheel, pinches and the keyboard.

`graph.drawsOnMap` is `true` while the graph draws on a map, mounted by `mountMapGraph` or `<MapGraph>`, or moved there with a [`surface`](#with-and-without-a-map): code shared between a plain graph and a map graph reads it to leave out what a map does not draw, such as a layout or the minimap.

A dragged node stays where it was dropped, even when its data says otherwise, until its own coordinates change. `graph.positions.reset()` puts every node back on its `longitude` and `latitude`, with a glide, and `reset(keys)` only some. `positionchange` carries `geo`, the moved nodes in degrees, and `persistPositions` writes them into the fields you name with `longitude` and `latitude`. See [Positions](/docs/positions#put-nodes-back).

`graph.view.set`, `fit` and `zoomBy` move the map, animations included, and the keyboard of the graph does too: arrows move the focus, Shift and arrows pan, `+`, `-` and `0` zoom and fit. `update({ view })` has no effect while the graph stays on the map: move the map instead. A `view` given in the same `update` as a new `surface` is the view to take there: on a map, it moves the map once the graph has arrived (see [With and without a map](#with-and-without-a-map)).

The map stays north up and without pitch: `mountMapGraph` turns off rotation and pitch, and gives them back when the last graph on the map is destroyed or leaves it. On a flat map, the graph is drawn once, between longitudes -180 and 180, on the world copy the camera is over: across the antimeridian, a node and its edges show on one side only.

## Time

The [time window](/docs/time) works on a map as on any graph. In React, put `<Timeline>` inside [`<MapGraph>`](#react), or pass it the graph with `<Timeline graph={graph} />`. Without React, create the timeline with `createTimeline(graph)` and draw it with `mountTimeline`, or from its store.

```ts
import { createTimeline, mountTimeline } from '@bruno00o/graph/timeline'

const graph = mountMapGraph(map, { definition, ariaLabel: 'Places in time' })
const timeline = createTimeline(graph, { mode: 'grow' })
const view = mountTimeline(timeline, { ariaLabel: 'Timeline', labels })
footer.append(view.element)
```

Destroy them in the reverse order: `view.destroy()`, `timeline.destroy()`, `graph.destroy()`, then `map.remove()`. See the [map in time](/examples/map-time-window) example.

## Precision

Positions are stored relative to an origin that follows the camera, so nodes sit on their place on the map down to the deepest zoom of the map, at street level and beyond.

## Hulls and groups

[Hulls](/docs/drawing-layers#hulls) work on a map, on the globe too: their padding is in pixels, as anywhere else. [Groups](/docs/groups), made with the `parent` channel or with [`groups()`](/docs/transformations#group-items-by-a-field), work as well: a group needs no coordinates, its container encloses its children, and a folded group starts at their center and can be dragged. A `groups()` mark without `units` takes the units of its members, so the groups of nodes placed by `longitude` and `latitude` keep their size in pixels. On a map, the `padding` of a container is in pixels, so the frame keeps its margin as the map zooms. On the globe, a container is a rectangle facing the screen around its children. On a map, containers are translucent by default, so the basemap shows through them: set `container.fillOpacity` to change it, 1 for an opaque fill.

Places that share coordinates, or that overlap at the zoom of the map, are [spread](/docs/groups#spread-children) when their group unfolds: they move apart around their place, a few pixels from each other, and keep that gap as the map zooms, on the globe too. Their coordinates do not change, and they go back to their place when the group folds. Pass `container: { spread: false }` to `groups()` to keep them stacked, and `gap` to change the space between them. Near the horizon of the globe, the gaps shrink with the curve of the Earth.

## Shapes

[Shapes](/docs/shapes) draw on the map, flat or on the globe, at their place in the graph: under containers, hulls, edges and nodes, above the basemap. Give their geometry in degrees, as GeoJSON or with `{ longitude, latitude }` points, and they line up with the basemap and with the nodes placed by coordinates. A circle around a place in degrees takes its radii in meters, and is drawn as a polygon of 128 points that follows the surface of the Earth.

```ts
import { defineGraph, nodes, type ShapeGeometry } from '@bruno00o/graph'
import { mountMapGraph } from '@bruno00o/graph/map'
import { shapes } from '@bruno00o/graph/shapes'

type Area = { id: string; geometry: ShapeGeometry }

const areas: Area[] = [
  {
    id: 'coast',
    geometry: {
      type: 'Polygon',
      coordinates: [[[-5, 43], [8, 43], [8, 51], [-5, 51], [-5, 43]]],
    },
  },
  { id: 'reach', geometry: { center: { longitude: 2.35, latitude: 48.86 }, radius: 250_000 } },
]

mountMapGraph(map, {
  definition: defineGraph({
    marks: [shapes(areas), nodes(places, { longitude: 'lon', latitude: 'lat' })],
  }),
  ariaLabel: 'Areas and places',
})
```

- A ring or a line that crosses the antimeridian takes the short way, from one point to the next. On a flat map, a shape that crosses it is drawn, picked and taken by the lasso on both sides.
- On the globe, outlines and fills follow the surface: edges longer than 8 world units, about 5.6 degrees at the equator, are split into shorter ones, once per geometry. The part of a shape behind the horizon is neither drawn nor picked.
- A geometry in world units, `{ x, y }` points or a rectangle, stays in world units: on a map of 512 world units, a rectangle 100 units wide covers a fifth of the Earth. Circles and rectangles in world units keep their exact curve on a flat map. On the globe, they face the screen at their center, at the scale of the globe there, and the [shape editor](/docs/editing-shapes#on-a-map) shows them the same way.
- Selection, hover, states, `others`, `hide`, zoom ranges, the time window and layers work as on any graph. `exportMapPng` draws the shapes with the graph.
- A [shape editor](/docs/editing-shapes#on-a-map) moves and reshapes shapes on the map, and writes their edits in degrees.
- [Labels](/docs/shapes#labels) show on the map, once per shape. A shape [pinned to a node](/docs/shapes#pin-shapes-to-nodes) follows it, flat or on the globe, with its geometry in world units around the node: a ring of radius 2 spans about 1.4 degrees of longitude.

## What is left out

On a map, the definition keeps its marks, states, scales, labels, images, badges, flows, hulls, groups, shapes, [time window](/docs/time) and interaction options, and the [legend](/docs/minimap-and-legend#legend) works as on any graph. These parts are left out:

- `layout`: positions come from the coordinates. Give every node a `longitude` and a `latitude`, or `x` and `y` in world units. A node without coordinates starts near its placed neighbors, or next to the placed nodes: see [Nodes at one place](#nodes-at-one-place). In development, a layout in the definition logs a warning, and `graph.layout.run` rejects.
- `background`, `bundling`, `routing` and `bridges`.
- The [lens](/docs/lens): `graph.lens.set` does nothing.
- The [minimap](/docs/minimap-and-legend#minimap): the map has its own navigation. `createMinimap` and `<Minimap>` draw nothing on a map graph, and warn once in development.
- Rotation, pitch and terrain: the graph draws on a north-up map, flat or on the globe. In development, it warns when the map is rotated or tilted.

## Export

`exportMapPng` saves the map and the graph in one PNG. It draws the map again in a hidden element at the chosen pixel ratio, waits until its tiles are loaded, draws the graph above it, and writes the attribution of the map in the bottom right corner: most tile licenses require it.

```ts
import { exportMapPng } from '@bruno00o/graph/map'

const png = await exportMapPng(graph, { pixelRatio: 2 })
```

`badges: false` leaves the badges of the nodes out. The image has the size of the map times `pixelRatio`, which takes `'auto'`, `'device'` or a number as in `exportPng` and defaults to the pixel ratio of the map: the exact `size` of `exportPng` does not apply, because the map draws the area its camera shows.

The attribution is the text the map shows, or else the attribution of its sources. Pass `attribution` to write your own. On the globe, the image shows the globe as on screen. `exportPng` and `exportSvg` from [`@bruno00o/graph/export`](/docs/export) draw the graph alone, without the map: `exportPng` follows the globe for the region on screen, and `exportSvg` always draws the flat map.

## Bundlers

MapLibre loads its tiles in a web worker, which it looks for next to its own module. Once a bundler has moved that module, give MapLibre the URL of the worker before you create the map. With Vite:

```ts
import { setWorkerUrl } from 'maplibre-gl'
import workerUrl from 'maplibre-gl/dist/maplibre-gl-worker.mjs?worker&url'

setWorkerUrl(workerUrl)
```

See [`mountMapGraph`](/docs/api/map) for every option, and the [map example](/examples/map).
