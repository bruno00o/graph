`graph.paths` answers two questions on the nodes and edges of the graph: which path joins two nodes at the lowest cost, and which nodes can be reached from one. It reads the same adjacency the graph draws from, so a query needs no copy of your data.

## Shortest path

```ts
const path = graph.paths.shortest('a', 'f')
// { nodes: ['a', 'c', 'f'], edges: ['ac', 'cf'], costs: [0, 1, 2], cost: 2 }
```

The result lists the keys of the nodes along the path, from the start to the end, and the keys of the edges between them, one fewer. When two nodes are joined by several edges, `edges` tells which one the path takes. `costs` holds the cost from the start to each node, and `cost` the total.

`shortest` returns `null` when no path joins the two nodes, or when a key is unknown. A value that is not a key, such as `undefined`, `null`, an object or `NaN`, counts as an unknown key in every read by key. From a node to itself, the path is that node alone, at cost 0.

Without options, every edge costs 1: the path has the fewest edges. Edges are crossed both ways.

## Weights and direction

```ts
graph.paths.shortest('a', 'f', { weight: 'distance', direction: 'forward' })
graph.paths.shortest('a', 'f', { weight: (link) => link.delay + link.wait })
```

- `weight` is a field of the edge items, or a function of an item. The path is the one with the lowest sum of weights.
- An edge whose weight is missing, not a number or infinite cannot be crossed. A negative weight throws a `RangeError`: shortest paths need weights of 0 or more.
- `direction` sets which way edges are crossed: `'both'`, the default, `'forward'` from source to target only, or `'backward'` from target to source only.

Field names and function arguments are typed from the items of your edge marks, as in the definition. See [TypeScript](/docs/typescript).

Examples: [path costs](/examples/weighted-path) weighs each edge, and [upstream and downstream](/examples/upstream-downstream) follows edges forward, then backward.

## Keep to some nodes and edges

```ts
graph.paths.shortest('a', 'f', {
  nodes: (item) => item.status !== 'closed',
  edges: (link, key) => !blocked.has(key),
})
```

`nodes` and `edges` choose what the search may enter or cross. The two ends must pass `nodes`, or there is no path. See the [detour around blocked nodes](/examples/detour) example.

## Within reach

```ts
const near = graph.paths.reach('a', { maxCost: 2 })
graph.states.set('near', near)
```

`reach` lists the nodes the start leads to, by increasing cost, with the cost of each, and the edges between two reached nodes that the search may cross. Without `weight`, `maxCost` counts edges: `{ maxCost: 1 }` is the start and its neighbors. Without `maxCost`, `reach` returns the whole connected component of the start; with `direction: 'forward'`, every node it leads to, and with `'backward'`, every node that leads to it. A negative or `NaN` `maxCost` throws a `RangeError`. It takes the same options as `shortest`.

Examples: [neighborhood by hops](/examples/k-hop-neighborhood), [within a cost budget](/examples/cost-budget) and [connected components](/examples/connected-components).

## Two ways out

```ts
import { ways, pair } from '@bruno00o/graph/ways'

const result = ways(graph, { exits: (datum) => datum.exit === true })

const two = pair(graph, 'a', { exits: ['exit-1', 'exit-2'] })
```

From the `@bruno00o/graph/ways` subpath, `ways` and `pair` work on a mounted graph, on a graph without a page ([`createGraph`](/docs/api/create-graph)) and on a `PathFinder` of [`createPathFinder`](#createpathfinder): pass the graph or the finder as the first argument.

`ways` tells which nodes have two ways out to two distinct exits, which have a single way out, and which none. It ignores the direction of the edges, and takes the same `nodes`, `edges` and `visible` options as the queries of `graph.paths`. `exits` is a function of the node item and key, or a list of keys; keys of missing nodes are skipped.

- `result.two` lists the nodes with two ways out to two distinct exits, the exits excluded.
- `result.one` lists `{ key, through }`: every path from `key` to an exit passes through `through`, an exit or a node of `two`.
- `result.none` lists the nodes no exit is reachable from, the exits excluded.
- `result.chains` lists the chains of nodes between two exits, `{ nodes, edges, ends, covered }`, the covered chains first. They are read from the biconnected blocks of the graph with the exits joined to a virtual node, so the branches hanging on a chain do not hide it, and they do not depend on `failure`. A chain that returns to its own exit is never covered: `ends` holds the same exit twice and `covered` is `false`.
- `result.weak` lists the articulation nodes and bridges whose loss cuts at least one node off from every exit: `{ nodes, edges }`.

`failure` says what may fail when counting the ways out: `'node'`, the default, any node or edge may fail, or `'edge'`, an edge or an exit only. With `'edge'`, more nodes are in `two`: the ones that still have two ways out when any single edge or exit is removed.

`pair` returns the two cheapest paths from a node to two distinct exits, with no node in common, or no edge or exit in common with `failure: 'edge'`, or `null` when there is no such pair or the key is unknown. It takes the same options as `ways`, plus `weight`, which works as in `shortest`: without it, every edge costs 1.

The result of `ways` is frozen, and the same object comes back while the data and the options do not change.

## Groups

By default, queries run on the data: every node and edge, inside a folded group or not. With `visible: true`, they run on the graph as drawn:

- nodes and edges outside the [time window](/docs/time) or their [zoom range](/docs/zoom) are left out;
- a folded group stands for the nodes it hides, and an end hidden in a folded group is replaced by the group;
- the edges inside a folded group are left out;
- an edge between two groups, drawn as one merged edge, is reported by the key of one of its members. Put that key in a state and the merged edge takes the state.

```ts
graph.paths.shortest('a', 'f', { visible: true })
```

See [Groups](/docs/groups).

## Highlight a path

A path is a set of node and edge keys, the shape `states.set` takes. Declare a state, style it, and put the path in it. A [flow](/docs/marks#flows) shows its direction, [`raise`](/docs/states#raise-a-state) draws it above the other edges, and [`others`](/docs/states#style-the-others) fades the rest of the graph.

```ts
const graph = mountGraph(container, {
  definition: defineGraph({
    marks: [edges(links, { source: 'from', target: 'to' }), nodes(items)],
    states: {
      path: {
        flow: true,
        stroke: 'var(--graph-accent)',
        strokeWidth: 2.5,
        label: true,
        raise: true,
        others: { opacity: 0.15, label: false },
      },
    },
  }),
  ariaLabel: 'Network',
})

graph.on('selectionchange', ({ selection }) => {
  const [from, to] = selection.nodes
  const path = from !== undefined && to !== undefined ? graph.paths.shortest(from, to) : null
  if (!path) return graph.states.clear()
  graph.states.set('path', path)
})
```

To step along the path, walk `path.nodes` with [`graph.focus.set`](/docs/interaction#keyboard) or [`graph.view.fit`](/docs/view), and frame the whole path with `graph.view.fit(path)`. The [path through waypoints](/examples/waypoints) example chains shortest paths through stops you click.

## Without a graph

`createPathFinder` runs the same queries on marks, without mounting anything: on a server, in a worker or in tests.

```ts
import { createPathFinder, edges, nodes } from '@bruno00o/graph'

const paths = createPathFinder({
  marks: [nodes(items), edges(links, { source: 'from', target: 'to' })],
})
paths.shortest('a', 'f', { weight: 'distance' })
paths.destroy()
```

It reads the arrays and subscribes to the live sources, such as a TanStack DB collection, as soon as it is created, and applies their changes at the next query. `destroy` stops listening to them; later queries find nothing.

## Cost

Queries run on the adjacency of the graph, stored in typed arrays, and allocate only their result. `shortest` searches from both ends at once, a breadth-first search without weights and Dijkstra's algorithm with them, and stops when the two searches meet. Pending data changes are applied first.

On 500,000 nodes and 1,000,000 edges, in the browser, a path between two far nodes takes about 1 millisecond without weights and 2 to 3 milliseconds with them, under 10 at worst. On a graph of communities linked in a tree, where paths cross few bridges, weighted searches take 5 to 30 milliseconds, and up to 100. A `reach` over the whole graph takes 0.1 to 0.8 seconds: bound it with `maxCost` in interactive code.

`ways` reads the whole adjacency once, and `pair` only what it visits. On 100,000 nodes and 200,000 edges, `ways` takes 27 to 62 milliseconds, and 39 with `failure: 'edge'`; `pair` takes a median of 3.0 milliseconds, 7.5 at the 90th percentile. On 500,000 nodes and 1,000,000 edges, `ways` takes 0.31 to 0.43 seconds, and 0.32 with `failure: 'edge'`; `pair` takes 11.6 milliseconds, 14.3 at the 90th percentile. The cached result comes back in 0.1 millisecond while the data and the options do not change. For comparison, a full `reach` takes 28 milliseconds and 0.25 seconds on the same graphs.
