---
title: Upgrading
description: What changes in your code from one version to the next.
---

Versions before 1.0 may break the API in a minor release. Each change is listed here with what to do. The full list of changes is in the [changelog](https://github.com/bruno00o/graph/blob/main/CHANGELOG.md).

## 0.19.0

### Invalid numbers throw in `hull`

`hull` throws a `RangeError` when `padding` or `strokeWidth` is negative, `NaN` or infinite. Before, a negative value counted as 0, and `NaN` or an infinite value fell back to the default (16 pixels of padding, an outline of 1 pixel). Pass 0 for no padding or no outline, and leave the option out for the default.

### Export `padding` is checked

`exportPng` and `exportSvg` throw a `RangeError` when `padding` is negative, `NaN` or infinite, before any work. A negative value used to count as 0. Pass 0 for no margin.

### `maxEdges: Infinity` means no limit

`densityBundling` and `orthogonalRouting` took `maxEdges: Infinity` for the default limit. It now means no limit, as for `bridges.maxEdges`. A negative value is still raised to 0, and `NaN` still falls back to the default.

### `grid` ignores a `columns` that is not finite

`grid({ columns: NaN })` placed every node at `NaN`, and `Infinity` made a single row. Both now count as the default, the square root of the count, rounded up.

## 0.16.0

### Marks of live sources take no `key`

A live source keys its items by the `key` of each change, and the `key` option of `nodes()` and `edges()` was never read for it. It is now refused by the types: remove it. To key the items otherwise, change the `getKey` of the collection, or map the changes of your own source.

```ts
// Before: compiled, and the option was ignored
nodes(collection, { key: 'code', label: 'name' })

// After
nodes(collection, { label: 'name' })
```

A change whose key is neither a string nor a finite number used to reach the graph and could break its indices. It is now skipped and listed by `graph.issues()` as a `missing-key` problem, whose `datum` is the value of the change.

### `createExploration` needs keys for items without `id`

Without `nodeKey`, the nodes of `createExploration` must have an `id` field, and the same for edges without `edgeKey`: other items no longer compile. `nodeKey` and `edgeKey` now also take a field name.

```ts
// Before: compiled, and every edge was keyed undefined
createExploration(client, { roots, neighbors })

// After
createExploration(client, { roots, neighbors, edgeKey: (link) => `${link.from}:${link.to}` })
```

### Invalid numbers throw in `defineGraph`

`defineGraph` throws a `RangeError` for numbers it used to correct without a word:

- `transitions.positions` and `transitions.layout`: a negative duration counted as 0, and `NaN` was kept. Pass 0 for no animation.
- `interaction.zoom.speed` and `interaction.autoPan.speed`: must be finite, 0 or more.
- `background.spacing` and `bridges.size`: 0, a negative or a non-finite value fell back to the default. Leave them out for the default.
- `bridges.maxEdges`: a negative or `NaN` value fell back to the default. `Infinity` still means no limit.

### `reach` checks `maxCost`

`graph.paths.reach` and `createPathFinder().reach` throw a `RangeError` when `maxCost` is negative or `NaN`. A negative limit used to return the start alone, and `NaN` the whole component.

### Options are compared by content

A mark at the same place whose options are equal by content no longer restyles its elements: an inline `label: { text: 'name' }` or `ends` rebuilt on every render now rewrites nothing. Functions are still compared by identity, so a function created on every render still restyles every element of its mark. Several definitions given before one frame now restyle the elements whose options differ from the last drawn ones; they used to compare with the previous definition only, and could keep a stale look.

### `<Graph>` calls `onTimeChange` in a microtask

With a controlled `time`, `<Graph>` now hands each window request to `onTimeChange` in a microtask, then renders the new state at once, before the next frame. It used to call it synchronously, which made React warn when `time.set` ran from an effect. Playback still draws in the same frame. A test that asks for a window and reads the state right after now awaits the microtask:

```tsx
// Before
act(() => graph.time.set({ start, end }))

// After
await act(async () => graph.time.set({ start, end }))
```

### Controlled requests start from the last pending one

With a controlled `selection`, `folded` or `hiddenLayers`, a request now starts from the last request not answered yet, as view requests already did, instead of the applied value. Two Shift-clicks before the application answers ask for both elements, where the second used to drop the first. An application that applies every request sees no change.

### `LayoutGraph` has no `groupLinks`

The `groupLinks` field of `LayoutGraph`, pairs of members of the same unfolded group, is removed: no layout read it. A custom layout that keeps groups together reads `groups` instead, whose `parent` gives the group of each node.

```ts
// Before
const links = graph.groupLinks

// After: the index of the group holding a node, or -1
const group = graph.groups?.parent[index] ?? -1
```

## 0.15.0

### Anchors take a single target

`AnchorOptions`, and the props of `<Anchor>`, now take exactly one of `node`, `nodes`, `edge`, `point` or `state`, and `when` only with `node`, `nodes` or `edge`. A call that gave two targets, where the first one in the order `node`, `edge`, `point`, `nodes`, `state` won, no longer compiles: keep the target that was drawn. At runtime, nothing changes.

```ts
// Before: compiled, and followed the node
graph.anchors.set(menu, { node: key, point: world, when: 'selected' })

// After
graph.anchors.set(menu, { node: key, when: 'selected' })
```

A target typed apart from the placement, such as `Pick<AnchorOptions, 'node' | 'point'>`, no longer fits `set`. Let TypeScript infer it, or type it as a union with one member per target:

```ts
// Before
const at: Pick<AnchorOptions, 'node' | 'point'> = hit ? { node: hit.key } : { point: world }

// After
const at: { node: Key } | { point: Point } = hit ? { node: hit.key } : { point: world }
graph.anchors.set(menu, { ...at, side: 'right' })
```

The types of each target are `AnchorNodeTarget`, `AnchorNodesTarget`, `AnchorEdgeTarget`, `AnchorPointTarget` and `AnchorStateTarget`; `AnchorPlacement` holds `side`, `align`, `offset`, `scale` and `interactive`. See [Anchors](/docs/api/graph-instance#targets).

### `undefined` means the default

Every optional option now accepts `undefined` in its type, and reads it as left out. A few options set to `undefined` used to behave otherwise:

- `label: undefined` in `groups()` removed the labels of the groups; they now show their value.
- A style of `selected`, `hovered` or `focused` with a property set to `undefined`, such as `{ raise: undefined }`, cleared that part of the built-in look; it now keeps it.
- A property of `aggregate` set to `undefined` drew the default; it now takes the look of the first merged edge.
- A mark, a layout, a bundling or a routing rebuilt with an option set to `undefined` updated every element or ran again; it is now equal to the same one without the option.

### A single value keeps its size

When the data held a single value, a number scale without `domain` drew it at the middle of its range: `size: () => 12` drew 20 pixel nodes, and `width: () => 2` 3.5 pixel edges. The scale now keeps the value, clamped to its range: 12 pixel nodes and 2 pixel edges. An explicit `domain` of a single value still gives the middle of the range, and a sequential color scale still draws a single value in the middle of its colors.

Number literals and `raw()` now draw a size as given, without an identity scale:

```ts
// Before
defineGraph({
  marks: [nodes(items, { size: () => 24 }), edges(links, { source: 'from', target: 'to', width: () => 2 })],
  scales: { size: (value) => value, width: (value) => value },
})

// After
defineGraph({
  marks: [nodes(items, { size: 24 }), edges(links, { source: 'from', target: 'to', width: 2 })],
})
```

To keep the size drawn before, write it: `size: 20`. `size` and `width` are now typed `NumberChannel<T>`, and `color` `ColorChannel<T>`: they add number literals and `RawAccessor` to `Channel`, so a type read from `NodeOptions<T>['size']` includes them. See [Channels and styles](/docs/marks#channels-and-styles).

### Twelve categorical colors

The default categorical scale now cycles through `--graph-cat-1` to `--graph-cat-12`: the ninth to twelfth categories take the new colors instead of starting over at `--graph-cat-1`. The first eight colors are unchanged. A theme that sets `--graph-cat-1` to `--graph-cat-8` keeps the default values of the four new tokens: set them too, or give the scale a `range`.

```css
/* Before */
.my-theme {
  --graph-cat-8: #6b5a4e;
}

/* After */
.my-theme {
  --graph-cat-8: #6b5a4e;
  --graph-cat-9: #a8475e;
  --graph-cat-10: #5f6a1c;
  --graph-cat-11: #6a68c8;
  --graph-cat-12: #9a63ad;
}
```

### `view.fit` takes options

`view.fit` takes a single object of [`FitOptions`](/docs/view#fit): the keys to frame go in `nodes`, next to `padding` and `duration`. Edges can be framed too, by their two ends, and a path or the selection passes as is. Keys given as a list now throw a `TypeError`.

```ts
// Before
graph.view.fit(['n1', 'n2'], { padding: 64, duration: 400 })
graph.view.fit(undefined, { duration: 400 })
graph.view.fit(path.nodes)

// After
graph.view.fit({ nodes: ['n1', 'n2'], padding: 64, duration: 400 })
graph.view.fit({ duration: 400 })
graph.view.fit(path)
```

A fit after each layout run can become `autoFit: 'layouts'` in the `view` of the definition, and a padding repeated on every fit, such as room for a panel, the `padding` of that `view`:

```ts
// Before
graph.on('layoutend', ({ completed }) => {
  if (completed) graph.view.fit(undefined, { padding: { right: 320 }, duration: 400 })
})

// After
defineGraph({ marks, layout: force(), view: { autoFit: 'layouts', padding: { right: 320 } } })
```

See [The first view](/docs/view#the-first-view) and [Padding](/docs/view#padding).

### `selectionchange` carries the selection in `selection`

The payload of `selectionchange`, and of `onSelectionChange` in controlled mode, is now an object with the selection in `selection`, so that it can grow without breaking handlers.

```ts
// Before
graph.on('selectionchange', ({ nodes }) => show(nodes))
mountGraph(container, { definition, ariaLabel, selection, onSelectionChange: (next) => apply(next) })

// After
graph.on('selectionchange', ({ selection }) => show(selection.nodes))
mountGraph(container, { definition, ariaLabel, selection, onSelectionChange: ({ selection }) => apply(selection) })
```

In React, `onSelectionChange={setSelection}` becomes `onSelectionChange={(event) => setSelection(event.selection)}`.

### Paths take a `direction`

`directed` in the options of `paths.shortest`, `paths.reach` and `createPathFinder` is replaced by `direction`, which can also follow edges backward, from target to source. A path finder built on reversed edges to walk upstream is no longer needed. `merge: { directed }` on edges does not change.

```ts
// Before
graph.paths.reach(key, { directed: true })

// After
graph.paths.reach(key, { direction: 'forward' })
graph.paths.reach(key, { direction: 'backward' })
```

See [Weights and direction](/docs/paths#weights-and-direction).

### `update` keeps the options left out

`update` on a timeline, a legend, a minimap and their renderers changed every option: an option left out went back to its default. It now changes only the options it is given, and an option set to `undefined` goes back to its default. Calls that passed every option still work. To reset an option, pass it as `undefined`:

```ts
// Before: also returned loop and speed to their defaults
timeline.update({ mode: 'grow' })

// After: keeps loop and speed
timeline.update({ mode: 'grow' })

// After: returns speed to its default
timeline.update({ speed: undefined })
```

The React components `<Timeline>`, `<Legend>` and `<Minimap>` behave as before: a prop that goes away returns to its default.

### Edge targets carry their ends

Edge targets, in events, `pick`, `focus.get` and the store, carry a new `endpoints` key, the ends of the edge as drawn. Strict equality checks on edge targets in your tests see it.

## 0.10.0

### Data types flow from the marks

`defineGraph` now infers the item type and the name of each mark, and types every target with them: events, `hovered` and `focused` in the state, `graph.pick`, `graph.focus.get`, aggregated edges and the event props of `<Graph>`. Casts of `datum` to its own type keep compiling and can go. Give marks a `name` to tell several marks of one kind apart: see [TypeScript](/docs/typescript).

What may need a change:

- `graph.update({ definition })` refuses a definition whose marks have item types the mounted definition does not have, and so does `defineGraph({ marks: [] })` mounted first and replaced later. Give the first definition every mark, or type the instance as a plain `GraphInstance`: `const graph: GraphInstance<'muted'> = mountGraph(...)`.
- Targets carry a new `mark` key, the name of their mark, `undefined` without one. Strict equality checks on targets in your tests see it.
- Components inside `<Graph>` still get untyped targets from the hooks. Type them with `useGraph<S, M>()`, or by typing the parameter of the selector of `useGraphState` or of the handler of `useGraphEvent`.
- Type parameters, if you write them: `GraphDefinition`, `GraphDefinitionOptions`, `MountGraphOptions`, `GraphInstance`, `GraphState`, `GraphStore` and `GraphProps` take the union of the marks as a second parameter. `GraphTarget`, `GraphEvents`, `GraphFocus`, `GraphLayout`, `GraphEventProps` and the event payloads take it as their first, and `GraphEventHandler` as its second. Without it, every type keeps its untyped form.
- `NodeMark`, `EdgeMark`, `NodeOptions` and `EdgeOptions` take the type of the name as a second parameter: `nodes(items)` is a `NodeMark<Item, undefined>`. `Layout` and `LayoutGraph` take the item type of the nodes, and `grid` and `rings` return a `Layout<T>`.
- The second type parameter of `useGraphEvent` is now the payload type, inferred from the handler.

## 0.8.0

### Layout spacing is a gap between node borders

`spacing` in [`grid`, `rings` and `radial`](/docs/api/layouts) used to be the distance between the centers of two neighboring places. It is now the gap left between the borders of the largest moved nodes, like `spacing` in `force` and `layerSpacing` and `nodeSpacing` in `layers`.

Without an explicit `spacing`, nothing moves: the default gap is the largest diameter, at least 24, which gives the same distances as before.

With an explicit value, subtract the largest node diameter to keep the same result. With nodes at most 20 world units across, `grid({ spacing: 60 })` becomes `grid({ spacing: 40 })`.

`0` is now allowed and makes the largest nodes touch. A negative or non-finite value falls back to the default.
