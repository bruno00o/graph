A shape mark draws free shapes under the nodes and the edges: polygons with holes, discs and rings, rectangles, and lines. Unlike [hulls and containers](/docs/drawing-layers), which follow nodes, a shape has its own geometry, given by your data in world units or in degrees. Shapes are elements of the graph: they come from a mark, with keys, live sources, `issues()` and `count()`, and the exports draw them.

```ts
import { defineGraph, edges, nodes } from '@bruno00o/graph'
import { shapes } from '@bruno00o/graph/shapes'

const zones = [
  { id: 'north', geometry: { rings: [[[0, 0], [400, 0], [400, 300], [0, 300]]] } },
  { id: 'pond', geometry: { center: { x: 600, y: 150 }, radius: 120, inner: 60 } },
  { id: 'path', geometry: { points: [{ x: 0, y: 360 }, { x: 700, y: 330 }] } },
]

defineGraph({
  marks: [
    shapes(zones, { fill: 'color-mix(in srgb, var(--graph-cat-1) 20%, transparent)' }),
    edges(links, { source: 'from', target: 'to' }),
    nodes(items, { x: 'x', y: 'y' }),
  ],
})
```

`shapes` comes from `@bruno00o/graph/shapes`: the geometry reader and the triangulation stay out of a graph that has no shapes. Every option is in the [API reference](/docs/api/shapes).

## Geometries

`geometry`, the `geometry` field by default, takes one of these forms:

| Form | Draws |
| --- | --- |
| `{ rings }` | A polygon: the first ring is the outline, the others are holes. Rings close on their own, in either direction |
| `{ points, closed }` | A line through the points, closed or not. A line is never filled |
| `{ center, radius, inner }` | A disc, or a ring with `inner` |
| `{ x, y, width, height, cornerRadius }` | A rectangle, with rounded corners or not |
| GeoJSON `Polygon`, `MultiPolygon` | Polygons from `[longitude, latitude]` positions |
| GeoJSON `LineString`, `MultiLineString` | Lines from `[longitude, latitude]` positions |

A point is `{ x, y }`, `[x, y]` or `{ longitude, latitude }`. Degrees are projected like the `longitude` and `latitude` of nodes, so shapes from GeoJSON line up with nodes placed by coordinates. A circle around a place in degrees takes its radii in meters.

A geometry that cannot be read, and a polygon whose rings cross, are listed by `issues()` with the type `'invalid-shape'`: see [Problems in the data](/docs/data#problems-in-the-data). A crossed polygon is still drawn as well as can be.

## Style

`fill` colors polygons, discs, rings and rectangles, and `stroke` their outline and the lines. Both default to the theme, `--graph-shape-fill` and `--graph-shape-stroke`, and `null` draws none. `strokeWidth` is in screen pixels, 1 by default, and `dash` takes `'solid'`, `'dashed'` or `'dotted'`, as for edges. `opacity` fades the fill and the outline together.

```ts
shapes(zones, {
  fill: (zone) => (zone.id === 'pond' ? 'var(--graph-cat-6)' : null),
  stroke: 'var(--graph-ink-muted)',
  strokeWidth: 2,
  dash: (zone) => (zone.id === 'path' ? 'dashed' : 'solid'),
  opacity: 0.4,
})
```

Fills and outlines are antialiased at every zoom, and outlines keep their width in pixels.

## Order

Shapes draw right after the [background grid](/docs/drawing-layers#background-grid), under containers, hulls, edges and nodes. Between shapes, the marks draw in the order of `marks`, and within a mark, `order` sorts them: a lower value draws first, under the others. Without `order`, or for equal values, shapes draw in the order they arrived.

```ts
shapes(zones, { order: (zone) => (zone.id === 'pond' ? 1 : 0) })
```

## Selecting and hovering

Shapes take the pointer like nodes and edges: hover, `click`, `doubleclick`, `contextmenu`, `pointerenter`, `pointerleave` and `pointermove` carry a target whose `kind` is `'shape'`, and the cursor turns into a pointer over a shape that can be picked. A click selects a shape, and Shift, Cmd or Ctrl adds it or removes it, as for nodes; a click on the background and Escape clear the selection. With a shape mark in the definition, the selection has a `shapes` list next to `nodes` and `edges`:

```ts
graph.on('click', ({ target }) => {
  if (target?.kind === 'shape') console.log(target.key, target.datum)
})

graph.selection.set({ shapes: ['pond'] })
graph.selection.get() // { nodes: [], edges: [], shapes: ['pond'] }
```

Nodes and edges stay on top: a shape never takes the pointer from a node, an edge or a container drawn over it. Between shapes, the one drawn last wins, and a [raised](#states) shape comes first. Dragging a shape moves the view, and a double click on a shape does nothing by default. The [lasso](/docs/interaction#lasso), Shift and drag, starts on the background or on a shape, and takes the nodes inside it and the shapes whose every point is inside it: a shape that contains the lasso is not taken. The keyboard focus stays on nodes: shapes are neither focused nor announced.

`graph.datumOf({ kind: 'shape', key })` returns the item of a shape. The selection, `selectionchange` and the states hold shape keys only when the definition has a shape mark: see [`ElementKeys`](/docs/api/graph-instance#selection). In a [controlled selection](/docs/interaction#controlled-selection), pass `shapes` with the other keys.

## What takes the pointer

`pick` says what of a shape takes the pointer:

| `pick` | Takes the pointer |
| --- | --- |
| `'painted'` (default) | Its inside when it is filled, its outline when it is stroked |
| `'stroke'` | Its outline only, filled or not |
| `false` | Nothing: the pointer, the clicks and the lasso go through |

A large zone under everything is easy to click by mistake: give it `pick: 'stroke'` to select it by its border, or `pick: false` when it only decorates. Outlines take the pointer within half their width plus a few pixels, at every zoom. Holes are not part of a shape.

```ts
shapes(zones, { pick: 'stroke' })
shapes(background, { pick: false })
```

## States

States apply to shapes as to nodes and edges. `selected` draws the outline of a shape in the accent color, 2 pixels wide, and `hovered` in the ink color; both are raised. A style for every kind applies to shapes too, and a style by kind takes `shapes` next to `nodes` and `edges`:

```ts
defineGraph({
  marks: [shapes(zones), nodes(items)],
  states: {
    flagged: {
      nodes: { stroke: 'var(--graph-cat-4)' },
      shapes: { fill: 'var(--graph-cat-4)', strokeWidth: 3 },
    },
  },
})

graph.states.set('flagged', { nodes: ['a'], shapes: ['north'] })
```

`fill`, `stroke`, `strokeWidth` and `opacity` restyle a shape; `label`, `halo` and the other node and edge properties do not apply. `raise` draws a shape after the other shapes and picks it first among them: it still stays under containers, hulls, edges and nodes. `hide` removes a shape everywhere: drawing, picking, the lasso, `count().shown` and the exports.

`others` crosses kinds: a state whose members are nodes styles the shapes outside it, and a shape member activates a state for every kind. To dim the nodes around a selected zone, and not the other zones, give `others` by kind:

```ts
states: {
  focus: { nodes: { others: { opacity: 0.2 } } },
}
```

## Zoom, time and layers

`minZoom`, `maxZoom`, `time` and `layer` work on shapes as on nodes. A shape out of its [zoom range](/docs/zoom), out of the [time window](/docs/time) or in a [hidden layer](/docs/multilayer) is absent: not drawn, not picked, not taken by the lasso, not counted in `shown` and not exported. It fades in and out with the same margins as nodes.

```ts
shapes(parcels, { minZoom: 2, layer: 'parcels' })
shapes(floods, { time: (flood) => ({ start: flood.from, end: flood.to }) })
```

`graph.layers` sees the layers of shapes, and a layer may hold nodes, edges and shapes. `view.fit` keeps counting shapes hidden by a zoom range or the time window, as it does for nodes.

## Framing and counting

The first automatic fit frames the shapes with the nodes, and a graph with shapes only frames its shapes. `view.fit` takes `shapes`, a list of shape keys, next to `nodes` and `edges`:

```ts
graph.view.fit({ shapes: ['north'], duration: 400 })
```

With a shape mark in the definition, `count()` returns `shapes` and `shown.shapes` as well: see [`count`](/docs/api/graph-instance#count). A graph without shapes keeps the counts it had.

## Not there yet

- Shapes have no labels.
- On a [map](/docs/map), they are not drawn yet, with a warning in development, and they take no pointer.
- Shapes cannot be dragged or edited.

## Cost

A graph without shapes creates no program, texture or buffer for them, and does no work per frame. Polygons are triangulated once, when their geometry changes: 10,000 polygons of 50 points take about 70 milliseconds, and their first frame about 150 milliseconds in Chrome. Panning over them costs about 3 milliseconds per frame, with a selection, a hover and a state with `others`. The first pick after a change builds an index of the shapes, about 10 milliseconds for 10,000 polygons; then a pick takes a few microseconds.
