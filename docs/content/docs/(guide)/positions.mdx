## Initial placement

A node gets its first position in this order:

1. From the `x` and `y` channels, when the mark has them, or else from `longitude` and `latitude`.
2. Near its neighbors that are already placed, on a ring around them. A node that arrives while you explore appears next to what it connects to.
3. Otherwise on a spiral around the origin. A first batch without coordinates starts as a compact disc.

With a layout in the definition, nodes without `x` and `y` then move to the place it computes: the first batch as a whole, later nodes next to their neighbors. See [Layouts](/docs/layout).

## Positions from your data

`x` and `y` are channels like the others: a field or a function, in world units. When an update changes them, the node moves there.

```ts
const definition = defineGraph({
  marks: [nodes(items, { label: 'label', x: 'x', y: 'y' })],
  transitions: { positions: 200 },
})
```

The move is animated over `transitions.positions` milliseconds, 120 by default, and 0 with `prefers-reduced-motion`. Updates spaced by a paced write stay smooth.

A node only moves when its own `x` or `y` value changes, or its `longitude` or `latitude`. A node dragged by the user does not jump back when another field of its data changes, and incoming updates are ignored while the user is dragging it.

## Longitude and latitude

`longitude` and `latitude`, in degrees, place a node with Web Mercator, the projection of web maps. The world spans 512 units, from longitude -180 at `x` 0 to longitude 180 at `x` 512, and from latitude 85.05 at `y` 0 to latitude -85.05 at `y` 512. Nodes placed this way default to `units: 'screen'`, so their size does not change with the zoom.

```ts
nodes(places, { longitude: 'lng', latitude: 'lat', label: 'name' })
```

`geoToWorld` and `worldToGeo` convert between degrees and world units, for example to read where the user clicked. Edges between such nodes can follow [great circles](/docs/map#great-circles) with `geodesic`. To draw the nodes over a basemap, flat or on a globe, see [Map](/docs/map). Nodes placed this way never move, even when they overlap: to place them by their coordinates and still move apart those that overlap, use the [`geo` layout](/docs/layout#geography) instead.

## Move nodes from code

```ts
graph.positions.get('n1')
graph.positions.set([['n1', { x: 0, y: 0 }], ['n2', { x: 80, y: 0 }]], { duration: 300 })
graph.positions.set(new Map([['n3', { x: 40, y: 60 }]]))
```

`set` takes any iterable of `[key, point]` pairs; a `Map` works. Without a duration, the nodes move at once. A pair whose `x` or `y` is not a finite number, such as `NaN` or a missing value, is skipped with a warning in development: its node stays where it is, and the other pairs apply.

## Save and restore

`positions.snapshot()` reads every node at once, in a new `Map` from key to point that `set` takes back as is. It holds every node of the data, those hidden in folded groups included.

```ts
const saved = graph.positions.snapshot()
localStorage.setItem('positions', JSON.stringify([...saved]))

graph.positions.set(new Map(JSON.parse(localStorage.getItem('positions') ?? '[]')), {
  duration: 400,
})
```

A node that glides, after `set` with a duration, after a layout result or toward new `x` and `y` values, is read where it is going, so a snapshot taken mid-glide is the layout you will see. `snapshot({ settled: false })` reads where nodes are drawn now, as `get` does.

Examples: [save and restore positions](/examples/save-positions) takes a snapshot and sets it back, and [snap to a grid](/examples/snap-to-grid) moves a dropped node to the nearest grid point.

## Listen to moves

`positionchange` fires when nodes are moved by a drag, by `positions.set`, or by a layout run that ended, with their target positions. Its `origin` is `'drag'`, `'api'` or `'layout'`. Moves that come from your data do not emit it, so writing the positions back to the data never loops.

During a drag, it fires on every move of the pointer. To save once per drag, listen to `dragend` instead, or pace your writes.

```ts
graph.on('positionchange', ({ origin, positions }) => {
  if (origin !== 'drag') save(positions)
})

graph.on('dragend', ({ keys }) => {
  save(new Map(keys.map((key) => [key, graph.positions.get(key)])))
})
```

To write positions to a TanStack DB collection, use [`persistPositions`](/docs/tanstack-db).
