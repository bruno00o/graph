## Give elements a time

`time` on `nodes()`, `edges()` and [`shapes()`](/docs/shapes#zoom-time-and-layers) tells when an element exists. It is a channel: a property name, or a function of the item.

```ts
import { defineGraph, edges, nodes } from '@bruno00o/graph'

const definition = defineGraph({
  marks: [
    edges(links, { source: 'from', target: 'to', time: (link) => link.since }),
    nodes(items, {
      label: 'label',
      time: (item) => ({ start: item.created, end: item.closed }),
    }),
  ],
})
```

A time is one of:

- a moment, in milliseconds since the epoch or as a `Date`: the element exists at that moment only;
- a period `{ start, end }`, from `start`, included, to `end`, left out. A missing or `null` end leaves the period open on that side: `{ start: date }` exists from `date` on, forever;
- `null`, `undefined`, or a value that is not a time: the element has no time and always shows.

A period whose end comes before its start counts as the moment of its start. The types are in the reference of [`nodes`](/docs/api/nodes#options) and [`edges`](/docs/api/edges#options).

## The time window

Without a window, every element shows. A window keeps only the elements that exist in it:

```ts
const graph = mountGraph(container, {
  definition,
  initialTime: { start: new Date(2024, 0, 1), end: new Date(2024, 6, 1) },
})

graph.time.set({ start: Date.UTC(2023, 0, 1), end: Date.UTC(2024, 0, 1) })
graph.time.set({ start: new Date(2024, 0, 1) })
graph.time.set(null)
```

The window too goes from `start`, included, to `end`, left out, and a missing end leaves it open. An element shows when it exists at some moment of the window:

- a period shows when it starts before the window ends and ends after the window starts. A period that ends where the window starts does not show, nor one that starts where the window ends;
- a moment shows from the start of the window, included, to its end, left out;
- with `start` equal to `end`, the window is a single moment, and shows what exists at that moment: periods that contain it, moments equal to it;
- an edge shows only when it, its source and its target all show. An edge without a time follows its ends.

`graph.time.get()` returns the window as numbers, or `null`. Each change emits `timechange` and updates `time` in the [store](/docs/api/graph-instance#graph-state):

```ts tab="Vanilla" tab-group="framework"
graph.on('timechange', ({ window }) => {
  status.textContent = window ? format(window) : ''
})
```

```tsx tab="React" tab-group="framework"
const window = useGraphState((state) => state.time)
```

### Controlled window

Pass `time` to own the window, as for the [view](/docs/view#controlled-view). `graph.time.set` and the timeline then call `onTimeChange`, and only a new `time` moves the window:

```tsx
const [window, setWindow] = useState<TimeWindowInput | null>(null)

<Graph definition={definition} time={window} onTimeChange={(event) => setWindow(event.window)} />
```

In React, `<Graph>` hands each request to `onTimeChange` in a microtask and renders the new state at once, before the next frame: playback stays smooth, and a `time.set` called from an effect does not make React warn. See the [time slider of your own](/examples/time-slider) example.

## Fade

By default, elements appear and disappear at once. `time.fade` in `defineGraph` fades them in after the window reaches them and out before it leaves them, over a duration in the milliseconds of the data:

```ts
defineGraph({ marks, time: { fade: 30 * 86_400_000 } })
```

With a fade, an element exactly at the edge of the window has faded out, and counts as hidden. The fade multiplies the opacity of the element and of its label. An edge takes the faintest of its own fade and those of its ends. See the [moments and periods](/examples/time-moments) example.

## What a hidden element is

An element outside the window behaves like one outside its [zoom range](/docs/zoom#what-a-hidden-element-is):

- it is not drawn, and neither are its label, its badges and the edges that end on it; its anchors leave the screen;
- it is not picked: hover, click and the lasso pass through it, and the arrow keys move the focus over shown nodes only;
- the [legend](/docs/minimap-and-legend) counts only shown elements, the minimap draws only them, and envelopes wrap only them;
- [exports](/docs/export) draw what the current window shows, or the window of their `window` option, and a `'graph'` region frames shown elements only;
- [`graph.paths`](/docs/paths) with `visible: true` walks over shown nodes and edges only.

A hidden element stays in the data, in the selection and in states. `view.fit` still frames it, and layouts place every node, in the window or not, with all its edges: the nodes in the window keep the places they have in the whole graph, and the graph does not move when the window moves.

In a [group](/docs/groups), each node follows its own time. An edge drawn in place of edges that end in a folded group exists from the earliest start to the latest end of its members, and has no time when one of them has none. `aggregate.time` reads it from the [aggregated edge](/docs/api/edges#merged-edges) instead.

## Timeline

`@bruno00o/graph/timeline` follows the time of a graph: its extent, a histogram of how many nodes and edges exist over time, and the window, which it moves by brushing, stepping and playing.

```ts
import { createTimeline, mountTimeline } from '@bruno00o/graph/timeline'

const timeline = createTimeline(graph, { mode: 'slide', loop: true })
const view = mountTimeline(timeline, {
  ariaLabel: 'Timeline',
  labels: { play: 'Play', start: 'Start of the window', end: 'End of the window', window: 'Window' },
})
footer.append(view.element)
```

`createTimeline` keeps its state in `timeline.store`: the extent, the range shown on the bar, the bins and ticks, the window and playback. `mountTimeline` renders it: a play button, the histogram, the window as a brush with two handles, and ticks. Draw your own instead from the store; every action is a method of the timeline. The options are in the [reference](/docs/api/timeline).

A timeline follows a graph on a map the same way: see [Map](/docs/map#time) and the [map in time](/examples/map-time-window) example.

### Histogram

Bins follow the calendar: a day, a week starting on Monday, a month, a year, or a multiple of them, chosen so that the bar holds about `bins` of them. A bin counts the nodes and the edges whose time meets it, the same way the window does, so a bin brushed alone shows what it counts. An edge counts over the time when it and both its ends exist. Elements without time are not counted.

[Shapes](/docs/shapes) follow the window like any element, but the timeline counts only nodes and edges: it draws no bar for a shape, and the extent ignores their times.

The extent goes from the earliest start to the latest end of the nodes and edges. A graph whose only times are on shapes has no extent, unless you pass one. Pass `extent` to fix one end or both, for instance to show the whole of a year or to end at today.

### Brush, step and play

- Drag across the histogram to brush a new window, drag the window to move it, drag a handle to move one end. A click centers the window on the time clicked. Ends snap to the bins; hold <kbd>Alt</kbd> for a free end.
- The wheel and a trackpad pinch zoom the bar around the pointer; <kbd>Shift</kbd> and the wheel, or a horizontal swipe, pans it.
- The handles and the window are sliders: the arrow keys move them by a bin, <kbd>Page Up</kbd> and <kbd>Page Down</kbd> by ten, <kbd>Home</kbd> and <kbd>End</kbd> to the ends of the extent.
- The play button, `play`, `pause` and `toggle` run playback at `speed`, in milliseconds of data time per second; by default it crosses the extent in twenty seconds. In `'slide'` mode the window keeps its width and moves; in `'grow'` mode its start stays and its end moves, so it gathers everything since the start. With `loop`, playback starts again from the beginning.

```ts
timeline.brush(new Date(2023, 0, 1), new Date(2023, 3, 1))
timeline.step()
timeline.update({ mode: 'grow', speed: 7 * 86_400_000 })
timeline.play()
```

`update` changes the options it is given and keeps the others; an option set to `undefined` returns to its default.

See the [graph that grows](/examples/time-growth) example, which plays in `'grow'` mode.

### A moment instead of a window

With `instant: true`, the window is a single moment, a cursor: `start` equals `end`, and the graph shows what exists at that moment. The bar draws a cursor instead of the brush; a press or a drag on the bar moves it, and it snaps to the bins unless you hold <kbd>Alt</kbd>. The arrow keys move it by a bin, `step` and `nudge` too, and playback moves it at `speed`.

```ts
const timeline = createTimeline(graph, { instant: true })
timeline.set({ start: new Date(2024, 5, 1), end: new Date(2024, 5, 1) })
timeline.step()
timeline.play()
```

The window stays the default; `update({ instant: true })` switches a timeline without moving its window, and `set` still takes any window.

### Events

The histogram counts the nodes and edges of the graph by default. Pass `events` to count the events of your application instead, such as a log of what changed and when: each event is a moment and a kind, and the bins stack the kinds.

```ts
interface Change {
  readonly at: Date
  readonly type: 'added' | 'changed' | 'removed'
  readonly key: string
}

declare const changes: Change[]

const timeline = createTimeline(graph, {
  events: changes,
  eventTime: 'at',
  eventKind: 'type',
  kinds: ['added', 'changed', 'removed'],
  instant: true,
})
```

- `eventTime` and `eventKind` read the moment and the kind of an event, as a field name or a function; by default, the fields `time` and `kind`. An event without a valid moment is left out; one without a kind belongs to the kind `''`.
- The kinds stack in the order of `kinds`, then in the order the events first give them, colored by the category tokens `--graph-cat-1` to `--graph-cat-12`, or by `kindColors`. `state.kinds` lists them, with their colors and counts, and each bin counts them in `bin.kinds`, in the same order.
- `toggleKind` hides a kind, or shows it again; `hiddenKinds` sets the hidden kinds when it changes. A hidden kind leaves the stacks, `bin.events`, stepping and `timeline.events`. The bar shows a button per kind, which hides or shows it, when there is more than one; `legend: false` removes them, `kindText` writes their text.
- The extent comes from the events: from the first to the last. The bins still count nodes and edges, for a renderer of your own.
- `events` takes a new array for each change; the array is never changed in place. When the new array starts with the items of the previous one, as a log does when it grows, only the items added are read. The `data` of a [TanStack DB](/docs/tanstack-db) live query is a new array for each change: pass it as it comes.

`stepEvent` moves to the next event, or back with a negative count, skipping hidden kinds and counting events at the same moment once. With `instant`, the cursor lands on the event, and `timeline.events(moment)` returns the events made at that moment, for a panel of details; `timeline.events(bin.start, bin.end)` returns those of a bin. Without `instant`, the end of the window lands 1 ms after the event, so that the window includes it. In the bar, <kbd>Shift</kbd> with the arrow keys steps from event to event on the cursor and on the window.

```ts
timeline.stepEvent()
const window = timeline.store.state.window
const made = window?.start == null ? [] : timeline.events(window.start)
```

See the [history of changes](/examples/change-history) example, which replays a graph over thirty days of generated changes.

Bins follow the calendar and the zoom of the bar, so the timeline needs the events themselves, not counts per day: 100,000 events cost a few tens of milliseconds to read (see [Performance](#performance)).

### Without a graph

A timeline does not need a graph: `createTimeline(options)`, without a graph, counts its `events` and keeps the window in its state instead of moving the window of a graph. Apply it to as many graphs as you want, or to none:

```ts
const timeline = createTimeline({ events: changes, eventTime: 'at', eventKind: 'type', instant: true })
timeline.store.subscribe(({ window }) => {
  for (const graph of graphs) graph.time.set(window)
})
```

In React, `useTimeline({ graph: false, events })` does the same.

### Text

The timeline writes no text of its own. `labels` names the play button, the handles, the window, the cursor and the group of the buttons of the kinds for assistive technologies, and `labels.range` writes the value of the window from the values of its ends. Ticks and values are dates and times written by `Intl.DateTimeFormat` in the language of the page (`<html lang>`), as precise as the unit of the bins; pass `format` to write them yourself:

```ts
mountTimeline(timeline, {
  format: (time, unit) => (unit === 'year' ? String(new Date(time).getFullYear()) : day.format(time)),
})
```

### React

```tsx
import { Graph, Timeline, useTimeline } from '@bruno00o/graph/react'

<Graph definition={definition} ariaLabel="Graph">
  <Timeline loop labels={labels} ariaLabel="Timeline" />
</Graph>
```

`<Timeline>` renders the default timeline where it stands. `useTimeline` returns the state and the timeline, for a timeline drawn by your components, as in the [time slider of your own](/examples/time-slider) example. Both read the graph of the `<Graph>` or [`<MapGraph>`](/docs/map#react) around them; elsewhere, pass it with `<Timeline graph={graph} />` or `useTimeline({ graph })`, or `graph: false` for a timeline without a graph.

To draw the timeline that `useTimeline` made, and read it at the same time, pass it to `<Timeline timeline={timeline} />`: the bar and your components then share one timeline.

```tsx
function Replay() {
  const { state, timeline } = useTimeline({ events: changes, eventTime: 'at', instant: true })
  const moment = state.window?.start
  const made = timeline && moment != null ? timeline.events(moment) : []
  return (
    <>
      <Details changes={made} />
      <Timeline timeline={timeline} labels={labels} />
    </>
  )
}
```

## Values over time

`time` says when an element exists. A history says what its fields are at each moment: a journal of changes, each a key, a moment and values. `historyFrom` from `@bruno00o/graph/history` reads it, and the `history` option of `nodes()`, `edges()` or [`shapes()`](/docs/shapes) applies it to the elements of the mark.

```ts
import { defineGraph, nodes } from '@bruno00o/graph'
import { historyFrom } from '@bruno00o/graph/history'

interface Item {
  readonly id: string
  readonly state: 'idle' | 'active'
  readonly level: number
}

interface Change {
  readonly id: string
  readonly time: Date
  readonly kind: 'state' | 'level'
  readonly node: string
  readonly state?: 'idle' | 'active'
  readonly level?: number
}

declare const items: Item[]
declare const changes: Change[]

const history = historyFrom(changes, {
  key: 'node',
  values: (change) => ({ state: change.state, level: change.level }),
})

const definition = defineGraph({
  marks: [nodes(items, { color: 'state', label: 'id', history })],
})
```

The graph reads each element as its item plus the values of its entries up to the end of the time window:

- with a single-moment window, as the cursor of a timeline with `instant: true`, the entries at that moment count;
- with a window, only the entries before its end count, as the end is left out;
- without a window, or with an open end, every entry counts: the elements show their latest values.

Entries apply in the order of their moments. Each sets the fields it names; `undefined` leaves a field as it was, so a function can return every field it might set. The values may change any field but those named by the `key` and `time` options of the mark: the label and the color, and also the ends of an edge, the parent of a node, its position or the geometry of a shape. Every reader sees the values of the moment: styles, `datumOf`, events, the legend, paths and exports.

By default, `historyFrom` reads entries that are already `{ key, time, values }`; its `key`, `time` and `values` options read entries of any other shape. Entries can be an array or a live source, such as a TanStack DB collection. The values must fit the items: a field they do not have is refused by TypeScript. See the [API](/docs/api/history) for the details.

`graph.history.of({ kind: 'node', key })` lists the entries of an element, and `graph.history.instant()` returns the moment the values are read at.

### One journal for the timeline and the graph

A journal of changes is also a list of [events](#events): pass the same array to the timeline and to `historyFrom`. The timeline counts the changes and steps from one to the next, and the graph shows the values of each moment:

```ts
const timeline = createTimeline(graph, { events: changes, eventKind: 'kind', instant: true })
timeline.stepEvent()
```

Moving the cursor reads again only the elements whose entries it crosses: stepping from one change to the next touches one element. See the [values over time](/examples/values-over-time) example.

### Scales over the whole history

The scales of a mark with a history cover every value its elements take over the whole journal, not only those of the moment. A state keeps its color and a level its size at every moment, and moving the cursor never rewrites elements that its step does not cross:

- a numeric scale, for a size, a width or a sequential color, spans the smallest and the largest value of the journal;
- a categorical color gives each value its color in the order of its first appearance in the journal, the values of the items first, so the colors are the same whatever the moment shown first. A `domain` still comes first.

Entries that arrive later, from a live source, extend the scales: a new value takes the next color and the others keep theirs. Marks without a history keep scales on their current values.

The [legend](/docs/minimap-and-legend#sections) lists the categories of the whole history and counts the elements of the moment, zero for a value not drawn then. `empty: 'hide'` leaves those out:

```ts
const legend = createLegend(graph, { empty: 'hide' })
```

Scales do not follow the values of the moment only: each step would move their ends and rewrite every element. A `domain` sets them by hand.

Merged edges and folded groups read their aggregate at the moment and take no part in the scales of the history.

## Performance

The time of each element is read when the data changes, like every style. Moving the window only compares it with them on the GPU: playback costs no work per element. Measured on a laptop, at 500,000 nodes and 1,000,000 edges, each with a random period:

| Step | Time |
| --- | --- |
| Reading the times, on top of the first frame | 130 ms |
| Frame while playing | 16.7 ms, at 60 frames per second |
| Histogram, first count | 180 ms |
| Histogram, after 100 nodes change their time | 12 ms |
| Histogram, after every node changes its time | 120 ms |

The timeline counts again only when times change, and only for the elements whose time changed and the edges that end on them.

Events cost little next to the graph. Measured on a laptop, with events spread over 30 days in five kinds:

| Step | 100,000 events | 1,000,000 events |
| --- | --- | --- |
| First count | 3 to 4 ms | 31 ms |
| Count after 1,000 events are added at the end | 0.7 ms | 30 ms |
| Count of a new array in another order | 3 to 4 ms | 32 ms |
| `stepEvent` | under 0.01 ms | under 0.01 ms |
| First `events` after a change, then each one | 7 ms, then 0.02 ms | 77 ms, then 0.13 ms |

Stepping through the events of the [history of changes](/examples/change-history) example at every frame keeps 60 frames per second.

A [history](#values-over-time) costs work only where a step crosses entries. Measured on a laptop, at 100,000 nodes and 200,000 edges, with 1,000,000 entries spread over 30 days on the nodes:

| Step | Time |
| --- | --- |
| Reading the entries, on top of mounting | 140 to 165 ms |
| [Scales over the whole history](#scales-over-the-whole-history), on top of the first frame | 210 to 260 ms, about 0.25 µs per entry |
| Memory of the history | about 40 bytes per entry, plus about 80 bytes per element for its scales |
| A step of one hour, about 1,400 entries | 6 to 7 ms of work, 21 ms per frame |
| A step of one day, about 33,000 entries | 48 to 50 ms of work |
| A jump of 20 days, every node read again | 200 to 235 ms of work |
| Without a history, any step | under 0.2 ms of work |

The scales of the history are read once, then again only for the elements whose entries or items change: the steps above cost the same as without them. Marks without a history cost nothing more.
