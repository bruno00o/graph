## Add bundling

Pass a bundling to `defineGraph`. Bundling by density comes from its own entry point, `@bruno00o/graph/bundling`, so a graph that does not use it carries none of its code.

```ts
import { defineGraph, edges, nodes } from '@bruno00o/graph'
import { densityBundling } from '@bruno00o/graph/bundling'
import { force } from '@bruno00o/graph/layouts/force'

const definition = defineGraph({
  marks: [
    edges<Link>(links, { source: 'from', target: 'to', opacity: 0.5 }),
    nodes<Item>(items, { color: 'group', size: 'weight' }),
  ],
  layout: force(),
  bundling: densityBundling({ strength: 0.85 }),
})
```

Each edge bends toward the places where edges are densest, pass after pass with a smaller reach: edges that run side by side merge, and the routes between parts of the graph stand out. The options are in the [reference](/docs/api/bundling).

- `strength` is the share of the bundled shape drawn: `1` draws the bundles as computed, `0.5` halfway between them and straight lines. A new strength alone eases the edges to it, without computing again: see the [bundling strength](/examples/bundling-strength) example.
- `radius` is how far an edge reaches for others at the first pass, as a share of the larger side of the graph. A longer reach merges edges from further away into fewer, thicker bundles.
- `iterations` is the number of passes. More passes draw tighter bundles.

Bundles read best with thin, light edges: their opacity adds up where edges merge.

A definition takes `bundling` or [`routing`](/docs/routing), not both.

## When bundles are computed

Bundles follow the positions of the nodes, so they are computed once nodes stand still:

- after a layout run, and after the nodes glide to its result;
- 150 milliseconds after a drag, a `positions.set` or a change of positions in the data;
- after edges are added or removed;
- after a new definition changes the bundling, unless only its `strength` changes.

While nodes move, the drawn bundles follow the ends of each edge: the shape of an edge is kept as offsets from the line between its ends. New edges stay straight until the next computation. When a layout moves most nodes, edges ease back to straight lines at its start, and bundle again at its end.

Each new result does not jump into place: edges glide from their current shape to the new one over `transitions.layout`, 400 milliseconds by default, at once with `prefers-reduced-motion`.

`graph.bundling.run()` computes now, without waiting for nodes to stand still, and resolves to `true` once the new bundles are drawn. `bundling.running` in the store is `true` during a computation.

```ts
graph.store.subscribe(() => {
  indicator.hidden = !graph.store.get().bundling.running
})

await graph.bundling.run()
```

## Which edges bundle

Every edge bundles, except loops. Set `bundle` on `edges()` to leave edges out: they stay straight and pull no other edge.

```ts
edges<Link>(links, {
  source: 'from',
  target: 'to',
  bundle: (link) => link.kind !== 'direct',
})
```

Parallel edges bundle with the others and keep their lanes on each side of the path. Edges drawn in place of edges that end in a folded [group](/docs/groups) bundle like any edge.

Bundled edges keep everything else: width, color, arrows, dashes, [flows](/docs/marks#flows), state styles and the highlight of selected and hovered edges. They are picked along their path, their label sits at the middle of the path and turns with it, and [exports](/docs/export) draw them as on screen.

## Size and cost

The computation runs in a Web Worker, so the page stays responsive. Measured on a laptop, for communities placed by a force layout:

| Edges | Computation | Frame, bundled | Frame, straight |
| --- | --- | --- | --- |
| 10,000 | 60 ms | 2.3 ms | 2.1 ms |
| 100,000 | 0.2 s | 4.7 ms | 4.3 ms |
| 1,000,000 | 1.7 s | 43 ms | 25 ms |

Edges spread at random, which cross each other everywhere, take about four times longer: 0.85 s for 100,000 and 7.7 s for a million. Each bundled edge is drawn with 5 to 33 points, by length. On the GPU, a bundled edge takes 16 bytes and each of its points 16 more: 10 MB for 100,000 edges between communities, 25 MB for 100,000 edges at random.

Above `maxEdges`, 200,000 by default, edges stay straight and a warning is logged in development. Raise it for larger graphs that can wait for their bundles.

Bundling is not available on a [map](/docs/map): edges stay straight, or follow [great circles](/docs/map#great-circles). Geodesic edges are never bundled.

## Write your own bundling

`bundling` takes any object of the [`EdgeBundling`](/docs/api/define-graph#bundling) shape. `start` receives the node positions and the edges to bundle, and reports one polyline per edge, from its source to its target, through `end`. A bundling that bends every edge into an arc:

```ts
import type { EdgeBundling } from '@bruno00o/graph'

const arcs: EdgeBundling<Link> = {
  name: 'arcs',
  options: {},
  strength: 1,
  maxEdges: 100_000,
  start(graph, listener) {
    const count = graph.edges.length
    const offsets = new Uint32Array(count + 1)
    const points = new Float32Array(count * 3 * 2)
    for (let edge = 0; edge < count; edge++) {
      const source = graph.ends[edge * 2] ?? 0
      const target = graph.ends[edge * 2 + 1] ?? 0
      const ax = graph.xy[source * 2] ?? 0
      const ay = graph.xy[source * 2 + 1] ?? 0
      const bx = graph.xy[target * 2] ?? 0
      const by = graph.xy[target * 2 + 1] ?? 0
      const middle = [(ax + bx) / 2 - (by - ay) * 0.2, (ay + by) / 2 + (bx - ax) * 0.2]
      points.set([ax, ay, ...middle, bx, by], edge * 6)
      offsets[edge + 1] = (edge + 1) * 3
    }
    listener.end({ offsets, points })
    return { stop: () => {} }
  },
}
```

`graph.datum(index)` returns the item of an edge, typed by the marks of the definition. The graph resamples each polyline evenly, keeps its offsets from the line between the ends, and draws `strength` of them.
