description: Turn data values into colors, sizes and widths, shared by every mark or kept to one.

## Shared scales

Channels go through three scales: `color`, `size` and `width`. A scale is shared by every mark of the definition without [scales of its own](#scales-of-a-mark), so a group keeps the same color on nodes and edges. Configure them in `defineGraph`.

```ts
defineGraph({
  marks: [edges(links, { source: 'from', target: 'to' }), nodes(items, { color: 'group', size: 'weight' })],
  scales: {
    color: { domain: ['A', 'B', 'C'], range: ['var(--graph-cat-3)', 'var(--graph-cat-1)', 'var(--graph-cat-7)'] },
    size: { type: 'linear', range: [10, 40] },
  },
})
```

| Scale | Default | Options |
| --- | --- | --- |
| `color` | Categorical, `--graph-cat-1` to `--graph-cat-12` in order of appearance, cycling | `{ domain, range }`, or `{ type: 'sequential', domain, range }` |
| `size` | Square root from the data extent to `[8, 32]`, so the area follows the value | `{ type: 'linear' \| 'sqrt', domain, range }` |
| `width` | Linear from the data extent to `[1, 6]` | `{ type: 'linear' \| 'sqrt', domain, range }` |

## Color

The color scale is categorical by default, even for numbers: nothing is guessed. A category keeps its color as long as the scale does not change, even when the data changes.

For a gradient, ask for a sequential scale. It interpolates from `--graph-cat-5` to `--graph-cat-1` by default, in steps of one percent.

```ts
scales: {
  color: { type: 'sequential', domain: [0, 100] },
}
```

Values outside an explicit domain are clamped to it. Without a domain, the scale uses the extent of the data and follows it as the data changes.

Examples: [categorical colors](/examples/categorical-colors) and [sequential colors](/examples/sequential-colors), each with its legend.

## Size and width

`size` is a diameter. The default square root scale makes the area of a node proportional to its value. `width` sets the edge width in screen pixels.

```ts
scales: {
  size: { type: 'sqrt', domain: [0, 1000], range: [6, 48] },
  width: { range: [0.5, 4] },
}
```

A number literal skips the scale: `size: 24` draws every node 24 pixels wide, and `width: 2` every edge 2 pixels wide. `raw()` does the same for a function, and for colors:

```ts
import { edges, nodes, raw } from '@bruno00o/graph'

defineGraph({
  marks: [
    edges(links, { source: 'from', target: 'to', width: 2 }),
    nodes(items, { size: raw((item) => item.radius * 2), color: raw((item) => item.hex) }),
  ],
})
```

Raw values stay out of the extent and the categories of the scale, so they never move the other elements of that scale. See [Channels and styles](/docs/marks#channels-and-styles).

### A single value

When every value of the data is the same, the extent is a single point. A number scale then keeps the value, clamped to its range: with the default `size` range `[8, 32]`, a weight of 12 draws a 12 pixel node and a weight of 40 a 32 pixel node. An explicit `domain` of a single value returns the middle of the range, a sequential color scale draws a single value at the middle of its colors, and a function scale gets the value as it is.

Examples: [size scale](/examples/size-scale) compares the square root, linear and identity scales, and [edge width, dashes and arrows](/examples/edge-styles) reads the width from a field.

## Scales of a mark

A mark with `scales` of its own keeps its values apart: its own extent, its own categories and its own legend section. Nodes take `color` and `size`, edges take `color` and `width`, and the ends of an edge use the scales of their mark. Every other mark keeps the shared scale.

```ts
defineGraph({
  marks: [
    edges(links, { source: 'from', target: 'to', width: 'amount', scales: { width: { range: [1, 12] } } }),
    nodes(items, { color: 'group', size: 'weight' }),
    nodes(topics, {
      color: 'kind',
      size: 'score',
      scales: {
        color: { range: ['var(--graph-cat-9)', 'var(--graph-cat-11)'] },
        size: { range: [24, 64] },
      },
    }),
  ],
})
```

The scores of `topics` span their own extent, so a large score does not shrink the other nodes, and their kinds take colors without sharing categories with the groups of `items`. A scale of a mark takes the same options as a shared one, a function included, and `groups()` takes `scales` like `nodes()`. Types: [`NodeScalesOptions`](/docs/api/nodes#scales) and [`EdgeScalesOptions`](/docs/api/edges#scales). In the [legend](/docs/minimap-and-legend#sections), each mark with scales of its own has its own sections.

## Functions

Any scale can be a function of the channel value.

```ts
scales: {
  size: (value) => 8 + Math.log10(1 + value) * 8,
  color: (value) => (value === 'A' ? 'var(--graph-cat-4)' : 'var(--graph-node)'),
}
```

An identity function uses the channel values as they are: `size: (value) => value` makes `size: 'weight'` a diameter in pixels. To keep the values of one mark only, wrap its channel in `raw()` instead.

## Missing values

A channel that returns `null` or `undefined`, or a mark without that channel, takes the theme default: `--graph-node` and 16 for nodes, `--graph-edge` and 1.5 for edges.

## When a scale changes

Scale options are compared by content, shared scales and scales of a mark alike: a definition rebuilt with the same scales rewrites nothing. A changed scale restyles every element that uses it and resets its categories. Adding or removing the scales of a mark, or moving a mark to another position, restyles every element.
