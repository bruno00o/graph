`createExploration` from `@bruno00o/graph/query` loads the neighborhood of a node with a TanStack Query, on demand, and exposes the result as two live sources. Expand a node to fetch its neighbors; collapse it to remove what no other expansion holds.

## Create an exploration

`neighbors(key)` returns query options whose data is `{ nodes, edges }`. What the exploration knows about the node and edge types depends on how you write them:

- With `queryOptions` from a TanStack Query adapter, such as `@tanstack/react-query`, the types are inferred from `queryFn`. `@tanstack/query-core` does not export `queryOptions`.
- With a plain object, nothing carries the data type through: the items are typed `{ readonly id: Key }`, and `color: 'group'` or `label: 'label'` on a mark would not compile. Give `createExploration` the node and edge types as type arguments.

```ts
import { defineGraph, edges, type Key, nodes } from '@bruno00o/graph'
import { createExploration, type ExplorationData } from '@bruno00o/graph/query'
import { QueryClient } from '@tanstack/query-core'

interface Item {
  readonly id: string
  readonly label: string
  readonly group: string
}

interface Link {
  readonly id: string
  readonly from: string
  readonly to: string
}

declare function fetchNeighbors(key: Key): Promise<ExplorationData<Item, Link>>

const exploration = createExploration<Item, Link>(new QueryClient(), {
  roots: ['n1'],
  neighbors: (key) => ({
    queryKey: ['neighbors', key],
    queryFn: () => fetchNeighbors(key),
  }),
})

const definition = defineGraph({
  marks: [
    edges(exploration.edges, { source: 'from', target: 'to' }),
    nodes(exploration.nodes, { color: 'group', label: 'label' }),
  ],
})

graph.on('doubleclick', ({ target }) => {
  if (target?.kind === 'node') exploration.toggle(target.key)
})
```

With an adapter, drop the type arguments and use its `queryOptions`:

```ts
import { queryOptions } from '@tanstack/react-query'

const exploration = createExploration(new QueryClient(), {
  roots: ['n1'],
  neighbors: (key: Key) =>
    queryOptions({ queryKey: ['neighbors', key], queryFn: () => fetchNeighbors(key) }),
})
```

- Roots are expanded at once and never removed.
- The response for a node usually contains the node itself: that is how a root gets its data. An expanded node holds itself while its expansion exists.
- Keys are the `id` field by default. Pass `nodeKey` and `edgeKey`, a field name or a function, when your data differs: without them, items without an `id` field do not compile.
- New nodes appear next to the neighbors they connect to.

## Queries do the caching

Each expansion is a `QueryObserver`. Caching, deduplication, `staleTime` and retries come from TanStack Query. Invalidate `['neighbors', key]` and the graph updates by difference.

The observers only run while something listens to the sources, that is while a mark using them is mounted. Creating an exploration has no side effect, StrictMode does not fetch twice, and a remount resumes from the cache. `destroy` stops everything for good.

## Read the exploration state

`exploration.store` is a read-only TanStack Store.

It holds `expanded`, the keys of the expanded nodes, `loading`, the keys whose query is fetching, and `errors`, a `ReadonlyMap` from key to error. See [`ExplorationState`](/docs/api/create-exploration#result).

Mirror it into graph states to show what is expanded and what is loading. The [loading and errors while exploring](/examples/exploration-errors) example also marks the nodes whose query failed, from `errors`, and retries them.

```tsx
import { useSelector } from '@tanstack/react-store'

function ExplorationStates({ exploration }: { exploration: Exploration<Item, Link> }) {
  const graph = useGraph()
  const expanded = useSelector(exploration.store, (state) => state.expanded)
  const loading = useSelector(exploration.store, (state) => state.loading)
  useEffect(() => graph.states.set('expanded', { nodes: expanded }), [graph, expanded])
  useEffect(() => graph.states.set('loading', { nodes: loading }), [graph, loading])
  return null
}
```

## Methods

`expand(key)` fetches the neighborhood of a node and adds it, `collapse(key)` removes what only this expansion holds, `toggle(key)` does one or the other, and `reset()` collapses every expansion but the roots. See [`Exploration`](/docs/api/create-exploration#result).

A failed expansion stays expanded, with its error in `errors`. `retry(key)` fetches it again and removes its error meanwhile: the key is back in `loading`, then in `errors` only if the new fetch fails too. Without a listener, the fetch waits until a mark subscribes again.

```tsx
<Graph
  definition={definition}
  ariaLabel="Explored graph"
  onDoubleClick={({ target }) => {
    if (target?.kind !== 'node') return
    if (exploration.store.state.errors.has(target.key)) exploration.retry(target.key)
    else exploration.toggle(target.key)
  }}
/>
```

In React, create the exploration once with `useState(() => createExploration(…))` and build the definition from its sources in a `useMemo`.

To explore a graph database, a neighborhood query returns the result of a Cypher query converted by `cypherGraph`: see [Cypher](/docs/cypher#explore-with-a-query).
