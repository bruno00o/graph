## Channels and styles

A mark is a list of data and a set of options. One rule decides what happens to each value:

- A **channel** takes a field name or a function `(datum) => value`, and its value goes through a [scale](/docs/scales). Field names are filtered by type: `size` only accepts numeric fields.
- A **style** takes a value or a function, never a field name, and its value is used as is. A style wins over the channel it overrides: `fill` wins over `color`.
- A **number literal** and a function wrapped in **`raw()`** are used as is, outside the scale: `size: 30` draws every node 30 pixels wide, and `size: raw((item) => item.radius * 2)` draws each node at the diameter it returns.

```ts
import { nodes, raw } from '@bruno00o/graph'

nodes(items, {
  color: 'group',
  size: raw((item) => item.weight * 2),
  opacity: (item) => (item.weight > 2 ? 1 : 0.5),
  shape: 'diamond',
})
```

`size` and `width` take a number literal, edge ends included. `color` takes none: a constant color is a style, `fill` on nodes and `stroke` on edges. `raw()` works on `size`, `width` and `color`: a raw color is a CSS color, drawn as given.

Raw values stay out of the extents and the categories of their scale, so they never move the other elements of the scale. A raw color has no category in the [legend](/docs/minimap-and-legend#legend): like a `fill`, its elements count only under the looks of their mark.

Colors are CSS strings: hex values, `var(--graph-cat-3)`, `color-mix(…)`. They are resolved by the browser, so a color given as a CSS variable follows the theme.

## Node options

| Option | Family | Value |
| --- | --- | --- |
| `name` | constant | Name of the mark, reported by targets. See [TypeScript](/docs/typescript) |
| `key` | channel | Node key, `id` by default |
| `color` | channel | Category or number, through the `color` scale, or a CSS color with `raw()` |
| `size` | channel | Number, through the `size` scale, or a diameter in pixels as a literal or with `raw()`; the height of a box |
| `label` | channel | Text, or an object with `text` and its style. See [Labels](/docs/labels) |
| `x`, `y` | channel | Position in world units, followed when it changes |
| `shape` | style | `'circle'`, `'square'`, `'diamond'` or `'box'` |
| `width` | style | Width of a box: `'label'` (default) to fit its label, or a number |
| `cornerRadius` | style | Corner radius of a box, a quarter of its height by default |
| `fill` | style | Fill color, wins over `color` |
| `stroke` | style | Color of the inner contour |
| `strokeWidth` | style | Width of the inner contour in screen pixels |
| `outline` | style | Color of a ring drawn outside the shape, or `null` for none |
| `outlineWidth` | style | Width of that ring in screen pixels |
| `opacity` | style | Opacity from 0 to 1 |
| `image` | style | URL, or `{ src, scale, color }`, or `null` |
| `badges` | function per corner | `{ text, fill, color }` or `null` |
| `units` | constant | `'world'` or `'screen'`. See [Screen units](#screen-units) |
| `scales` | object | `color` and `size` scales of this mark alone. See [Scales](/docs/scales#scales-of-a-mark) |

Without a color or a size, nodes take the theme color `--graph-node` and a diameter of 16. Defaults and details are in [`nodes`](/docs/api/nodes#options). See the [node shapes](/examples/node-shapes) example.

## Edge options

| Option | Family | Value |
| --- | --- | --- |
| `name` | constant | Name of the mark, reported by targets |
| `key` | channel | Edge key, `id` by default |
| `source`, `target` | channel | Key of the node at each end |
| `color` | channel | Category or number, through the `color` scale, or a CSS color with `raw()` |
| `width` | channel | Number, through the `width` scale, or screen pixels as a literal or with `raw()` |
| `label` | channel | Text, or an object with `text` and its style. See [Labels](/docs/labels#edge-labels) |
| `dash` | style | `'solid'`, `'dashed'` or `'dotted'` |
| `arrow` | style | `'none'`, `'source'`, `'target'` or `'both'` |
| `stroke` | style | Line color, wins over `color` |
| `opacity` | style | Opacity from 0 to 1 |
| `flow` | style | Moving dashes: `true`, a speed in pixels per second, or `false` |
| `ends` | object | A look and a label for each end. See [Edge ends](#edge-ends) |
| `waypoints` | channel | Points the edge passes through. See [Waypoints](#waypoints) |
| `scales` | object | `color` and `width` scales of this mark alone. See [Scales](/docs/scales#scales-of-a-mark) |

Without a color or a width, edges take `--graph-edge` and a width of 1.5 pixels. Defaults and details are in [`edges`](/docs/api/edges#options). Examples: [arrows and dashes](/examples/arrows-and-dashes), and [edge width, dashes and arrows](/examples/edge-styles) from the data.

## Labels

`label` takes a field or a function for the text. For more control, pass an object:

```ts
nodes(items, {
  label: {
    text: 'label',
    secondary: (item) => `Group ${item.group}`,
    size: 14,
    weight: 'bold',
    placement: 'right',
    background: true,
  },
})

edges(links, { source: 'from', target: 'to', label: { text: 'name', size: 10 } })
```

- `text` is the main line, and `\n` breaks it. `secondary` adds a smaller second line, on nodes only.
- `size`, `color`, `weight` and `font` style the text, `maxWidth` truncates it with an ellipsis.
- `placement` puts a node label below, above, beside or on the node, and `minScreenSize` hides it on small nodes.
- `background` draws a rounded plate behind the label: a CSS color, `true` for the theme color `--graph-label-background`, or `false` and `null` for none.

Labels never overlap. Node labels are placed largest node first, then edge labels, widest edge first. The hovered and focused elements always show theirs; selected elements come next and still avoid overlaps. See [Labels](/docs/labels).

## Outlines

`stroke` and `strokeWidth` draw the contour inside the shape. `outline` and `outlineWidth` draw a ring outside it, in screen pixels, which reads well around images and dense colors.

```ts
nodes(items, {
  outline: (item) => (item.weight > 5 ? 'var(--graph-cat-2)' : null),
  outlineWidth: 3,
})
```

- `outline` alone draws a 2 pixel ring.
- `outlineWidth` alone draws the ring in `--graph-node-ring`.
- A function that returns `null` draws no ring for that node.

The selection halo starts outside the outline, and the label moves down by its width. See the [stroke and outline](/examples/stroke-and-outline) example.

## Flows

`flow` moves dashes along an edge, from its source to its target. It shows a direction, or a movement, without a second shape to draw.

```ts
edges(links, {
  source: 'from',
  target: 'to',
  flow: (link) => (link.active ? 60 : false),
})
```

- `true` moves at 40 pixels per second, a number at that speed in screen pixels per second, and a negative number toward the source. `false`, `0` and `null` stop the edge.
- A solid edge flows as dashes, and a dashed or dotted edge moves its own pattern. Arrowheads stay still.
- A [state](/docs/states) can start or stop flows with its own `flow`, without touching the data: `states: { path: { flow: true } }`.

The graph draws frames only while a flowing edge is on screen, in a visible page. Without flows, it draws nothing until something changes. With `prefers-reduced-motion`, the dashes stand still. Each frame moves the dashes on the GPU: 100,000 flowing edges hold 60 frames per second, for well under a millisecond of CPU per frame.

[Exports](/docs/export#flows) draw the dashes at a given moment. Examples: [flow speed and direction](/examples/flow-speed), and [flows on a map](/examples/map-flows).

## Boxes

`shape: 'box'` draws a rectangle with rounded corners, with the label written on it. `size` is its height, and its width fits the label by default, with half the height of room on each side.

```ts
nodes(items, {
  shape: 'box',
  size: 28,
  label: 'label',
  fill: (item) => (item.weight > 5 ? 'var(--graph-cat-1)' : 'var(--graph-cat-6)'),
})
```

- `width: 'label'` fits the box to the longer of its label lines, secondary line included, and never draws it narrower than it is tall. A box without a label is a rounded square. The height stays `size`: give a label with two lines a box tall enough for both.
- A number sets the width in the units of `size`. The label is cut with an ellipsis to fit, unless it sets its own `maxWidth`.
- `cornerRadius` rounds the corners, a quarter of the height by default, and at most half the height: `cornerRadius: 0` gives square corners.
- The label goes on the box, `placement: 'center'` by default. Another placement puts it outside, and the box keeps its height as width.

Boxes are measured with the font of the labels, the same one the glyphs are drawn with, so the text fits the box at every zoom level. When the theme changes `--graph-font`, the boxes are measured again. When a web font in the family list loads after the first frame, the boxes are measured again with it (see [Fonts](/docs/labels#fonts)).

Edges end at the border of a box, rounded corners included, and their arrows touch it: straight edges, parallel curves, [bundled](/docs/bundling) and [routed](/docs/routing) paths, and edge ends. Loops start from the right end of the box. Picking, the [view fit](/docs/view), [hulls](/docs/drawing-layers#hulls), [anchors](/docs/drawing-layers#anchored-html), the [minimap](/docs/minimap-and-legend) and the [exports](/docs/export) follow the box too. Badges sit on its corners, and an image is drawn as a square as tall as the box, in its middle. See the [box nodes](/examples/box-nodes) example.

### Text inside a node

A label drawn inside its node, always on a box and on the other shapes when a `'center'` label fits, has no halo. Without a `color`, its text takes `--graph-ink` or `--graph-paper`, whichever contrasts more with the fill, so a light label sits on a dark node and a dark label on a light node. The choice follows the WCAG contrast ratio of the colors the theme resolves, so it holds in a dark theme, when a state changes the fill, and when a fill is partly transparent over the page. The secondary line follows the main text.

An explicit `color` of the label, or a `labelColor` of a [state](/docs/states), always wins. A label with a `background` keeps its plate and the ink of the theme.

## Screen units

By default a node grows when you zoom in. With `units: 'screen'`, its size stays the same on screen at every zoom level, which suits markers and icons.

```ts
defineGraph({
  marks: [nodes(items, { size: 12, units: 'screen' })],
})
```

A number literal is drawn as given, so every node is 12 pixels wide.

Without `units`, nodes placed by `longitude` and `latitude` are in screen units, and the group nodes of [`groups()`](/docs/transformations#group-items-by-a-field) take the units of their members.

Edge widths are always in screen pixels. See the [screen units](/examples/screen-units) example.

## Parallel edges and loops

Edges between the same two nodes, in either direction, bend apart in symmetric arcs. An edge alone on its pair stays straight. An edge from a node to itself draws a loop at the top right of the node, and several loops nest around it. Curves keep their shape at every zoom level, and picking follows the curve.

## Waypoints

`waypoints` draws an edge through points of your own, in order from its source to its target, such as a route drawn by hand or a line read from a map. The edge starts on its source node, passes each point with a sharp corner, and ends on its target node.

```ts
type Link = { id: string; from: string; to: string; via: { x: number; y: number }[] }

declare const links: Link[]

edges(links, { source: 'from', target: 'to', waypoints: 'via' })
```

```ts
type WaypointInput = Point | GeoPoint | readonly [x: number, y: number]
```

- A point is `{ x, y }` or `[x, y]` in world units, or `{ longitude, latitude }` in degrees, placed with the projection of [`longitude` and `latitude`](/docs/positions#longitude-and-latitude), with or without a map. The channel takes any iterable, an array or a generator.
- Only the points in between are fixed. The first and last segments go to the drawn nodes, so they follow a drag, a layout, an animation or a spread group, and the corners stay where the data puts them.
- `null`, `undefined` or an empty list draw a plain edge. A point that is not a finite number is skipped, and so is a point equal to the one before it.
- An edge with waypoints is never [bundled](/docs/bundling) or [routed](/docs/routing), never jumps or is jumped over by a [bridge](/docs/routing#bridges), and does not bend apart from [parallel edges](#parallel-edges-and-loops). Loops ignore their waypoints. Waypoints win over `geodesic`.
- Everything else follows the path: width, color, dashes and flows run through the corners, arrow heads point along the first and last segments, [`ends`](#edge-ends) splits the visible length of the path, and the label sits halfway along the path, turned with its segment. Picking, hovering, the [export](/docs/export) to PNG and SVG and `view.fit` with `edges` follow the path too.
- An edge takes up to 8,190 points; beyond, its points are thinned evenly, with a warning in development. Points cost 24 bytes each in memory and 16 bytes on the GPU.

With 100,000 edges of 30 points each on a 1280 × 800 page, the first render takes 0.15 to 0.4 seconds more than with straight edges, and a frame of the whole graph about 18 ms instead of 8 ms. Graphs without waypoints pay nothing: no texture is sent and no program is compiled for them.

See [routes along a network](/docs/map#routes-along-a-network) for lines read from GeoJSON.

## Edge ends

`ends` splits an edge in two: the line from the source node to the split takes the `source` options, the rest takes the `target` options. Each end has its own color, width, dash pattern and label, so one edge can show a value per direction.

```ts
type Exchange = {
  id: string
  from: string
  to: string
  sent: number
  received: number
}

declare const exchanges: Exchange[]

edges(exchanges, {
  source: 'from',
  target: 'to',
  arrow: 'both',
  ends: {
    split: (exchange) => exchange.sent / (exchange.sent + exchange.received),
    source: {
      color: 'sent',
      width: 'sent',
      label: (exchange) => String(exchange.sent),
    },
    target: {
      color: 'received',
      width: 'received',
      label: { text: (exchange) => String(exchange.received), background: true },
    },
  },
})
```

- `split` is the share of the visible length, between the two node borders, where the source end stops: `0.5` by default, clamped to 0 and 1. A function makes it follow the data.
- `color` and `width` go through the `color` and `width` scales of their edge mark: end values widen the extent of the scale, take categories in order and appear in the legend. A number literal and `raw()` work as on the edge. Without them, an end keeps the color and width of the edge; `stroke` sets a color directly.
- An arrow head takes the color and width of its end. A dash pattern keeps its rhythm across the split, and flows run through it.
- An end label sits near its node, past the arrow head, and turns with the line. It shows only when it fits, after the middle label. With a `background`, it reads as a badge on the line.
- A state that sets `stroke` or `strokeWidth`, such as hover and selection, applies to both ends. States that only change the opacity or add a halo keep the colors of the ends.
- Every geometry splits the same way: straight edges, parallel curves, loops, bundled paths, [orthogonal routes](/docs/routing), [waypoints](#waypoints) and great circles on a map, on screen as in PNG and SVG exports.

Picking reports the end under the pointer in `target.end`, `'source'` or `'target'`. Moving across the split emits `pointerleave` for one end and `pointerenter` for the other, so a tooltip can follow the end. Selection and states still hold whole edges: an end has no key of its own, and keeping one per end would double the work of every state change. To highlight an end, read `target.end` and style that end from your data.

## Drawing order

Shapes draw in mark order, then all labels, then a final pass for hovered, selected and focused elements so they stay visible inside a dense cluster. Put edges first to keep them under the nodes.
