## PNG and SVG

`@bruno00o/graph/export` turns a mounted graph into a file. Both functions are asynchronous and leave the graph on screen untouched.

```ts
import { exportPng, exportSvg } from '@bruno00o/graph/export'

const png = await exportPng(graph)
const svg = await exportSvg(graph)
```

`exportPng` returns a `Blob` of type `image/png`. `exportSvg` returns the text of an SVG document: wrap it in a `Blob` to download it, or insert it in a page.

```ts
function download(blob: Blob, name: string) {
  const url = URL.createObjectURL(blob)
  const link = document.createElement('a')
  link.href = url
  link.download = name
  link.click()
  URL.revokeObjectURL(url)
}

download(await exportPng(graph), 'graph.png')
download(new Blob([await exportSvg(graph)], { type: 'image/svg+xml' }), 'graph.svg')
```

## Region and scale

By default, the file shows what the graph shows: the same area, the same zoom, the same labels, the background grid, the [shapes](/docs/shapes) and the hulls. `region: 'graph'` frames every node instead, with the shapes, labels, loops, curved edges and hulls that reach past them, and a `padding` in CSS pixels around them.

Elements outside the [time window](/docs/time) of the graph are left out, as on screen. `window` exports another window, or every element with `null`, and the hulls then wrap the nodes of that window:

```ts
await exportSvg(graph, { region: 'graph', window: null })
```

Elements pinned with [`graph.anchors`](/docs/drawing-layers#anchored-html) or `<Anchor>` are HTML over the canvas, not part of the scene: no export draws them.

```ts
await exportPng(graph, { region: 'graph', padding: 48 })
```

`zoom` sets the scale of the file in CSS pixels per world unit, the unit of the zoom of the [view](/docs/view#the-view), which it defaults to. Nodes sized in world units grow with it, while edge widths, labels and nodes with `units: 'screen'` keep their size in pixels, as they do when you zoom on screen. A larger zoom gives a larger file of the same region, never a crop: with the default region, twice the zoom of the view draws the same area in a file twice as wide and twice as tall.

```ts
await exportSvg(graph, { region: 'graph', zoom: 2 })
```

The children of an unfolded group that are [spread](/docs/groups#spread-children) apart are drawn where the screen shows them. At another `zoom`, their gaps in pixels scale with it instead of being computed again for that zoom.

The [PNG export options](/examples/png-export-options) example previews the region, the scale, the pixel ratio and the background, with the size of the image.

## Exact size

`size` sets the size of the image in pixels, instead of the zoom: the export picks the largest zoom at which the region fits inside it, with its aspect kept. It suits thumbnails and batches, where every image must have the same size whatever the graph. Give a `width`, a `height`, or both; with one side only, the other follows the aspect of the region.

```ts
await exportPng(graph, { region: 'graph', size: { width: 640, height: 400 } })
await exportSvg(graph, { region: 'graph', size: { width: 320 } })
```

- With `region: 'graph'`, the nodes, labels, loops, curved edges and hulls fit inside the size with `padding` around them, which stays in CSS pixels. Since edge widths and labels keep their size in pixels, the zoom is found by search, not by a ratio of sizes.
- With `region: 'view'`, the whole area the view shows fits inside, so a size of another aspect shows more of the graph around it. `padding` applies to `region: 'graph'` only.
- The space the region leaves over, on the longer side, shows the background.
- A PNG has exactly `size` pixels, whatever `pixelRatio`, which keeps its meaning: edge widths and labels are drawn at their CSS size times it, and the area drawn is `size` divided by it. A smaller ratio draws the graph with relatively larger labels. An SVG takes `size` as its width and height, in CSS pixels.
- `size` sets the zoom, so passing `zoom` too throws a `RangeError`, as does a side that is not a finite number of pixels, 1 or more.

## Pixel ratio

`pixelRatio` is the number of image pixels per CSS pixel. It defaults to the pixel ratio the graph draws at, so the image is as sharp as the screen: the device pixel ratio, unless the [`pixelRatio`](/docs/api/define-graph#pixel-ratio) of the definition sets another, or WebGL runs in software and the graph draws one pixel per CSS pixel. Raise it for print.

```ts
await exportPng(graph, { region: 'graph', pixelRatio: 4 })
```

The image is drawn in a WebGL context of its own, freed at the end. Past 4,096 pixels on a side it is drawn in tiles, so its size is bounded by memory rather than by the GPU. Labels are chosen once for the whole image, so none is cut or doubled at a tile edge. The PNG records its pixel density, so a viewer shows it at its CSS size.

## Grid and badges

The background grid of the definition and the badges of the nodes are drawn by default. `grid: false` leaves the grid out and `badges: false` the badges, in a PNG and in an SVG, so a batch of images can show the same graph without them. The nodes keep their size, their labels and their place.

```ts
await exportPng(graph, { grid: false, badges: false })
```

## Labels

`labels: 'visible'`, the default, keeps the labels of the screen: small labels are hidden and overlapping labels give way, as on screen. `'all'` draws every label, whatever its size or overlaps. `'none'` draws none.

```ts
await exportSvg(graph, { labels: 'all' })
```

## Background

The background is `--graph-paper` by default, resolved with the current theme. Pass any CSS color, a `--graph-…` token or `'transparent'`.

```ts
await exportPng(graph, { background: 'transparent' })
await exportPng(graph, { background: 'var(--graph-paper)' })
await exportSvg(graph, { background: '#ffffff' })
```

On screen, the canvas is transparent and the page paints what lies under the graph. An export cannot read the page: a background drawn by your CSS, such as a pattern on the element, is not in the file. Draw it with the [background grid](/docs/drawing-layers#background-grid) of the definition, which exports draw, or export with `'transparent'` and lay the image over the same background.

## Flows

An export is a still image: edges with a [`flow`](/docs/marks#flows) are drawn as dashes, at the moment `time`, in milliseconds after the dashes start. At `0`, the default, every pattern starts at the source of its edge, so two exports of the same graph match. The SVG holds no animation.

```ts
await exportPng(graph, { time: 250 })
```

## What the SVG contains

The SVG is written from the scene, without reading pixels back, so it stays sharp at any size and its text can be selected and searched. It draws:

- the [shapes](/docs/shapes) of `shapes()` marks, with fill, outline, line and opacity, over the background grid and under the containers, hulls, edges and nodes;
- node shapes, fills, inner strokes, outlines, halos and opacity;
- pictures cut to the node shape, and icons tinted with their `color`;
- badges with their text, unless `badges` is `false`;
- unfolded groups as containers behind their children, rectangles or circles, and folded groups as nodes;
- straight and curved edges, loops, dashes, dots, flows as still dashes, and arrows;
- labels with their placement, color, weight, second line and background;
- the background grid, as one pattern per level, unless `grid` is `false`, and the fills and outlines of hulls, over the containers and under the edges;
- the state styles in force, such as selection, hover and your own states;
- colors of the current theme, as hex values.

Images are copied into the document as data URLs, so the file stands alone. Pass `embedImages: false` to keep links to their URLs instead. An image the browser cannot load, for lack of CORS headers for instance, is left out, as it is on screen.

Text uses the font of the theme. A viewer without that font falls back to another one, so labels may be a little wider or narrower than on screen.

## draw.io diagrams

`exportDrawio` writes the graph as a [draw.io](https://www.drawio.com) (diagrams.net) file that stays editable: every node becomes a shape, every edge a connector attached to its two nodes, so moving a node in the editor drags its edges along. It resolves to the text of an uncompressed `.drawio` file with one page.

```ts
import { exportDrawio } from '@bruno00o/graph/export'

const file = await exportDrawio(graph)
download(new Blob([file], { type: 'application/vnd.jgraph.mxfile' }), 'graph.drawio')
```

By default the page frames the whole graph, with a `padding` of 32 units, at one draw.io unit per world unit (`zoom: 1`): a node 100 world units from another is 100 units from it in the editor. Sizes set in screen pixels, such as edge widths, labels and nodes with `units: 'screen'`, keep their size in units whatever the `zoom`. `zoom` scales the diagram, and `size` chooses the zoom that fits a page of that size. On a [map](/docs/map), the world is 512 units wide: pass a `zoom` or a `size` to get a readable page. `region: 'view'` keeps the nodes the view shows, even in part, and the edges between them. Elements hidden by a `hide` state, a [layer](/docs/multilayer), a [zoom range](/docs/zoom) or the [time window](/docs/time) stay out of the file, as on screen; `window` works as for the other exports.

The file keeps the states the definition adds, such as a state that marks the leads of a team, and leaves out the selection, the hover and the focus, whose rings and dimmed `others` would be frozen in the drawing. `states: 'all'` keeps them, as the PNG and the SVG do, and `states: 'none'` keeps no state at all.

What the file holds:

| On screen | In draw.io |
| --- | --- |
| circle, square, diamond and box nodes | ellipse, rectangle, rhombus and rounded rectangle of the same size, corner radius included |
| fill, inner stroke and its width, opacity | fill, line and its width, opacity; the outline stands for the line when the node has no inner stroke |
| node labels | the text of the shape, with its placement, size, weight, color, font family, second line and background color |
| pictures | an image shape inside the node, linked to its URL (data URLs are kept), cut to a circle, square or diamond |
| unfolded groups | containers holding their children, with their box and label; folded groups are ordinary shapes |
| edges | connectors with color, width, dashes, dots and arrows at either end, and their label |
| curved parallel edges, loops, great circle arcs, bundled paths | curved connectors through control points |
| orthogonal routes and waypoints | straight connectors through their bends |
| labels at the ends of an edge | labels on the connector, near each end |
| merged edges | one connector for the whole set |

Some looks have no equivalent and are approximated: an edge whose two ends have different colors takes the color, width and dash of its longer end; an image tinted with `color` keeps its own colors; the scale of an image inside its node is kept, its maximum label width is not. Halos, flows, badges, [hulls](/docs/drawing-layers#hulls), the background grid and the [shapes](/docs/shapes) of `shapes()` marks are left out. Colors are those of the current theme, as hex values with an opacity.

Each cell takes its id from the key of its element (`n:` for a node, `e:` for an edge, with `#` instead of `:` for a number key), so two exports of the same graph line up and a script can find a cell again. The diagram uses the page background of the theme, or none with `background: 'transparent'`.

draw.io itself saves a diagram as a PDF, a PNG or an SVG file, from the editor or from the command line of draw.io Desktop, for example `drawio --export --format pdf graph.drawio`. To export many graphs from a script, mount each one in a page of a headless browser, such as one driven by Playwright, call `exportDrawio` there, and write the text it returns: the diagram does not need a GPU.

## Visio drawings

`exportVsdx` writes the same diagram as a Visio drawing (`.vsdx`, Visio 2013 and later) and resolves to a `Blob`. It takes the options of `exportDrawio`, with the same region, scale, states and hidden elements, and needs no dependency.

```ts
import { exportVsdx } from '@bruno00o/graph/export'

download(await exportVsdx(graph), 'graph.vsdx')
```

One diagram unit is 1/96 inch, so at `zoom: 1` a node 96 world units from another is one inch from it, and the page fits the content. What the drawing holds:

| On screen | In Visio |
| --- | --- |
| circle, square, diamond and box nodes | shapes with their own geometry (no masters), with fill, line color, weight, dashes, rounded corners and transparency |
| node labels | the text of the shape, below, above, left, right or centered through its text block, in a font of the document, with size, weight, color and background color |
| edges | connectors glued to the whole of their two nodes, with color, width, dashes, dots, arrows at either end, and their label above the middle |
| curved edges, loops, arcs and bundled paths | connectors through points sampled along the curve |
| orthogonal routes and waypoints | connectors through their bends |
| unfolded groups | Visio groups holding their members, drawn behind them |

Moving a node in Visio keeps its edges attached: their ends slide along the outline of the node. The bends of an edge stay where they are on the page, so only the first and last segments follow the node; a curve, written as points, keeps its shape and only its ends move. An edge stays glued to a member inside a group, and moving the group moves its members and their edges.

Labels at the ends of an edge become separate text shapes, which stay in place when a node moves. Pictures are left out, as are halos, flows, badges, hulls, the background grid and the shapes of `shapes()` marks. The page background is a locked rectangle under the drawing, or nothing with `background: 'transparent'`. Each shape keeps the key of its element in a `Key` shape data field. Fonts take the first family of the theme, with Calibri instead of `system-ui` and `sans-serif`.

The parts of the file are compressed with `CompressionStream`, where the browser or Node has it, and stored uncompressed otherwise.

## Large graphs

`exportPng` and `exportSvg` read the scene in a single pass and build their output in memory. On 50,000 nodes and 100,000 edges, an SVG of the view takes about half a second and weighs about 25 MB; a PNG of the view takes about the same time. For very large images, the PNG is encoded strip by strip.
