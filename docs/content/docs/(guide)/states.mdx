---
title: States
description: Style named sets of nodes and edges, and set their members by key.
---

A state is a named set of nodes and edges drawn with its own style. Three come built in: `selected`, `hovered` and `focused`. You declare the others in `defineGraph` and fill them from code. States are resolved on the GPU, so setting thousands of members costs one buffer update.

## Declare a state

Add a `states` object to the definition. Each key names a state and each value is its style.

```ts
const definition = defineGraph({
  marks: [
    edges(links, { source: 'from', target: 'to' }),
    nodes(items, { color: 'group', label: 'label' }),
  ],
  states: {
    muted: { opacity: 0.2, label: false },
    pinned: { outline: 'var(--graph-ink)', outlineWidth: 3 },
  },
})
```

The names become types. `mountGraph` returns an instance whose `states` methods accept `'muted'` and `'pinned'` only: a misspelled name, or a built-in name, does not compile. See the [named states](/examples/named-states) example.

## Set the members

`graph.states` changes membership by key.

```ts
graph.on('click', ({ target }) => {
  if (target?.kind !== 'node') {
    graph.states.clear('muted')
    return
  }
  const keep = new Set([target.key, ...graph.neighbors(target.key)])
  graph.states.set('muted', { nodes: items.filter((item) => !keep.has(item.id)).map((item) => item.id) })
})

graph.states.add('pinned', { nodes: ['n12'] })
graph.states.has('pinned', { kind: 'node', key: 'n12' })
```

The methods are listed in [`GraphStates`](/docs/api/graph-instance#states).

<Callout title="Keys before elements">
A key can join a state before its element exists. The element takes the style as soon as it arrives, which suits data that loads in steps. A removed element keeps its states and gets them back if it returns.
</Callout>

The selection is not a free state: change it through `graph.selection`. See [Interaction](/docs/interaction).

## Style options

A style sets any of the properties of [`StateStyle`](/docs/api/define-graph#state-styles): `opacity`, `fill`, `stroke`, `strokeWidth`, `outline`, `outlineWidth`, `halo`, `label`, `labelColor`, `flow`, which moves dashes along edges (see [Flows](/docs/marks#flows)), `raise` (see [Raise a state](#raise-a-state)) and `hide` (see [Hide members](#hide-members)). Leave a property out and the element keeps its own value. An `opacity` of `0.2` pushes an element into the background. `label: true` still hides labels smaller than 8 pixels: see [Labels in states](/docs/labels#labels-in-states).

## Override the built-in states

Declare a built-in name to change its style, property by property.

```ts
states: {
  selected: { stroke: 'var(--graph-cat-1)' },
  hovered: { outline: 'var(--graph-ink)' },
}
```

By default, a selected node gets an accent ring, a halo and its label; a hovered node an ink ring; a focused node a focus ring. A selected edge changes color and gets a halo but keeps its width.

## Priority

An element can be in several states at once. Each property comes from the first state that sets it, in this order: `selected`, `hovered`, `focused`, then your states in the order you declared them. The opacity of the winning state multiplies the element's own.

Selected, hovered and focused elements are drawn again above all others, so they stay visible inside a dense cluster.

## Raise a state

A free state is drawn in place: inside a dense cluster, other nodes and edges cover its members. `raise: true` draws them above every mark, as the selection is:

```ts
states: {
  path: { stroke: 'var(--graph-accent)', strokeWidth: 2.5, label: true, raise: true },
}
```

A raised element:

- is drawn in a last pass, above every mark, with the selected, hovered and focused elements, in the order of its mark, then of its index;
- places its label before the labels of other elements, as selected elements do: it may still give way to the hovered and focused labels, and to another raised label in the same place;
- is picked before the elements it covers, so a click hits what is drawn on top;
- is drawn on top in [exports](/docs/export) too.

An element is raised when any of its states raises it. `raise` is `true` for `selected`, `hovered` and `focused`: set `raise: false` on one of them to draw its members in place. Raising costs one more draw of the raised elements, about the cost of selecting them: 100,000 raised edges redraw faster than 100,000 selected edges, whose halo costs more. The [named states](/examples/named-states) example turns `raise` on and off.

<Callout title="Limit">
A definition holds up to 29 states besides the three built-in ones. Past that, `defineGraph` throws a `RangeError`.
</Callout>

## Hide members

`hide: true` takes the members of a state out of the drawing: they are neither drawn, labeled, picked, exported nor counted by the legend, and the edges of a hidden node hide with them. They keep their position, their selection and their other states, and come back as they were when they leave the state.

```ts
states: { off: { hide: true } }

graph.states.set('off', { nodes: ['a', 'b'] })
```

Hiding writes no data: it costs about as much as any other state change. See [Hide without losing state](/docs/transformations#hide-without-losing-state), and the [filter by degree](/examples/degree-filter) and [filter with a hidden state](/examples/threshold-filter) examples.

## Read states in React

`useGraphState` subscribes to the graph store. Select only what you render: the component updates when that slice changes.

```tsx title="MutedCount.tsx"
import { useGraphState } from '@bruno00o/graph/react'

export function MutedCount() {
  const count = useGraphState((state) => state.states.muted?.nodes.length ?? 0)
  return <output>{count} nodes muted</output>
}
```
