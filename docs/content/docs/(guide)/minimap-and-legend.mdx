## Minimap

`@bruno00o/graph/minimap` draws an overview of the whole graph with the rectangle of the current view. Drag the rectangle to pan, press elsewhere to center the view there, and scroll to zoom the graph.

```ts
import { createMinimap } from '@bruno00o/graph/minimap'

const minimap = createMinimap(graph, { corner: 'bottomRight', width: 200, height: 150 })
```

The minimap sits in a corner of the graph element. A `width` or `height` that is not above 0 falls back to its default. With `corner: null`, it leaves `minimap.element` to you, to place anywhere in the page. `minimap.update` changes the options it is given, keeps the others and returns an option set to `undefined` to its default, and `minimap.destroy` removes it; destroying the graph destroys it too, and a minimap created on a destroyed graph comes back destroyed, without a worker. Every option is listed in the [API reference](/docs/api/minimap), and the [minimap options](/examples/minimap-options) example tries them. A graph drawn on a [map](/docs/map) has no minimap: the map has its own navigation, so while the graph is on a map, the minimap leaves the graph, keeps an empty element and draws nothing, and a minimap created there warns once in development. `update` keeps its options for later: when the graph [moves back](/docs/map#with-and-without-a-map) to its canvas, the minimap takes its place again and draws the positions of the canvas, and one created on the map starts its worker then.

### What it draws

Nodes are drawn with their colors and shapes, group containers as frames, and edges as faint lines while the graph shows at most `maxEdges` of them. Past that, the minimap draws nodes only: at a few hundred thousand edges, lines fill the minimap without saying more. Selected nodes are drawn last, in `selectionColor`. Labels, badges, hulls and the background grid are left out.

[Shapes](/docs/shapes) are drawn first, under containers, edges and nodes: polygons, discs, rings and rectangles as pale fills, lines and unfilled shapes as thin outlines, in the color of their fill or outline. A pinned shape follows its node, and a hidden shape is left out but still counts in the frame. Each shape is drawn from the coarsest copy of its outline that stays within half a pixel of the minimap, and a shape smaller than three pixels as its bounding box. Past `maxShapePoints` points in all, 200,000 by default, the next shapes are drawn as their bounding boxes; `0` draws no shapes.

Nodes keep their size, between `nodeSize` and a cap that shrinks as nodes get more numerous, so that a large graph reads as density rather than as a solid shape.

### Cost

The minimap draws again when positions, data, the selection or the theme change, never more often than its own cost allows: it waits ten times as long as its last draw took on the page, and at least 32 ms. When the browser has workers and `OffscreenCanvas`, the drawing happens in a worker, the page only copies the columns it needs and shows each finished frame; otherwise it happens on the page. The rectangle of the view moves at every frame, without drawing again.

With 500,000 nodes and 1,000,000 edges, a draw costs the page a few milliseconds at most, the time to copy the columns, and panning or a force layout keeps the same frame rate as without the minimap. With 10,000 shapes of 50 points, preparing their outlines takes 4 to 6 ms on the page and drawing them 4 ms, again only when the data or the level of detail changes.

### Accessibility

The minimap is hidden from assistive technologies: it repeats what the graph shows, and the keyboard already moves the view (Shift and the arrows, `+`, `-` and `0`). It takes no focus.

### React

```tsx
import { Graph, Minimap } from '@bruno00o/graph/react'

<Graph definition={definition} ariaLabel="Graph">
  <Minimap corner="bottomLeft" />
</Graph>
```

Outside `<Graph>`, pass the graph: `<Minimap graph={graph} corner={null} />`.

## Legend

`@bruno00o/graph/legend` reads a legend from the scales of the definition, in two parts: `createLegend` gives the data, `mountLegend` renders it.

```ts
import { createLegend, mountLegend } from '@bruno00o/graph/legend'

const legend = createLegend(graph, { highlight: 'match', hidden: 'faded' })
const view = mountLegend(legend, { titles: { color: 'Group', size: 'Weight' } })
panel.append(view.element)
```

### Sections

The legend describes nodes, edges and [shapes](/docs/shapes).

`legend.store` holds the state of the legend, updated when data or definition change:

- `color`: for a categorical scale or a function, the categories in the order of their colors, with the number of nodes and edges drawn in each, and of shapes in a graph with a shape mark, leaving out the elements whose `fill` or `stroke` replaces the scale; for a sequential scale, a ramp with its domain and its stops. Raw colors, set with `raw()`, have no category.
- `size` and `width`: the ends of the domain and a rounded value between them, with the diameter or the width each one becomes.
- `marks`: the same sections for each mark with [scales of its own](/docs/scales#scales-of-a-mark), which the shared sections leave out. Their category ids carry the mark, such as `c:n1:string:north`.
- `looks`: the shapes and images of the nodes, the line patterns of the edges, and for shapes, areas or lines with their fill, outline and pattern, by mark. When the shapes of a look differ in fill or outline, as with `color`, the look shows the theme tokens `--graph-shape-fill` and `--graph-shape-stroke`.
- `layers`: the [layers](/docs/multilayer) of the marks, hidden ones included. Switching a layer off hides it in the graph.

A category that no element draws at the moment stays in place, with counts of zero: a value of a `domain`, or a value that a [history](/docs/time#scales-over-the-whole-history) gives at other moments. `empty: 'hide'` leaves them out.

The default renderer writes no text of its own. Titles come from `titles`, and from `markTitle` or the name of the mark for the scales of a mark, values go through `format`, looks show the `name` of their mark, or the text of `lookText`, and layers their name, or the text of `layerText`. Looks show only for nodes, edges or shapes drawn with more than one look.

### Highlight and switch off

Under the pointer, or with the keyboard focus, an item of the default renderer puts its elements in the `highlight` state. A click, Enter or Space switches it off: its elements go to the `hidden` state, and its button reads as not pressed. The elements of an item include each edge merged into an aggregated edge, and the nodes of a folded group, which join the state as soon as the group unfolds. Declare both states in the definition with the style you want.

```ts
const definition = defineGraph({
  marks: [...],
  states: {
    match: { outline: 'var(--graph-accent)', label: true },
    faded: { opacity: 0.08, label: false },
  },
})
```

Declare the `hidden` state with `hide: true` to filter the graph: the elements of an item switched off disappear, keep their selection, and the item stays listed. See [Hide without losing state](/docs/transformations#from-the-legend).

Without `hidden`, switching an item off only changes the state of the legend. Read `off` there to filter the data yourself:

```ts
let filtered = legend.store.state.off
legend.store.subscribe(() => {
  const { off, color } = legend.store.state
  if (off === filtered) return
  filtered = off
  const items = color?.type === 'categories' ? color.items : []
  const groups = new Set(items.filter((item) => item.off).map((item) => item.value))
  graph.update({ definition: define(data.filter((item) => !groups.has(item.group))) })
})
```

An item switched off stays in the legend, with no element, until it is switched on again.

`legend.only(id)` switches off every other item of the section of `id`, so that only its elements stay: the other categories, the other looks of nodes or of edges, or the other layers. `legend.reset()` switches them all back on.

```ts
row.addEventListener('dblclick', () => legend.only(item.id))
```

`legend.hover`, `legend.toggle`, `legend.only`, `legend.reset` and `legend.keys` drive the same behavior from a renderer of your own. `legend.keys` returns `shapes` next to `nodes` and `edges` in a graph with a shape mark. Like the minimap, `legend.update` changes only the options it is given. See the [legend of your own](/examples/custom-legend) example.

### A legend declared by the application

When elements take their colors from rules of the application, through style functions or states rather than through the scales of the definition, the sections above have nothing to read. Declare the entries yourself with `entries`: sections with a title, each with entries that carry their own label and swatch.

```ts
const legend = createLegend(graph, {
  highlight: 'match',
  hidden: 'off',
  entries: [
    {
      title: 'Weight',
      entries: [
        {
          id: 'heavy',
          label: 'Heavy',
          swatch: { kind: 'nodes', fill: 'var(--graph-cat-1)' },
          nodes: (item) => item.weight >= 40,
        },
        {
          id: 'strong',
          label: 'Strong links',
          swatch: { kind: 'edges', color: 'var(--graph-cat-2)', width: 3 },
          edges: (link) => link.strength >= 0.66,
        },
      ],
    },
  ],
})
const view = mountLegend(legend, { sections: ['entries'] })
```

The legend writes no text of its own: `label` and `title` are yours. The `swatch` is drawn like the swatches of the legend itself: a node shape with a fill, an outline and an image, an edge line with a color, a width and a pattern, or a shape as an area or a line. Give the same values to the style of the mark so the swatch matches what the graph draws.

An entry that has `nodes`, `edges` or `shapes` covers the elements for which that function returns `true`. It gets the item as given to its mark, typed from the marks of the definition, and the key. Such an entry works like a category: its elements go to the `highlight` state under the pointer, and to the `hidden` state when it is switched off, `only` keeps one entry of a section on, and `legend.store.state.entries` holds the number of nodes, edges and shapes drawn that belong to it. An entry without any of the three is only displayed, and is not a button. The id of its item is `a:` followed by its `id`, which `hover`, `toggle`, `only` and `keys` take.

An entry may overlap another: an element belongs to every entry whose function accepts it. A function is called once per item, then again only for an item that changed, so keep it pure, and give a new function when its rule changes: the legend compares functions by identity. Inside a component, hoist the entries or memoize them, or each render evaluates every rule again. The first reading of a large graph is cut into slices of a few milliseconds, so the legend fills in a moment after the graph. A function that throws counts as `false` and is reported once through `reportError`.

`sections` of `mountLegend` takes `'entries'` among the others to place the declared sections among the sections of the scales, or alone as above. Without `sections`, they come last. `empty: 'hide'` leaves out the entries that cover no element at the moment. `legend.update({ entries })` replaces them; an entry removed loses its switched off state.

In React, `<Legend entries={…} />` and `useLegend({ entries })` take the same option. See the [rules legend](/examples/rule-legend) example, and the [API](/docs/api/legend#entries) for the types.

### Theming

The default renderer is plain HTML styled inline with the [theme tokens](/docs/theming): `--graph-paper-raised`, `--graph-ink`, `--graph-font`, `--graph-node`, `--graph-edge`. Swatches use the colors of the scale as they are, so they follow the theme without drawing again. `[data-graph-legend]` marks the element, and `[data-item]` its items.

### React

`<Legend>` renders the default legend where it stands, inside `<Graph>` or `<MapGraph>`, or anywhere with its `graph` prop. `useLegend` returns the state and the legend, for a legend drawn by your components; it takes the graph in its `graph` option.

```tsx
import { Graph, Legend, useLegend } from '@bruno00o/graph/react'

<Graph definition={definition} ariaLabel="Graph">
  <Legend titles={{ color: 'Group' }} highlight="match" hidden="faded" />
</Graph>

function Swatches() {
  const { state, legend } = useLegend({ highlight: 'match' })
  if (state.color?.type !== 'categories') return null
  return state.color.items.map((item) => (
    <button key={item.id} type="button" onClick={() => legend?.toggle(item.id)}>
      {String(item.value)}
    </button>
  ))
}
```
